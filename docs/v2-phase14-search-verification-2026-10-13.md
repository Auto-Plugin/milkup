从已核验的 `55f8f999aa6363c1aaa7ef127e7b250c6a18850f` 接续，同一 `dot/milkup-v2-quality` 分支。本轮不合并远端 v2、不强推、不发布应用。范围仅为当前文档；设计和资源边界见[设计记录](./v2-phase14-search-design-2026-10-13.md)。

## 同夹具前后对照

104,857,639 字节、1,638,402 行编号 CRLF 文件，含中文和 emoji，查询 `tailneedle`；保持原完整文件与查询，未通过延长超时或缩小夹具宣称改进。

| 路径   | 本阶段旧实现 | 最终实现 | 说明                                           |
| ------ | -----------: | -------: | ---------------------------------------------- |
| source |    87,626 ms | 3,890 ms | 搜索 controller 到完整结果页，不含输入查询时间 |
| live   |    94,740 ms | 4,142 ms | 同上                                           |

旧实现每次扫描约 3,201 个行窗口。原生直接分解为读取 5.25 秒、JSON 序列化 12.59 秒、约 384 MB 序列化输出；前端窗口读取累计 source 83.67 秒、live 90.67 秒，正文和行正文重复返回约 206,444,460 UTF-16 单元。前端累计时间还包含 IPC、解码和调度，不能全算作磁盘扫描，也不能用不同运行的差值冒充精确传输耗时。首次脚本未等待 CLI ready 的超时保留为失败，加入 ready 断言后才取得可用基线。

新实现约 1 MiB 原生扫描步长，原生磁盘索引保存完整命中；对可证明等价的 ASCII 批次直接匹配，其他批次使用独立 Worker 中原有 JS `toLocaleLowerCase` 字面语义。前端仅保留有限结果页和背压批次。首版实测 6,304／6,168 ms；分项显示原生仍有重复 UTF-16 计数，再针对纯 ASCII 复用字节长度，最终结果见上表及原始分项。普通文档的既有搜索路径不扩大为工作区搜索。

密集 `x` 查询完整计出 83,558,400 处、索引约 131,072,000 字节，能够绕回并选中最后一处，前端页最多 128 处。这里的完整计数不等于全部同时高亮。最终 XTest 样本 source／live 分别为 17,281／16,242 ms，20 ms 观察定时器的最大间隔分别为 147／115 ms。完整两模式流程每 250 ms 采样，应用和 WebKit 进程 RSS 求和峰值 741,560 KiB（共享页可能重复计算）；cgroup 匿名内存峰值约 1.58 GiB，包含独立测试进程，文件缓存另列。输入期间从控件聚焦、Ctrl+Home、系统按键到版本改变的整段测量为约 360／376 ms；它包含测试传输、定位、批次提交及轮询，不能冒充单次按键延迟或已满足 200 ms 跳转目标。

## 替换安全与原生闭环

- 所有替换先提交已接收的输入，再按文档版本准备前后临时快照；准备期间暂时只读并显示取消按钮。原生分批释放锁，准备成功后再次检查版本，单次切换正文。准备失败或提交前取消都不改变当前正文和用户磁盘文件。
- 单项／全部替换均使用原生完整索引。前端历史仅保存不透明 token 和选区；整笔撤销／重做在原生侧切换快照，保存继续走现有磁盘冲突保护，没有把全文或百万个 Change 对象送到前端。
- 快照保留原编码；Rust 回归核对 UTF-16LE BOM、CRLF、中文和 emoji 的输出字节。独立 Unicode 原生界面验证 `İ` 的大小写展开、希腊末尾 sigma、emoji 的 UTF-16 位置、批次边界、大小写开关和字面 `$1😀` 替换。
- 索引最多 512 MiB、历史前后快照累计最多 4 GiB／文档；单逻辑行最多 8 MiB、查询最多 65,536 UTF-16 单元。超限明确失败而不是把部分结果标记完整。历史保留至文档关闭，预算用尽提示保存重开；尚不声称崩溃后临时文件回收已验收。
- 回归覆盖取消准备、过期版本、旧查询代次、无效历史转换、预算失败、准备 I/O 状态失败，以及取消／关闭后的索引和历史目录释放。I/O 失败包含受控注入，不冒充真实磁盘写满。

100 MiB source/live 各 10 个场景通过：头／中／尾／空查询、完整密集结果与末项导航、快速重搜、搜索期间编辑、替换准备取消、单项替换、1,638,400 处全部替换、整笔撤销／重做、保存重开及恢复原文。两模式的 Unicode 界面闭环及单独原生 IPC 失败／取消验证共 5 个场景通过；失败返回值通过真实 Tauri IPC 验证，不能称作实际磁盘写满。

保存断言检查完整文件长度与 SHA-256。测试进程可读取整份预期文件，产品前端不依赖该读取。另一次新增 IPC 失败断言最初被测试请求包装器误当成 WebDriver 协议错误（实际返回 `Search was superseded`），区分业务错误后复验通过；原始失败同样保留。首次大文件历史脚本过早读取磁盘时，观察到撤销／保存队列仍有两项，保留失败证据；修正为等待保存完成、dirty=false 且队列清空后再比对。Unicode 与后续完整 XTest 闭环使用该条件。

## 原生输入工具的独立边界

WebKitWebDriver 快速重搜在两次独立运行返回 `unknown error`，驱动会话日志出现 `malloc_consolidate(): unaligned fastbin chunk detected`。应用仍能返回查询状态；cgroup 没有 OOM／OOM-kill。刷新驱动后的有界复验仍失败，未继续无限重试，也未降低安全设置或延长超时。不能据此认定纯环境问题或宣称产品根因已修复。

改用 XTest 系统按键跑同一夹具与流程；WebDriver 仅作只读观察、截图及将控件聚焦。完整两模式 20 个场景通过，快速重搜和编辑期间重搜均完成。该结果支持系统按键路径的实际可用性，不能抹去 WebDriver 快速输入的未解故障。Unicode 输入用 WebDriver 键盘路径，不能代替真实系统中文 IME。

## 剩余必办

- WebDriver 快速输入／Worker 生命周期附近的原生工具故障仍需最小复现和进程级归因；本轮 XTest 通过不替代该问题的关闭。支持的下一步是用同一脚本的 `MILKUP_NATIVE_CASE_REGEX="dense|rapid"` 缩小场景，单独捕获 WebKitWebProcess 与 driver 的退出和回溯，再以无编辑器的 Worker 页面作对照；该更小复现尚未声称已运行。
- 密集匹配、全 Unicode 大文件、混合 Markdown、极长行和长时间交互继续做性能与稳定性验证；第十三阶段 live 暖跳转的 200 ms 缺口仍保留，不用本轮搜索提升覆盖它。
- 本轮原生使用 debug 二进制与 Vite 开发前端，生产 Vite 构建通过；打包应用的 Worker 协议与资源加载仍需在发布前实测，没有发布应用。
- 真正可用系统输入法中的中文预编辑、候选提交／取消、标点、光标、撤销及保存，仍未验收。Windows/macOS 当前分支原生路径、Word 2016 互操作仍未实测。
- 窗口化表格、复杂 Markdown 块组合、长行水平阅读／换行、窄窗、辅助功能和视觉纵向节奏，仍需完整体验验收。
- 替换期间暂时只读是当前明确交互约束；超长逻辑行／索引／历史预算超限不支持部分结果替换。崩溃恢复、快照长期保留策略和跨平台清理还需专项验证。

不以测试数量、搜索加速倍数或单组截图宣称达到 Typora 级质量。
