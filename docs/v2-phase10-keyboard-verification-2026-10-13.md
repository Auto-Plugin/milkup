# 第十阶段：原生启动诊断、表格方向键与窗口化块编辑

## 起点与原生启动诊断

从远端已核验的 `4539bcc2d9e74260030c5fb3f991f5f0e6b59f79` 开始，初始工作树干净。读取第九阶段交接、启动失败及驱动日志；使用同一 pnpm 11.7 / Rust 1.99 / GTK / WebKitGTK 原生环境。没有切换模型、委派、合并 v2、强推或发布。

第九阶段留下的七组表格回归必须在产品修改前补验，不能沿用第八阶段结果。诊断过程没有降低 WebKit 沙箱、扩大权限或操作其他端口的驱动：

- Xvfb `:99` 正常响应；共享内存无占用、磁盘空间充足。进程命名空间有 648 个僵尸，PID 1 是不回收它们的 `tail`；但 pids 上限为无限、实际线程数约 740，不能据此断言进程数耗尽。没有杀其他任务进程或试图改变 PID 1。
- 不经 WebDriver 直接运行相同二进制，先出现同样的 10×10 隐藏启动窗口；随后**同一个进程在观察到的 47 秒以内显示正常 1100×760 窗口**。这证明先前现象不能一律称为永久死锁。
- WebKit Network/Web 子进程已创建，并与 proot 持续消耗 CPU；应用原生 setup 会异步清理临时文件，没有发现该清理函数同步卡住 UI 的证据。读取内核 stack/syscall 被权限拒绝后没有升级权限。
- 单独的有界诊断探针允许最多 90 秒创建会话，仅用于测量，没有更改产品或回归期限。此次实际创建会话 **5.399 秒**，首次取得编辑器及页面标记 **14.295 秒**；页面 `html-ready` 约 922 ms、`module-evaluated` 约 4887 ms、`shell-created` 约 4908 ms。原生窗口截图确认可见。
- 可以确定：统一 20 秒的客户端请求期限能在实际仍继续启动时中断等待，且客户端中断不等于服务端会话已被撤销。**冷／热启动波动的底层原因尚未完全定位**；现有证据无法在 proot 系统调用开销、WebKit 初始化及前端加载之间给出唯一归因。恢复可操作不等于启动性能合格。

首次补验原始表格套件有六组通过，第七组在准备光标的一次长方向键批次上触发 20 秒 HTTP 超时，尚未进入尾段断言。将准备动作拆成每批八个真实 WebDriver 方向键，保持所有按键、光标与保存断言及请求期限；只补验最后一组。测试增加场景过滤以免重复已通过用例。

## 产品缺陷复现

- 正确使用 view-dom 的 jsdom 配置后，两项方向键用例失败：跨单元格 ArrowRight 预期 37、实际 35（隐藏分隔符）；单元格起点 Shift+Left 预期 33、实际 32。
- source/live 各三项窗口化用例均失败：空嵌套列表无法正确退出；可见窗口外开围栏中的 `- text` 被错误续写成列表且插入 LF；反向跨窗口选区 Tab 无法缩进。
- 最初从仓库根目录直接调用 Vitest，未载入 view-dom 的 jsdom 配置，产生 `document is not defined`。这些是调用配置错误，不计作产品复现；保留正确配置下的独立失败日志。

## 最小修复与范围

- 常规 live 表格方向键按单元格导航，跨越隐藏管道符及分隔行；Shift 方向键限制在当前单元格，避免意外选中 Markdown 分隔符。处理 Unicode 字形、转义管道和 `<br>` 原子跨度。新增浏览器及原生脚本覆盖；窗口化表格仍不在本次支持范围。
- 窗口化 source/live 支持列表续行、空列表退出、嵌套缩退、代码缩进与 CRLF；跨窗口反向选区 Tab/Shift+Tab 作为一次编辑并保持选区方向。围栏状态从文档前缀分批扫描、按版本缓存，不再仅凭可见窗口把代码里的列表样式文本续写成列表。
- 大文件编辑批次保留前后选区，成功的原生版本确认后才记录撤销历史；内存窗口与原生窗口均恢复选区。切换文档取消旧的排队操作，普通字符 Backspace 不触发全前缀扫描。
- 正常 Tauri + X11 XTest 实测又发现一个真实产品缺陷：四次撤销的磁盘正文均恢复正确，但随后输入 `x` 落在第二行起点 UTF-16 14，而不是第一行末尾 12。代码检查发现 `LargeDocumentSource.lineAtPosition()` 原先无实现、直接抛错，新加入的撤销选区恢复因此中断。补齐基于原生 UTF-16 行起点的二分定位，测试覆盖 emoji/CRLF/末尾空行、非法位置和读取期间版本变化。**该最后修复仅完成非原生回归，尚未重新进行原生闭环验收。**

范围限制：大文档前缀围栏扫描仍可能昂贵；窗口外长围栏的 live 视觉投影、复杂嵌套块语义、窗口化表格、10/100 MiB 完整延迟矩阵不在已验证声明中。没有扩大成 Markdown 重写。

## 后续原生尝试与停止重试的依据

新语义脚本经历以下有界尝试，均保留原始日志，不能算完整通过：

1. 原 20 秒会话交互期限失败于首次页面轮询。
2. 启动单独限 60 秒；另一次会话约 48 秒返回，X11 查询本身超时。确认 DELETE 会话后旧应用仍有隐藏窗口，按已记录的本任务 PID 停止应用和驱动。
3. 新建本任务独立 Xvfb `:100`，原生窗口出现耗时 44.282 秒；100,000 行数据的搜索已显示 `1/1`，但仍在扫描、尚未自动定位，随后请求超时。计数出现不等于搜索完成；不能把这一轮记作块编辑失败或成功。保留全扫描性能缺口。
4. 改为同样超过 1 MiB、约两千长行的数据，隔离块编辑与十万行搜索；新一次启动仍超过 60 秒。停止相同路径反复重试。
5. 不使用 WebDriver，以正常 CLI 打开真实测试文件，再用 XTest 系统键盘输入：列表续行、缩进、两层空项退出和四步撤销均以磁盘全量字节核对通过；随后发现上文光标偏差，本组未达到 PASS，六组整体完成数仍为零。该路径确实提供了交互证据，但不等于全部新语义通过；这次启动没有连续计时，不报告启动 SLA。

共享原生 helper 将启动会话上限设为 60 秒，编辑 HTTP 期限保持 20 秒；只在显式 `MILKUP_NATIVE_EXCLUSIVE_DISPLAY=1` 的独占测试显示上，且 PID、新观察记录、可执行路径、进程出生时间均相符时清理新应用。默认共享显示不自动发信号。单元测试验证既有进程、PID 复用与路径不符均不被误杀。最终 helper 的所有旧原生套件尚未重跑，不能外推。

## 最小恢复与交接方案

建议使用**同一已发布配置新建干净任务环境**作为隔离对照，保留旧环境。它能排除当前任务累积的进程／驱动状态，但不能保证解决 proot/WebKit/前端启动慢。无需改动安全权限或沙箱开关。

1. 新环境先记录工具链、工作树和用户修改；默认 `f713d91` 只是配置基点，不是最新成果。安全 fetch 专用 `dot/milkup-v2-quality`，核对本次交接最终完整 SHA，再以快进或新隔离工作线恢复；已有修改先保留，不能 reset/强推/合并远端 v2。
2. 关键日志、截图和报告在 `docs/evidence/v2-phase10-*`；真实失败 fixture 可由 `tests/native/x11-windowed-blocks.py --prepare` 在新的证据目录逐字重建。完整 `/tmp/milkup-v2-phase10/`（包括失败时文件、尝试日志和截图）另打本地归档及 SHA-256，保存到 `.tmp`；需要原始运行材料时复制该归档，不需要搬运 node_modules、Rust target、旧显示套接字或浏览器 profile。此前 phase9/phase10 检查点继续保留。
3. 新环境只启动一个专用显示／驱动／应用，分别记录正常 CLI 与 WebDriver 启动时间；最多各一次有界诊断，失败立即保留进程树和截图。先验证本次原生撤销光标修复，再跑六组窗口化 source/live，以及两组新增表格方向键；核对精确选区、字节、撤销／重做和真实磁盘保存。所有 PASS 之前保留本报告的未验收状态。
4. 完成本次提交推送核验后，旧环境停止代码修改，保留文件和证据，作为只读恢复来源。当前阶段已停止自己的应用 PID 85665、Vite 81142、专用 Xvfb 84886；不删除环境、不处置其他任务进程。新环境为唯一写入者，避免分叉。

本轮没有切换模型或委派；工具接口不提供独立模型档位核验。常规提交继续使用既有遗留 hooks 的单次跳过开关，完整验证结果另列，不更改 hooks 或 Git 安全配置。
