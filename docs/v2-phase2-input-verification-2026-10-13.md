# 第二阶段：组合输入取消与撤销边界

## 范围与基准

仓库仍为 `Auto-Plugin/milkup` 的同一 `v2` 工作树。阶段基准为 `6b5aec7f0aedb3f92ae457df63c3c61172d7a89a`（第一阶段三个本地提交），远端原始基准为 `f713d91d311ff22e7b19a01b3b94938b714ba375`。没有推送、发布、重建或销毁容器，没有重试系统包安装；没有模型切换或子模型委派。原生环境阻塞保持不变。

本阶段集中处理已复现的输入取消与事务历史问题，不重写内核，不扩大为完整列表／表格产品重构。

## 先失败后修复的证据

新增 `input-boundaries.test.ts` 六项回归在修改实现前 **6/6 失败**。日志：`/tmp/milkup-v2-phase2/repro-unit.log`。随后单独加入的撤销后新分支回归，在修改对应条件前失败（`repro-undo-branch.log`）。

在运行的 Chromium 桌面前端复现：

1. 输入 `AB`，左移一次，输入 `X`，Ctrl+Z：正文变成空串，而不是 `AB`。
2. 选中 `original`，分发 compositionstart/update(`zhong`)/end(`''`)：原文被 `zhong` 替换，而不是保持选区和正文。

第二条是**合成 composition 事件的浏览器逻辑复现**，不是操作系统中文输入法验收。空的最终 composition data 可能表示取消，不应回退到旧候选内容；依据 [UI Events compositionend](https://w3c.github.io/uievents/#event-type-compositionend)。

## 实现与验收矩阵

| 场景           | 修复／验收结果                                                                                  | 证据层级                                                |
| -------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 取消组合输入   | 普通及窗口化视图以最终 data 为准；空值不写入、不替换选区、不增加历史                            | DOM 单元；普通 source/live 浏览器合成事件               |
| 正常中文提交   | 提交一次；与前后普通输入分开撤销；选区替换后 undo/redo 正确                                     | DOM 单元；source/live 和约 156 KiB 窗口化内存文档浏览器 |
| 多行代码粘贴   | 粘贴为独立历史操作；保留空行；模式切换后撤销尾部输入不会连粘贴一起删掉                          | DOM 单元；浏览器 ClipboardEvent 注入                    |
| 回车与列表续行 | 回车独立历史组；原有列表前缀续行断言保留                                                        | DOM 单元                                                |
| 光标移位后输入 | 历史合并要求文档、选区、输入来源连续，不能仅依据一秒时间窗                                      | 单元；真实浏览器按键与光标位置断言                      |
| 撤销后新输入   | 存在 redo 分支时新输入不并入更早历史，旧 redo 分支正常失效                                      | core 单元（固定时间，修复前失败）                       |
| 窗口化批次     | paste/composition/enter 标记 isolate，不与相邻键入批次合并；常规连续键入仍保留批处理            | source view 单元；窗口化内存文档浏览器                  |
| 保存前 flush   | 不兼容批次同步登记，底层提交依然串行；延迟首批时必须等待后续批次；后续失败必须 reject           | 带异步 gate 和失败注入的 source view 单元               |
| 保存保护复核   | 第一阶段新建／打开／关闭、延迟保存取消、失败重试、原文／历史保护回归全保留并通过                | 完整浏览器回归                                          |
| 另存为成功标志 | 修正原有 `!session.dirty` 推断，只有收到保存结果才返回 true；取消／失败为 false；大文件错误可见 | 代码审阅；浏览器 mock 的取消／失败保留路径和 dirty 正文 |

`SourceDocumentEdit.historyGroup?: 'isolate'` 是新增的可选回调元数据。桌面 memory source 转发到核心事务；native large source 的独立回调对应独立 edit batch，但**本轮没有实际原生存储验证**。

原有 source-view 测试中“多个结构输入合成一次 native commit”的断言改为显式的独立历史批次；保留并加强了提交次数、位置、最终全文和失败断言，没有用宽松匹配绕过问题。没有新增 skip/only，没有关闭测试或吞掉提交失败。用于恢复队列继续工作的既有 catch 不作为保存成功依据，失败通过 flush 继续暴露。

## 第一阶段差异复核

- 原有两项格式修正仅改变格式。
- watcher UI 旧测试改用测试适配器事件，断言未移除；图片粘贴等待 ready 后仍检查插入和 dirty。
- document transition 保存失败／取消后保留待确认状态；取消 continuation 的对象身份检查避免后续异步结果再次替换文档。
- `recordFileSaveResult` 保存提交时捕获的版本，新版本保留 dirty，不用测试数量替代磁盘落盘证明。
- 发现并修正另存为内部成功标志不够严格的问题；这是历史路径的遗留逻辑，前端曾显示取消但内部 promise 可能对原本 clean 文档返回 true。
- 首阶段本地旧 main hooks 处理方式已记录在基线文档。本轮仍先执行 v2 检查，再使用旧 hooks 自带的单次跳过开关提交，不修改安全配置。
