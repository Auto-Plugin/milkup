# Installed document identity and output gate

The opt-in `document_health` installation workflow input extends the existing isolated pure-standard repair-health path. It tests the immutable installer selected by the recorded build run and source SHA; the test-harness SHA is recorded separately. It does not rebuild the application, publish a release, or change the old package.

The test edits/saves fixture A, exports its current contents to HTML and PDF, opens and edits/saves fixture B, exports B to both formats, discards an additional unsaved B edit during the switch back to A, and tests A's native window-close confirmation. Cancel must retain A's dirty buffer without changing either disk file. A second close uses the visible Save action; the owning PowerShell must observe normal process exit before repair/uninstall acceptance. The final A/B bytes and all intermediate file hashes are retained. Every document has a unique ASCII identity marker, and each of the four outputs must contain its own marker and exclude the other document's marker.

Editor, menu, plugin and close-confirmation changes use actual WebDriver input. File dialogs use native SendInput with exact filename readback. Native input requires the live held product process identity; export dialogs additionally require a unique direct child with the same installed executable and exact internal output-helper argument. A destruction hook and live dialog/control checks guard input. Targets are fresh, bounded files under the owned fixture root, with reparse ancestors rejected. No private application command or file-picker override is used. This is not the independent complete window/console observer audit.

The UI report cannot mark PDF content accepted. A separate bounded pypdf 6.10.0 reader checks the original PDF bytes/hash and extracted document markers after the isolated child exits. The final content audit also requires native normal-close and standard-account evidence. It fails on wrong-document PDF even when its bytes have been rehashed, truncated output, missing dirty-buffer preservation, cross-file overwrite, or forced cleanup. This marker check is not full PDF visual or Unicode fidelity.

Local preparation: six verifier positive/negative tests and twenty existing distribution/recovery tests pass. JavaScript parses and formats successfully. The C# input helper and PowerShell policy/GUI path require real Windows compilation and execution; no local mock is counted as installed acceptance. Runtime input has bounded waits and preserves failure records. No deadline, product identity, cleanup, package identity or signature gate is relaxed.
