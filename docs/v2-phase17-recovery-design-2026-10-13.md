# 第十七阶段恢复合同（实施前）

基线 `0ca868a077fe88459c227736739209ec141259c1`。架构文档把 crash recovery 列为 Rust 文件服务目标，但现实现没有恢复清单或启动交互。原子保存只保护磁盘原文件；内存草稿和 piece tree 结构不会自动重建。

本轮采用独立的、版本明确的完整恢复检查点，不把原文件当恢复载体：

- 普通文档保留按保存换行策略编码的文本；大文件在 Rust 内分块写出当前已提交版本，不送全文到前端。
- 编辑暂停 750 ms 后尝试检查点，持续编辑最多每 5 s 尝试一次。只有数据同步、SHA-256 和提交清单完成后才显示“恢复点 vN”。这不是硬实时丢失上限：排队、I/O 失败、未提交 IME/窗口化批次仍可能让恢复点更旧；界面明确显示待更新／失败。
- 保存与大文件替换准备之前尝试强制检查点，以便中断操作后至少恢复已确认版本。失败明确反馈；原文件保存仍受原子替换与冲突检测保护。
- 每个进程、文档使用独立记录，完整快照单份最多 256 MiB，最多保留当前与上一份已提交快照；写入中的临时文件不冒充恢复点。超过预算或磁盘错误显示保护失败，保留最后有效检查点。
- 异常退出后列出非活跃会话记录。恢复先验证长度和 SHA-256，再创建新副本，绝不自动覆盖原路径。原路径只作来源提示，外部修改不被吞掉。
- 暂不恢复留待下次启动；放弃本次恢复仅归档，保留数据并允许从菜单再次查看。成功打开副本后才归档原候选。中途再崩溃仍能重试。
- 不再自动删除死进程的大文件工作缓冲或未知旧临时文件；没有持久化树的旧缓冲不能保证完整恢复，应保留供人工排查。活跃进程文件一律保留。
- 不承诺恢复光标、撤销栈、未提交 IME 或应用未确认的最后输入，也不把进程 SIGKILL 验收外推成断电/介质故障保证。

测试仅使用 `/tmp/milkup-v2-phase17` 及本任务独立应用数据目录。终止前必须核验 X11 窗口 PID、命令行二进制及启动文件；保存原文件与工作文件副本。不得对未知进程或真实用户文件执行终止、覆盖或清理。
