## 脚注最小产品语义建议

1. 先冻结语法范围和 label 规则：引用 `[^label]`、定义 `[^label]: ...`、是否支持缩进续行/空段、大小写与空白归一化都必须显式。首版不支持的嵌套容器定义保留源码并提示，不能用一条跨全文 regex 假装完整解析。代码围栏、行内代码、转义、HTML 内示例不得登记为脚注。
2. 建议按首次有效引用顺序编号，多次引用同一定义共享编号但保留各自可返回的来源。重复定义采用稳定的“首个有效定义生效 + 重复诊断”，不静默拼接或覆盖；若选择拒绝歧义，应在 UI/导出同样拒绝。未知 ID 保持可识别的未解析状态，不能跳到第 0 行或创建伪链接；未引用定义仍可编辑且应可发现。
3. 索引状态区分 complete / scanning / invalidated / truncated / cancelled。只有完整扫描才能判定全局缺失、唯一性和最终编号。引用与定义分处窗口、文件首尾、超扫描预算时不能把“未加载”视为“不存在”。编辑重排、切文档、重开文件后必须依据 documentId/version 更新，旧结果不得写回新文档；跨两个应用窗口也不得共用裸 label 全局缓存。
4. live 引用应有可访问名称和真实可聚焦控件；Tab 可到达，Enter 激活，采用按钮语义时 Space 也激活。定义处有回到具体引用的入口；多次引用不能只回第一处。source 的原生文本编辑/选区不变，不能抢普通方向键、IME/composition 或输入框按键。返回目标包含文档身份与版本，过期时明确提示或经重新解析定位，不能跳到旧偏移。
5. 导航不应修改正文/dirty/history；新增、修改引用/定义才走编辑事务，保留反选、UTF-16 偏移、Unicode 与 CRLF。远处定义与当前引用的原子编辑不能靠先改正文再异步补定义。若公开事务不能安全覆盖两个位置，应缩小首版操作并明确说明，或增加受约束多范围快照合同。
6. 插件停用、卸载、崩溃、全部禁用后仍可读写原始 Markdown。异步索引/渲染取消后不得迟到更新 UI、导航或编辑。

## 可复用能力与合同缺口

- SDK 0.3.2 `documents.scan` 已有 documentId/version、流式 batch、progress、取消及完整性原因，可复用生命周期。现有 query 仅 text / regexp / markdownHeadings，**没有脚注语义索引**；regexp 的候选命中还需可信块上下文解析。
- 当前 `parseMarkdownWindow` 只解析本次行窗口，不能自然获得窗口外定义。建议提供有界、可取消、版本一致的语义扫描/索引；通用宿主负责文档快照和预算，语法实现承担定义/引用识别，插件负责业务 UI。
- 当前 `ui.revealLine(line)` 不显式携带目标 documentId/version/range。脚注建议新增兼容性的受版本约束导航请求及结果，必要时返回可撤销的导航位置令牌；不扩任意文件读取，也不让插件操作宿主 DOM。
- 当前 editing.capture/apply 是有界选区事务，64 Ki UTF-16 / 256 行 / 64 changes，具版本/选区/保存位置与生命周期约束。应复用，不改旧 `context.editor.dispatch`，不为脚注放开任意全文修改。
- 当前 declarative syntax extension 是受限正则、按单行 block/inline 处理，不能单独表达跨行定义、多行公式或全局引用解析。`parseMarkdownAst` 与 export 当前也没有统一接入扩展语义，须解决显示/编辑/导出的同义性，避免各写一份不一致 regex。

## P5 输出合同应预留

| 合同部分   | 最小要求                                                                                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文档输入   | 绑定 documentId/version 的不可变输出会话；大文件有界读取/流式处理、取消/进度、额度和过期结果；不能要求把所有文档全文装入插件。                                                          |
| 语义一致性 | 同一语法版本/功能清单；标题、任务、删除线、表格、代码、数学、图表、脚注定义/引用共享解释。脚注稳定且无冲突的 anchor、编号与多个 backlink。缺功能明确诊断/原文回退策略，不能静默删内容。 |
| 资源       | 宿主签发本地资源句柄，选择复制/嵌入等输出策略，保留授权来源和预算；无隐式网络请求。公式字体、图表资源、图片均须离线可用或明确失败。                                                     |
| 安全内容   | HTML URL scheme 策略、链接/图片区分；diagram SVG/HTML 不允许脚本或未经授权外链。现有 exporter 仅属性转义，没有 scheme 过滤，不能把“已 escape”当安全链接证明。                           |
| 输出目标   | 受控选择器/写入句柄、原子完成、失败/取消只清理本轮临时产物，原文及原图片不受影响；输出资源与正文一起形成一致结果。                                                                      |
| PDF/打印   | 真实渲染结果核验中文/Unicode、字体、分页、表格跨页、公式/图表、脚注布局及链接；PDF header 检查和 font strategy 元数据不足以证明字体嵌入或视觉正确。                                     |

现有 `ExportDocument` 只有 documentId/text/title，输出请求缺版本、取消、预算与受控目标；`resolveUrl` 回调并非资源权限合同。P5 可复用纯转换与测试夹具，但不能据此宣称独立导出/打印产品已实现。

## 回归验收清单

- 解析语料：有效/半输入/错误公式与图表；转义 `$`、货币、代码内分隔符；脚注前向/后向/重复/未知/未引用定义、重复引用、续行/空段、Unicode label、CRLF、嵌套容器与代码示例。断言源码与精确范围，不只截图。
- 脚注文档级：引用和定义跨窗口、定义在 EOF、重复定义在不可见窗口、扫描中编辑/切文档/取消/超限/卸载；只有 complete 后才报确切缺失，旧版本不得导航。两个文档同 ID label、两个窗口编辑同一路径分别验证。
- 真实交互：普通/窗口化 × source/live；鼠标与键盘正向导航和回到具体引用、未知/重复诊断；导航不 dirty、不吞字符；反选/IME/native 输入键保持；新增编辑独立 undo/redo、整文件字节保存重开。
- 渲染/可访问：light/dark、窄窗、100/125/150/200% 的公式/图表/脚注及面板，焦点可见、正文无遮挡、长公式/图横向访问；屏幕阅读器与系统 IME 需实际验证，不能从 DOM 属性推导完成。
- 生命周期/隔离：扩展禁用与全部插件禁用仍能基本编辑、保存、恢复；渲染异常/超时/资源失败保留源码，不重复提交或迟到更新。
- P5：实际打开导出 HTML/PDF/打印结果，比较脚注编号/多返回链接、strike/task、公式/图表和本地图片；取消/目标拒绝/资源丢失/额度边界不覆盖原文；检查危险 URL/SVG 及离线行为。

## 不能在本轮悄然销项的边界

- P4 资源后续：图片拖入、网络图片、未命名草稿持久暂存仍未实现；复杂引用式图片与实体 URL 仍明确拒绝。
- P4 迁移预算：最多 4 Mi UTF-16 / 4096 引用；超文本预算继续流式检查 `![`，无候选才可证明无需资源迁移，有候选则拒绝。不是任意大图片文档另存成功保证。
- P5：显式恢复导出仅 Markdown，不是图片归档；离线输出资源打包属于待建输出合同。
- 兼容缺陷应独立跟踪：通用 inline URL 平衡括号、深层嵌套解析、export strike/task 漂移、URL scheme 策略。未在本次只读审计中修复。
- Windows 构建/实测、系统 IME/读屏、上传/发布均不能沿用 Linux 历史结果声称完成，本任务未执行。
