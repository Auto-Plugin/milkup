# Test-only token observation preflight

The isolated token workflow builds the private Rust library test executable, not
the desktop product. It runs only fixed ignored parent/child probes in separate
fresh pure-standard and filtered-admin accounts. No COM, WebView, JavaScript,
Mermaid document, linked-token impersonation or process elevation is exercised. The
production rendering admission policy is unchanged in this diagnostic candidate.

The retained local wrapper regression report has 30 passed cases, including
actual local fixed-argv, delayed nonzero-exit/EOF, and timeout process stubs. The
three Unix-only process cases are skipped on Windows; the remaining 27 pure
fixtures and C# compilation also run in the Windows workflow. Local success is
not a Windows token observation or product acceptance.

The workflow YAML and all six embedded PowerShell scripts parsed locally.
Read-only diagnostics and exact account/resource cleanup must both succeed; a
missing or incomplete observation remains a failed run. Uploaded evidence is a
closed list of bounded JSON/log files with byte lengths and SHA-256, without the
probe executable or user profiles.

Scope clarification: the shared launcher's existing negative-write access test
temporarily impersonates the low-privilege AppContainer child token and reverts.
The linked-token experiment does not use returned linked handles for that test;
both actual observation contexts separately prove thread-token absence.
