# Native catalog milestone02 — implementation checkpoint

Baseline: `633a6d7910f9fa44b9fa89628967e6b7105071ec`. Product ownership: `plugin_catalog.rs`, production DOM/icon catalog readers and native catalog wire appendix. Root owns command registration and all Cargo/UI execution.

- Single wire contract: `docs/v2-product-phase6-native-catalog-wire.md`, shared with adapter and manager. Four state commands and a generation-bound Worker module snapshot reader; no plugin-facing raw native catalog API.
- Native-generated immutable generation directories; portable archive path/collision/base64/entry validation before stage; file hashes and canonical manifest/capability fingerprints. Content is read using descriptor-relative no-follow and the returned actual bytes are checked against seals.
- Unix global process mutex plus per-root filesystem lock; entry CAS; whole-catalog checksummed envelope replacement, previous valid backup, file/directory fsync. Corrupt-primary backup recovery clears enable intent/approval and preserves corrupt bytes, rather than reviving potentially revoked authority.
- Durable prepared/trial, exact transaction/fingerprint/revision approval, restricted-trial commit, abort, active approval/revocation, startup attempt completion, previous verified rollback, tombstone and retryable generation GC. User data/storage are not removed. Native commit assumes trusted manager has completed restricted activation; native does not itself implement the JS side-effect gate.
- Migration first preserves exact raw bytes, then requires trusted shared-schema validation hints bound to the exact UTF-8 raw SHA-256, unique row indices and original manifest values. Native matches hinted/raw/on-disk manifests and independently validates native-derived legacy package contents. Unknown old scope approval is not inherited; valid packages become disabled/unapproved prepared candidates. A single receipt is committed after processing; unvalidated records and missing/changed old packages are quarantined; new staging failure aborts migration so retry remains possible. Legacy directories are retained, not silently deleted.
- Limits: manifest 1MiB; file 32MiB; decoded package 64MiB; 4096 files; path 1024 UTF-8 bytes/32 components; catalog 16MiB/512 records. Space check reserves stage bytes plus 16MiB headroom and two maximum catalog writes. Existing official Mermaid size is within these limits.

## Final native reader and cleanup boundaries

Production DOM preparation and icon reading use catalog generation seals; the old installed-package snapshot readers are retained only as test fixtures. Worker loading returns the exact seal-verified module bytes, not an arbitrary path. DOM start rechecks live catalog authorization and exact module SHA before consuming its lease; same manifest with different current bytes is rejected. DOM stop returns true only for a matching instance whose guardian cleanup/exit was confirmed, false for an unknown instance, and error for unconfirmed cleanup. Failed release retains ownership; starting another instance for that plugin is refused while any retained instance exists. Per-plugin/all-plugin cleanup attempts remaining leases even if one fails. Existing 2-second render and guardian cleanup deadlines are unchanged.

GC retains verified generations referenced by the current catalog **and its valid backup**. This can temporarily retain one extra generation beyond current/previous; it is required recovery material, not a storage leak silently cleared under pressure. Tombstone removal still permits package GC while preserving user data.

Five ignored tests in the full native invocation were explicit: private output-helper entry; real WebKit PDF requiring sandbox/display; private guardian subprocess fixture; real WebKit DOM/runtime integration requiring fresh executable/display; explicit legacy search profiling baseline. Existing tests may spawn their own non-GUI subprocess fixtures, but this log is not a new real WebKit/UI/platform acceptance. The only compiler warning was pre-existing `piece_tree.rs` test `Arc` import.

## Migration schema isolation follow-up

Root reproduced a real availability defect: the narrower native security manifest checks admitted missing-name/invalid-contributions/invalid-settings legacy manifests, causing the strict adapter to reject the whole returned catalog. `migration-poison-red.log` preserves the failed regression (expected one valid entry, got four). The implementation now requires the shared parser's row decisions rather than duplicating its complete schema in Rust. Only the trusted host can supply this validation; the hint is not an independent signature or authorization exposed to plugins. Missing hints cannot trigger an unsafe import fallback.

Added native regressions cover exact raw backup before missing/invalid hint rejection; digest/version/index/manifest/diagnostic bounds; corrupt root receipt/idempotence; missing or changed on-disk legacy package isolation. Existing migration staging-failure retry and duplicate-ID checks remain. Root's final native catalog run completed **24 passed, 0 failed, 0 ignored**; `catalog-migration-final.log` is an unchanged copy. The mixed-schema regression now passes with only the valid row imported. This is unit/fault-injection verification, not real migration UI or cross-platform acceptance.
