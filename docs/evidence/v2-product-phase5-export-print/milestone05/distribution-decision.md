# P5 输出功能发行决策：优先复用已有系统运行时

记录日期：2026-10-19。用户约束是尽量不增大默认安装包，优先复用机器已有运行时。本记录只核对发行证据；没有安装依赖、构建浏览器或字体，也没有修改产品源码、Windows、Runtime、Library。

## 当前决策

Linux PDF／打印仅作为复用**已有系统 Chromium** 的可选输出能力。MilkUp 与独立插件均不捆绑浏览器或字体，不自动下载浏览器，不通过新增 deb/rpm 强制依赖让所有用户安装 Chromium。机器没有受支持的系统浏览器时明确失败；HTML 导出仍不需要 Chromium。不得静默回退到已证实丢失原文字形对应关系的旧 WebKit PDF 路径。

当前 native 查找固定 `/usr/bin/chromium`，要求系统路径不可由应用写入，保留 Chromium 沙箱；缺失时返回现有 `unsupported` 错误。安全或流式 CDP 能力不可用时停止。**当前仅 Chromium 154.0.8037.57 实测通过**，没有推导更低版本的最低支持保证，也未做跨发行版验收。

本页是当前发行决策，优先于早期 `chromium-unicode/README.md` 的可行性讨论。早期文档中的系统依赖成本是启用该可选能力的环境成本，不能解释为主安装包的新增强制依赖或默认下载量。原始实验文件保留原字节，避免重写历史证据。

独立 `plugins/export-print` 继续只依赖公开 SDK，拥有格式、范围、选项、进度、取消和错误 UI。受控转换、文件目标授权和打印提交仍由通用宿主服务执行。插件的可独立安装属性不会扩大其文件系统或进程权限。

## 本机 Installed-Size 精确字段值

只读命令：

```sh
dpkg-query -W -f='${binary:Package}\t${Version}\t${Installed-Size}\n' chromium chromium-common chromium-sandbox
chromium --version
```

| 本机包 | 本机已安装版本 | Installed-Size 字段（KiB） |
| --- | --- | ---: |
| chromium | 154.0.8037.57-1~deb13u1 | 319700 |
| chromium-common | 154.0.8037.57-1~deb13u1 | 65876 |
| chromium-sandbox | 154.0.8037.57-1~deb13u1 | 408 |
| 三包字段合计 | Debian GNU/Linux 13（trixie） | **385984** |

浏览器版本命令输出：`Chromium 154.0.8037.57 built on Debian GNU/Linux 13 (trixie)`。

三包字段合计换算为 **376.9375 MiB**。这些字段是软件包维护者提供的安装占用估计，实际文件系统块大小、属性及维护脚本会影响真实磁盘占用；字段单位是 KiB。[Debian Policy 的 Installed-Size 定义](https://www.debian.org/doc/debian-policy/ch-controlfields.html#installed-size)

这三个包的字段合计不包含整个共享库、字体等依赖树，也不是 `.deb` 压缩下载大小、网络传输量或新增安装磁盘量。已有 Chromium 的机器无需为了本功能再安装一份浏览器；缺失机器若由用户自行安装，具体下载量和新增占用取决于发行版、所选版本、缓存及已有依赖，**本次没有测量**。

**不能把约 377 MiB 写成 MilkUp 安装包增量，也不能写成所有用户必需下载或额外安装的体积。**

## 方案取舍

| 方案 | 默认包体积／运行时影响 | 本轮结论 |
| --- | --- | --- |
| 复用已经存在的系统 Chromium | 不向应用或插件复制浏览器；默认不强制安装；应用适配代码增量待构建测量 | 当前采用；Linux 可选能力，缺失明确失败 |
| 修复并继续复用系统 WebKit | 若修复由系统运行时提供，可避免新增第二套浏览器；但引擎修复、分发与回归成本仍存在 | 保留研究方向，当前没有已验证可部署的轻量引擎修复 |
| 在宿主或插件内捆绑 Chromium／字体 | 把浏览器或字体文件加入某个分发包；移入插件只改变负担位置 | 不采用，不符合本轮默认轻量约束 |
| 自动下载“输出 Runtime”或新增强制包依赖 | 可能保持主包小，但把较大安装／网络成本转移到安装后，并改变默认依赖 | 不采用；未新增 Runtime 下载或自动安装路径 |
| 可选独立导出插件 | UI／业务能力本来已是独立公开 SDK 插件，可不安装／不启用；转换仍受宿主授权边界约束 | 保持现状；插件本身不携带引擎 |
| 另做可选原生后端分发组件 | 有机会进一步拆分适配代码，但新增协议、版本、签名、升级和权限维护面；不能据此断言更小 | 未实现，未验证；不得给插件任意路径／任意进程接口来绕开受控服务 |

WebKit 2.52.6 的现有证据显示绘制链没有向 Skia PDF 传递足够的原文簇信息；相同字形对应不同 Unicode 字符时，后处理不能恢复已丢失的信息。NFKC、换字体或插入隐藏文本不构成完整修复。真实 CSS 连续避分页候选也未解决所有长块标题孤行；拆首行／首项改变容器语义且表格仍失败。因此，不能把当前候选描述为“已完成的轻量 WebKit 修复”，也不能为保证轻量而悄悄退回已知错误的 PDF 输出。原始引擎源码证据保存在 `native-unicode/sources/manifest.json`；PDFium/Chromium 的对照见 [引擎比较](./chromium-unicode/README.md) 和 [实际 native helper 验收](./chromium-controlled/README.md)。

## 平台与保真边界

当前原生输出后端只实现 Linux。Windows／macOS 的原生选择器、PDF、打印及相关原子输出路径明确不受支持；安装独立插件不代表这些平台已有可用后端。本轮没有评估或验证这些平台可复用的系统打印实现，不推测其功能可行性、包体积或开发工作量，也没有构建其产物。

Linux 样例已证明 Chromium 生成的 PDF 保留 ActualText，Poppler／MuPDF 可以恢复测试中的汉字与部首／兼容字区别、组合字符、引号、emoji 和图表文字。仍保留阅读器差异：pypdf 的该提取路径忽略 ActualText，Arabic 阅读顺序未通过；不能保证所有阅读器的任意文本逐字复制。物理打印、发行版覆盖以及实际压缩安装包增量也不能由这组 Linux helper 结果代验。
