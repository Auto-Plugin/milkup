# Generic isolated DOM render task: implementation audit

Status: external prototype prepared; first Rust compile failed on API imports and enum comparison. Those external-only errors were corrected; build-02 and build-03 passed. The mechanism-01 launch was rejected by automatic approval before process creation. No prototype UI or Mermaid render has run. This document distinguishes implementation facts, proposed contracts, and unverified platform boundaries.

## Concrete implementation choice

Use a separately launched trusted helper executable with Wry 0.55.1 and Tao 0.35.3, matching the application's locked versions. It owns one GTK event loop on Linux, one fresh ephemeral WebKit context, and no Tauri application bridge. It loads a fixed bootstrap and the plugin's approved offline engine/resources from an immutable inventory. The parent owns the process lifetime, deadline, input/output bounds and generation. The host has no diagram plugin ID or Mermaid-specific parser.

An iframe does not supply a portable independently killable process or event loop. A timer on an event loop blocked by synchronous JavaScript cannot arbitrate its own timeout. A Worker has an independent event loop but lacks real SVG/font layout; jsdom explicitly omits layout and returns dummy geometry. Neither establishes the required DOM measurement contract. [HTML event loops](https://html.spec.whatwg.org/multipage/webappapis.html#event-loops), [jsdom limitations](https://github.com/jsdom/jsdom#unimplemented-parts-of-the-web-platform).

The selected helper is still an experiment. A separate process alone is not a complete filesystem/network sandbox. WebKit's renderer sandbox plus explicit resource/permission policy must be tested, and the trusted native helper must expose no arbitrary path, URL, command or script operation.

## Actual Linux API boundaries

Local sources: Cargo registry `wry-0.55.1`, `tao-0.35.3`, `webkit2gtk-2.0.2`; repository Cargo.lock also locks Tauri 2.11.5 and runtime-wry 2.11.4.

* Wry `with_incognito(true)` creates `WebContext::new_ephemeral()` on Linux. `with_related_view` explicitly shares a WebProcess and must not be used for isolation.
* Wry `with_custom_protocol` handles registered scheme bytes; it does not intercept arbitrary HTTP/file/subresource traffic. The Linux navigation handler receives navigation policy decisions, not every subresource request. Downloads default to allowed unless a handler denies them.
* The helper gets the native WebView via `WebViewExtUnix::webview()`. Before first load it explicitly enables the context sandbox and disables file-origin access, universal file-origin access, WebRTC/media streams, WebGL, storage, DNS prefetch, automatic windows and developer extras. It denies permission requests, file chooser requests, downloads, script dialogs and new windows. The sandbox setting must precede WebProcess creation; the prototype builds without an initial URL and then configures before `load_url`. This ordering still needs runtime verification. [WebKit sandbox API](https://webkitgtk.org/reference/webkit2gtk/unstable/method.WebContext.set_sandbox_enabled.html).
* Complete request cancellation uses **WebKitWebPage::send-request in a native WebProcess extension**, not a UI-process Wry callback. It fires before sending and again on redirects; returning TRUE cancels. Consequently the Linux package needs an additional reviewed `.so`, an explicit extension directory, and startup evidence that it actually loaded. `resource_guard.c` is that prototype extension. [WebProcess send-request contract](https://webkitgtk.org/reference/webkit2gtk-web-extension/2.42.5/signal.WebPage.send-request.html).
* `evaluate_script_with_callback` is the current native request/result primitive: the parent sends a bounded fixed task to the helper, and trusted helper code invokes one fixed bootstrap function. The callback returns a serialized result; no plugin-supplied JavaScript is interpolated. Wry internally installs an IPC JavaScript stub even without an application IPC handler. The accurate statement is **no Tauri/app-command capability**, not absence of every native browser messaging mechanism. Production must keep result frames typed, bounded and detached from application authority.
* WebView `stop_loading` cancels loads, not a running infinite JavaScript loop. `terminate_web_process` exists since WebKit 2.34, but only terminates the associated WebProcess, not all helper/network/GPU descendants. Neither alone is whole-job cleanup. [Stop-loading API](https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.stop_loading.html), [terminate-WebProcess API](https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.terminate_web_process.html).

## Resource inventory, CSP and fonts

The **mechanism probe** admits exactly two GET URIs: `milkup-render://job/index.html` and `milkup-render://job/engine.js`. Both custom protocol dispatch and the WebProcess extension enforce these exact strings. The bootstrap document carries its CSP in a response header, so inserting or editing a meta element cannot relax that header policy. Script source is the fixed engine URI; connect, fonts, images, frames, workers, objects and form submission are denied. Inline style is permitted only inside this disposable helper for SVG layout. No user HTML is accepted.

Two URIs suffice only for the fixed getBBox/loop probe. They **do not** establish full Mermaid/font support. The approved official single-module Mermaid 12.2.0 bundle is 5,254,581 bytes, SHA-256 `043c33385b8b41bb628872f4e419c7f20886403152b045736382db36072d8c0c`; it would need an explicit third module URI, an ES-module bootstrap and a revised exact allowlist. Bundled fonts require additional immutable inventory URIs, MIME/size/digest checks and a restricted font-src policy. The current probe deliberately uses installed system fonts and permits no font downloads. A final font inventory/license audit and cross-platform metrics comparison remain required. Mermaid documents that fonts must load before rendering to avoid incorrect labels. [Mermaid usage and font loading](https://mermaid.js.org/config/usage.html).

A production helper may accept a plugin inventory of exact digest-verified resource IDs; it must not turn paths or URL prefixes into broad filesystem/network grants. It must also deny arbitrary navigation, redirects and downloads independently of CSP. A compromised engine cannot be allowed to replace the native policy. The native extension and response headers are trusted host artifacts, separate from engine bytes.

## Deadline and cleanup contract

Preparation has a separate 10-second bound for helper creation, module compilation and readiness. Rendering has a fixed 2-second bound beginning immediately before native dispatch; the requested source's parse, layout, SVG serialization and bounded result transfer all belong inside it. Prewarming cannot perform the request's parse/layout off the clock. A nested helper may not silently reset an already-running worker deadline: production routing must propagate the original remaining budget or make the native supervisor the owner of the entire renderer invocation.

The external Python mechanism supervisor uses monotonic time, never accepts a frame at/after the cutoff, and is independent of the helper event loop. It runs getBBox twice in one helper, then a synchronous `while(true)` and kills the owned process group at the deadline. It records PID birth, process group, descendant lineage, states and CPU ticks. Linux subreaper mode permits explicit reaping of adopted descendants. Escaped descendants are generation-checked and cleaned individually, but their existence makes the group-only containment proof fail. No broad pkill is used. Deadline enforcement is not a hard real-time scheduling promise; actual kill latency must be measured.

`CommandExt::process_group(0)` establishes a new group, but a descendant can create a new session/group; ordinary process-group kill is not a universal containment guarantee. A delegated cgroup with `cgroup.kill` is stronger if the desktop runtime actually has one; this experiment does not assume those privileges. [Rust process groups](https://doc.rust-lang.org/std/os/unix/process/trait.CommandExt.html#method.process_group), [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html).

Existing repository `plugin_sidecar.rs` uses direct `Child.kill()` plus `wait()`. That is adequate only for a child with no escaping descendants, and must not be advertised as killing a WebKit process tree. The new mechanism cannot simply reuse that cleanup assertion unchanged.

## Cross-platform status

**Linux:** native request interception and process ownership can be exercised with the installed WebKitGTK/sysroot. The planned temporary mount namespace maps WebKit helper binaries without modifying the host or disabling WebKit sandboxing. No runtime proof is claimed yet.

**Windows:** use a unique WebView2 user-data folder/environment per helper, because multiple environments sharing a folder share a browser process collection. A native Job Object assigned before helper execution can own descendants; nested jobs, WebView2 process behavior and breakaway restrictions require actual Windows tests. WebResourceRequested filters and navigation/permission/new-window/dialog policies are separate requirements. Closing a controller is graceful lifecycle, not a hard deadline guarantee. [WebView2 process model](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-model), [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects), [WebView2 interfaces](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2?view=webview2-1.0.3537.50).

**macOS:** public WKWebView bindings expose stopLoading and process-terminated notifications, but no equivalent public method to kill a particular WebContent process. Custom scheme handling covers registered schemes; network denial also needs reviewed content rules. WebKit XPC process lifetime cannot be assumed to follow the helper's POSIX group. Until whole-job termination and resource denial are proven through supported APIs, the capability must remain unavailable rather than claiming equivalent enforcement. [WKURLSchemeHandler](https://developer.apple.com/documentation/webkit/wkurlschemehandler), [WKContentRuleListStore](https://developer.apple.com/documentation/webkit/wkcontentruleliststore).

## Result and export boundary

Proposed public input: bounded source/options/theme/viewport and opaque engine/resource handles. Output: bounded static SVG (or a typed safe SVG tree) plus dimensions and provenance. The host independently validates the whole output; unsupported nodes/attributes fail the whole render with accessible source fallback. No raw innerHTML, scripts, event handlers, foreignObject, external references, animation or Mermaid bindFunctions cross into the editor. Render as an inert validated image; interactive Mermaid DOM is explicitly outside this first contract.

P5 export should consume the same accepted static artifact and record engine/font/resource hashes, theme and dimensions. Export must not execute the diagram engine or fetch resources. This is a proposed interface, not implemented export support.
