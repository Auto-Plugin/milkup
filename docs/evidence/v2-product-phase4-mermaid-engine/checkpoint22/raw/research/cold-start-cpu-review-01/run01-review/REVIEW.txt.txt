范围：root 明确 GO 且 native 已冻结后，只读原始完成产物；未运行 native、未读 live /proc、未重试或清理。审查产物单独写于 run01-review。

权限边界
已有证据直接证明 guardian environ 返回 EACCES；没有证明所有 proc 文件都不可读。失败前已做 guardian stat、精确 helper argv，随后读取额外的环境一致性检查失败。此 run 没有记录造成权限拒绝的完整内核访问判定、dumpable 状态或 proc mount 权限链，不能断言唯一原因是某个 sandbox 设置或特定 Linux 安全开关。审查没有改权限、关闭 sandbox 或越权重读。

独立 harness setup 失败
failure.json 原错误：“Native startup did not produce one owned Milkup window within 60000ms; editing assertions were not started”。results.json=[]。startup helper 第43/67行精确匹配 WM_CLASS 的 milkup-desktop；原 xwininfo 留证窗口实际 class 为 diagnostic-only-milkup-desktop，标题 milkup 窗口确实存在。因此是诊断二进制 basename 改动造成原 startup 识别失败；cold assertion 未开始。这不是原产品冷 gate 的复测结果，既不证明原失败被修复，也不是新产品 gate failure。

Native capture 与 CPU 分开
native-capture complete.json/status.json 相等且 final/diagnosticClosed=true；attempted=enqueued=written=9；queueFull/disconnected/oversize/capped/ioErrors/incompleteTiming/inFlight 均0。实际9行=1 guardian-spawn +8 render-accepted，sequence连续、owner/App PID+birth一致。8 个 wire UTF8 bytes/SHA256/requestId 都通过独立核验。CPU guardian 环境检查失败并不取消 native创建记录的独立价值。
原 driver 有 render_1..render_8 dispatch，没有 deadline-observed。不能仅凭缺少 deadline 或只有 dispatch 宣称渲染成功；本次没有进入图像 gate，native日志为best-effort。
原 capture 后台 writerThreadCpuNs=240,684,198（240.684198 ms），属 App 自身 CPU；captureTotalNs=119,826（0.119826 ms），captureMaxNs=45,758（0.045758 ms），是同步capture elapsed wall时间。不能将 writer CPU、capture wall 和缺失的 App CPU delta 相加。writer范围贯穿约一分钟捕获，不与失败observer的4.254s窗口等同。

v02 的最小纠正与剩余边界
新 candidate-v02 保留 v01 原字节。可读的 guardian 环境必须精确匹配；只有 PermissionError 可记为 unavailable/errno、matched=null。此降级要求来自预置独占 App sink 的 guardian-spawn schema+来源文件标识、owner/guardian PID+birth、current PPID、精确argv、双stat重验全通过；instance只取native创建记录，不猜测。没有nativeproof或可读instance mismatch仍失败。
