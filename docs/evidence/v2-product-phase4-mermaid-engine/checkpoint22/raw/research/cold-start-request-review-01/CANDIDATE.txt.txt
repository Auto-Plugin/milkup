The accepted-render branch adds only a boolean inside the existing control lock.
After unlock, while the original 2s deadline is active, the recorder makes a bounded
copy of already-serialized bytes and calls try_send. It does not hash, serialize,
write disk, wait for observer readiness, or acquire a new lock on this path. There
are bounded allocations and atomic/clock operations; this is not zero overhead.
The accepted-wire record timestamp is after control unlock. Match its exact
instanceId/requestId to the original DOM_NATIVE_TIMING dispatch timestamp to form
the authoritative window; do not use the later capture timestamp as deadline start.

Output protocol (one App writer):
  events.jsonl: schema milkup.cold-accepted-wire.v1; kinds guardian-spawn and
    render-accepted; ownerPid/ownerBirth, guardianPid/guardianBirth, pluginId,
    instanceId, requestId, monotonicNs/captureBeforeNs/captureAfterCloneNs/
    captureAfterNs, sequence. render-accepted additionally carries exact UTF-8
    wire as a JSON string, original wireBytes and SHA-256. Parse wire to recover
    the entire original message; do not confuse this with the Tauri outer envelope.
  status.json: atomic rename snapshots, including all admission/drop/write counts.
  finish.request: external harness writes this marker only to close diagnostics.
  complete.json: background writer's final drain acknowledgment, final=true.

The harness must finalize while App is alive and before app.close/session cleanup,
using its agreed bounded wait. Parse complete.json; existence alone is insufficient
because the writer may still be writing it. No complete.json, null ownerBirth,
unmatched native request key, or any drops/errors makes the diagnostic incomplete.
Required accounting: attempted=enqueued+queueFull+disconnected+oversize+capped;
written=enqueued; inFlight=0; all drop/error/incompleteTiming counters zero.
Only pre-cutoff requests are covered; future product requests remain unaffected
and are not observed after finish.request. Missing native trace records still
retain the pre-existing trace-loss limitation; this recorder does not fix trace.

Hard bounds: 8 queued records, 1MiB per accepted wire, 256 attempts eligible for
capture, 16MiB cumulative reserved wire. Queue-full attempts conservatively consume
their reserved byte allowance. JSON escaping can expand output bytes beyond input
bytes; the 16MiB limit is explicitly a logical wire cap, not on-disk file size.
There can also be one record being serialized in the writer. No cap increases
product input limits. Error/status checkpoints are written at most each event or
100ms idle iteration, which adds App CPU/I/O. writerThreadCpuNs measures background
thread CPU through the last checkpoint, excluding final status/complete encoding;
it is part of App own CPU and must not be counted again as renderer CPU.
