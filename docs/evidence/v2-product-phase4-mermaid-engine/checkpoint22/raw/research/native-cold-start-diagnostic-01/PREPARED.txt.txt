Native cold-start diagnostic 01 — STATIC CANDIDATE, NO RUNTIME / BUILD PERFORMED

Purpose and limits
Retain production08 first failure unchanged. Exercise the original coldBundledWindow
using identical fixtures, startup helpers, startup flow, sample assertions and budgets.
The old late-start UI10 CPU/transport hooks are removed. New external CPU collection
starts before the harness and binds from the native guardian-spawn identity event.
After coldBundledWindow returns, emit DIAGNOSTIC_PREFIX_STOP and fullUIAccepted:false.
This never claims full UI or production acceptance, even if the cold gate passes.
All unexecuted later workflow function definitions remain copied for auditability.
