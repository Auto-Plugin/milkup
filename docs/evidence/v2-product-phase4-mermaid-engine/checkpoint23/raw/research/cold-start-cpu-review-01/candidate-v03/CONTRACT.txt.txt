Candidate v03 external CPU observer — review only; no v03 native run performed

CLI:
python3 cpu_sampler.py --output <new-empty-dir> --app-log <driver.log> --identity-log <native-capture/events.jsonl> --binary <frozen-installed-app> --binary-sha256 <frozen-sha256>

Start before harness launches App (driver may already be ready); wait for first stdout JSON event=waiting-app. This acknowledges binary hash verification, not App identity or successful observation. Binary hashing is outside App cold execution if the integration honors this handshake. stdout subsequently contains at most app-bound and finished status for the normal flow. Keep stdin open. Send {"event":"stop"} + newline or close stdin to freeze/write; observer also freezes on first matching exact-App native deadline or App terminal. No signals are issued. Timeout is 30 seconds waiting App identity and 60 seconds total, an explicit bounded cold diagnostic, not full workflow coverage.

Identity contract:
MILKUP_COLD_REQUEST_DIAGNOSTICS identity sink events.jsonl guardian-spawn event supplies ownerPid, ownerBirth, guardianPid, guardianBirth, instanceId, monotonicNs. Require births positive exact integers; null is incomplete, never rebind later to guessed identity. Event time must be inside observer lifetime; this requires same CLOCK_MONOTONIC namespace. Validate live App pid/birth/argv; bind App exactly once. Validate guardian birth, parent=App before and after metadata reads, helper argv, and the authoritative guardian-spawn record from the configured App-owned exclusive native sink. Validate the record schema and retain source file path/device/inode. Attempt ONLY its MILKUP_INTERNAL_DOM_INSTANCE_ID environment value as an additional check. If readable it MUST match exactly; a PermissionError alone becomes an explicit instanceEnvironmentCheck=unavailable/errno record, with instanceEnvironmentMatched=null. The instance still comes exclusively from the native creation record. PermissionError with no native record proof, wrong schema, birth, parent or argv is rejected; other read errors are not relaxed. Do not dump environment. Two stat reads bracket metadata. Native timestamp is an observation time, not renderer spawn time.

No global /proc table implementation exists. Only exact guardian and already-owned descendants' /proc/PID/task directories can be enumerated; App's siblings/whole App tree are not enumerated. The identity event replaces the former App children discovery. Parent/birth validation remains necessary: trace text alone is not ownership. Child discovery records firstSeenNs and firstSampleNs and parent PID/birth. Current parent links and start times are race checked but not an atomic kernel tree snapshot. Grandchildren born and dead between discovery rounds can be missed; adopted children may first be seen only after reparenting. A same executable helper directly under guardian is labeled renderer-leader; other children remain separately labeled WebKit web/network or renderer-descendant. Thread counts and unrelated process rows are not persisted.

Sampling choice and hard bounds:
- Process-wide own utime/stime, per exact PID at 250 ms (4 Hz). 100 ms would increase recurring reads 2.5x and improve only temporal coverage, not solve missed births, missing terminal counters or causal attribution. The observed deadline is about 2 seconds; 250 ms is a starting design yielding about 8 periods when coverage exists, not a guarantee of 8 valid samples.
- Children discovery at 500 ms; a first discovered child may have already used CPU for up to the discovery cadence or longer after delays. No prefix reconstruction. Discovery starts after native guardian event is received/validated; no claim that App startup before this point was measured.
- Maximum 64 total process identities including App; maximum 128 task entries across each discovery round; maximum 128 candidate children per parent. Byte-capped reads: proc stat/schedstat/children 4096; cmdline 16384; guardian environment 65536. A task-limit failure occurs after at most remaining-limit+1 directory entries, without iterating the rest. Counters of successful task enumeration exclude a rejected over-limit listing; the failure is explicit.
- Cooperative discovery wall budget 5 ms, sample wall budget 10 ms, checked between operations. A single blocked kernel read cannot be preempted; do not call these hard real-time guarantees. Over-budget rounds record incomplete/error, never fabricate zeros.
- 2 MiB sample ring, 256 native events, 32 error examples and bounded 60-second duration. Identity metadata is capped at 64. No catch-up bursts after skipped slots. Output ring evictions, all error counts, missed slots and actual maximum lateness are retained.
- Identity log is read at 50 ms before App binds, then no faster than 250 ms. Each read <=65536 bytes, partial line <=16384 retained. An oversized line is skipped only when its bounded prefix identifies kind=render-accepted; counted as requestPayloadLinesSkipped, not identity loss. Oversized guardian/unknown lines fail observation. Complete wire payload stays with native request evidence, never enters CPU output. A multi-chunk 150 KiB payload plus subsequent guardian event is covered by a synthetic test.
- Process CPU reads 2 stat records around one leader schedstat read, per live identity. At the absolute 64-process cap, base sampling makes <=768 proc reads/s before discovery/identity work; typical tree size and actual overhead must be measured. This bound is a work count, not evidence of low actual overhead. Samples retain read brackets so offline joins can require the whole bracket inside actual request intervals.

schedstat interpretation:
/proc/PID/schedstat describes the thread-group leader's runtimeNs, runqueueWaitNs and timeslices. It is NOT the process's aggregate thread wait time. No per-thread schedstat traversal is implemented. The task traversal only discovers children. A zero counter can reflect disabled/unavailable accounting; no sched_schedstats toggle or system change is made. Missing schedstat is marked missing; no substituted zero.

Native timing joins:
Read DOM_NATIVE_TIMING from driver.log from the beginning, but accept exact App PID and event monotonic >= App birth, exact valid instance and real requestId. No request number is hardcoded as an anchor. Keep actual dispatch and deadline and log-observation delay separately. These diagnostics are best effort with possible loss. A guardian not yet bound remains guardianBound=false on the event; do not infer its identity. Native identity/capture completeness must also be checked by controller against native status.json and complete.json; CPU success alone does not establish payload completeness.

Offline analyze.py <output-dir> reads only saved JSON/NDJSON. It joins actual (instanceId,requestId) dispatch/deadline pairs. Per-PID CPU delta is accepted only between consecutive valid samples whose entire read brackets lie inside the request window. Partial edges, first unseen CPU, terminal CPU and missing samples are not interpolated. Each role stays separate; leader schedstat is kept separate from process CPU. No cgroup measurement is included in this candidate; existing independent shared-cgroup evidence must retain its own timestamps/scope if later combined.

Measured overhead fields:
summary.overhead includes observerOwnCpuNs; prelaunchHashCpuNs; afterReadyCpuNs; procReads; readTotalNs/readMaxNs; sampleTotalNs/sampleMaxNs; discoveryTotalNs/discoveryMaxNs. Log read times, discovery incomplete/error counts, sample incomplete, max late, skips, first sight/sample and skipped payload lines are separate. ObserverOwnCpuNs includes prelaunch hash and setup and must not be assigned as runtime perturbation. afterReadyCpuNs still includes idle waits and controller activity but excludes hashing. No observation overhead is subtracted from product counters.
