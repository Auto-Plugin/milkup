Discovery and evidence
Only bound guardians and owned descendants are worklist owners; App itself is not enumerated. Each owner may use its exact /proc/PID/task/TID/children and /proc/PID/fdinfo. No other scan path exists. Missing task children file retains errno, exact owner/birth/TID/path/times; missing interface is not empty children. Other errors/caps also mark incomplete. The v03 gap remains even if pidfd finds a helper.

Pidfd candidates are obtained by bounded exact-owner fdinfo enumeration, never an assumed FD number. Pid is interpreted only in the observer's proc view. NSpid is preserved, never used for cross-namespace translation. Before acceptance require live owner birth before and after, positive target Pid, live target double stat with stable birth and both PPIDs equal owner, target birth >= owner birth, and identical first/repeated raw fdinfo. Saved pidfdProof includes owner/target before/after parsed stat, raw fdinfo, Pid/NSpid, read timestamps and FD. This is direct-child evidence, not an atomic tree snapshot. Repeated fdinfo detects visible change but does not rule out same-target ABA.

Role metadata is recorded only after ownership: exact helper argv under guardian => renderer-leader; WebKit executable basenames label web/network; otherwise renderer-descendant. Newly adopted descendants retain argvEvidence rawHex, parsed argv and readStart/EndNs (4096-byte read cap). These are binding-time descriptions only; later exec is not monitored. CPU is attributed to exact pid/birth, not to an assumed immutable role. Missing WebKit labels never proves no JS CPU. FirstSeen/firstSample are explicit lower bounds; no CPU before first sight is reconstructed.

An unclassified FD read error (including ENOENT) is recorded separately from a known pidfd target exit/change/verification error. It does not discard another independently verified target. Enumeration truncation, read caps, elapsed budget and later FD failure preserve completed proofs, but mark partial coverage. A proof not admitted due to the 64-identity cap is counted as verified evidence only, not listed as an adopted pidfdTargetIdentity. Summary knownIdentities remains the sampling membership authority.

Exit and coverage semantics
CLI exit2 if terminal observer failure OR any incomplete discovery round, children-interface gap or pidfd coverage gap. It can finish controller-stop with failure=null and exit2. In the known children-interface-unavailable environment, a useful helper CPU trace is expected to retain coverage=incomplete and exit2. The wrapper MUST save harness exit and observer exit independently; observer exit2 is not a cold product assertion FAIL. Exit0 never means full tree PASS. fullRendererTreeCoverage is always false. Limited pidfd proof cannot erase missing children or claim WebKit subtree coverage.

utime/stime is process-wide own CPU. /proc/PID/schedstat is ONLY thread-group leader runtime/wait/timeslices, not aggregate process thread wait. No thread schedstat traversal or schedstats system change. Missing data remains missing, not zero. App, guardian and each descendant stay separate; no cgroup measurement or causal deadline attribution.
Actual DOM_NATIVE_TIMING App/instance/request IDs are retained; no hardcoded request anchor. analyze.py unchanged joins only actual dispatch+deadline pairs and whole sample read brackets inside them; no partial interpolation, no terminal/request-end invention. Empty intervals are unmeasured even when a mechanical sum is zero. Capture status/complete and driver tails must be independently audited.
Observer own CPU, prelaunch hash CPU, after-ready CPU, proc read counts/times, sample/discovery durations/max, late/skipped slots, first sight/sample, record drops, fdinfo status/caps and per-round counts are saved. They are measurements to inspect later, not proof of low overhead now.
