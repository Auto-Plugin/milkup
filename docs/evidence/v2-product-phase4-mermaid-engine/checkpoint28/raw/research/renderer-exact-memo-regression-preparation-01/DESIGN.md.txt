# Narrow private Sankey memo: design and first RED regression

No product implementation is included. The external renderer.test.ts extends the unchanged product test with a proposed contract, and fixture/src/renderer.ts is a byte-identical baseline copy. The sole authorized mocked Vitest run exited 1: 48 tests, 11 failed / 37 passed. The first exact-full-request Sankey regression expected one engine invocation and actually observed two. Logs and actual exit are in first-red; no retry occurred. All recorded inputs remained unchanged. Passing baseline tests are not evidence that an unimplemented cache's invalidation works.

## Smallest proposed scope

Private module-local successful-result memo in diagrams renderer only. Admit a result only if every actually rendered block reports the official `rendered.diagramType === 'sankey'`, result.complete is true, fragments is nonempty, all fragments are ready, and there was no cancellation or environment change. Other families, especially Gantt, render normally and never enter this memo. Do not identify eligibility by plugin ID, source-prefix guessing, the case ID, or a document-controlled claim. Mixed-family or mixed ready/error results are not admitted. Empty/incomplete/fallback/over-budget/exceptional outputs are not admitted.

Key is the full JSON serialization of the SDK request, including documentId/version/source/offsets/line boundaries/protectedRanges/blocks/selection/theme/target/width and any future enumerable JSON fields. No whitelist/subset key and no source-only key. JSON insertion-order differences may conservatively miss. JSON serialization failure should bypass optional memo rather than change existing rendering behavior. A JSON-transport request cannot carry arbitrary functions or getters; this is not a generic cache for attacker-created JS objects.

Retain only serialized key/value strings. Charge `2 * (key.length + value.length)` bytes, including each complete key and value. Fixed maximum four entries and total retained string charge <= 2 * 1024 * 1024 bytes; an oversized item bypasses without evicting useful entries. A simple deterministic oldest-entry eviction is sufficient; no timer, pending-promise deduplication, cross-instance state, persistence, or public API. Lookup returns JSON.parse of the retained value, so no caller can mutate retained results. The initial return is likewise independent of the serialized stored value. The cap is retained UTF-16 payload accounting, not a claim to bound all JS heap overhead, JSON temporaries, engine memory or CPU.

Keep current initial abort check and singleton rendering guard ahead of reuse. Check cancellation again just before returning a hit and before admission. Never retain a task aborted during Mermaid/convert. Do not clear a good existing entry solely because a new already-aborted caller attempted it. Exception/fallback/partial remain normal existing behavior. Teardown of the isolated JS module/process naturally discards entries; no host cache added.

## Environment conditions, not a claim of universal purity

Before lookup and after conversion/container cleanup, require loaded document.fonts and document.styleSheets.length === 0. Bind a small environment epoch to actual Document identity, FontFaceSet identity, FontFaceSet.ready identity, document.URL, innerWidth, innerHeight and devicePixelRatio. Identity/value changes clear prior entries; an ineligible snapshot clears/bypasses. Compare pre/post snapshots and avoid admitting a render spanning an environment change. Check after the container is removed: Mermaid's own attached SVG style is expected during conversion. No full CSS fingerprint, stylesheet scanning, DOM observer or new event listener is proposed.

Source support: plugin_dom_helper.rs:26 denies network/fonts/images/frames/workers through CSP; :27 serves an empty document with owned bootstrap; :109 and :239 request a 1024x768 helper window/WebView. This is a requested size, not proof it cannot change, hence actual viewport values in the epoch. plugin.ts awaits prepareRenderer, which awaits fonts.ready. renderer.ts creates the owned width-specific container and removes it in finally; it locks theme/themeCSS via secure. The bootstrap has no product stylesheet/resize integration. These facts support a narrow known helper environment; they do not prove arbitrary future CSS, inline root changes, system font installation or OS settings can never affect rendering. A nonempty stylesheet list conservatively disables reuse. Do not call the seven-value signature a complete CSS/media fingerprint. Further broad environment observers would exceed the minimal fix and require separate evidence.

## Clock / global-state audit

Installed Mermaid12.2.0 core Sankey module reads getConfig, theme/font-derived style, graph, DOM geometry and deterministic d3 layout. Its parser/renderer contains no Date, Date.now, Math.random or performance clock call. d3-sankey0.12.3 src/sankey.js uses a fixed default six relaxation iterations and deterministic alpha math, with no Date/random/window/document read in that source. These are local source findings, not a mathematical proof of purity for every transitive dependency or OS font/layout behavior.

The module has a global Uid.count for node/gradient IDs. This is real state and must not be concealed. The converter constructs bounded closed references and remaps local definitions to d0,d1,... (svg-converter.ts:248), so cached closed image data does not require reissuing DOM IDs. Mermaid request sequence IDs also need not advance on a hit, since no new DOM is created and all refs in output are image-local. Every miss initializes configuration anew; do not reuse arbitrary global Mermaid configuration as a cache key assumption.

Gantt is explicitly ineligible: its renderer drawToday uses new Date() for a marker's x coordinate on each call (ganttDiagram core module around2032), and date parsing also uses current date defaults. Neither exact request nor Document/fonts identity freezes that output; a day-bucket or arbitrary TTL would not prove equivalence. All non-Sankey families stay uncached until separately justified.

## Regression evidence and limits

The external test retains all original tests and adds: exact repeat one-call RED; theme/width/version/documentId/selection/target/line/protected-range misses; initial/hit deep mutation isolation; Document/FontFaceSet/ready/URL/viewport/DPR invalidation; fonts-loading and external-sheet bypass; cancellation before hit/during engine/during conversion; engine/conversion/mixed errors and incomplete aggregate envelope; four-entry limit and combined key+value 2MiB accounting; oversized-key bypass; cached-request reentrancy rejection; Gantt/flowchart/class ineligibility.

The fake DOM/engine cannot establish native timing improvement, actual stable environment, real diagramType values, WebKit font behavior, visual fidelity or safety of cancellation across native IPC. Empty success is a policy requirement but cannot be usefully distinguished through an engine-call assertion when no engine is invoked; do not add a test-only cache-introspection API just to mirror implementation. Actual cancellation transport has separate evidence owned by Root. This preparation neither explains an unknown historical request nor claims the latest timeout was necessarily redundant identical input. Native request equality and an implementation review remain prerequisites before any product change.
