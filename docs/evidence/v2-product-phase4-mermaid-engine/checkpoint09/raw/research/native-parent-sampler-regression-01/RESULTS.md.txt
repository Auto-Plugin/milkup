# Parent process-table sampler regression

The production Instance launched a second background worker that repeatedly scanned all processes, even while idle. The dedicated guardian already owns descendant cleanup; the production stop path does not consume the parent sampling cache. The change removes only that worker and updates its explanatory comments. The watchdog, 2s render budget, 10s initialization/lifecycle budget, FD4/EOF guardian control, subreaper cleanup and standalone test fallback remain.

A cfg(test)-only per-Instance counter measures entry into the actual sample_owned function. It is absent from production builds. The real WebKit regression independently snapshots the guardian's PPID tree, checks current PID/birth/parent before and after owned argv reads, proves a direct exact helper and an owned WebKitWebProcess, and checks all observed identities have disappeared after the real infinite-loop timeout. It no longer treats the parent sampling cache as proof of observed descendants. The existing Cleanup Drop is installed before activation and covers assertion failure; final scan-count assertions occur only after successful stop.

Baseline no-run build first passed, then the one real fixture failed only its final zero-call assertion: **125 actual calls versus expected 0**. Activation, text bbox, native resource denial, network/file denial, global-alias rebind isolation, real 2s loop timeout and disappearance of all 9 observed identities passed first. The original failing log, executable, source and command remain unchanged.

After the minimal deletion, the same real fixture first passed: **0 actual calls**, all original checks retained, and all 9 independently observed identities cleared. The same frozen GREEN test executable then ran all non-ignored plugin_dom:: regressions: **14 passed, 0 failed, 2 ignored**. These cover unsampled escaped descendant cleanup on EOF, cancelled/malformed/late responses, blocked pipe writes, lease identity/memory and confined installed sources. The private subprocess test is invoked by its parent test; the real WebKit test was separately executed. No all-Rust-library sweep was substituted.

The owner code lives in each separately compiled test executable; this is not a new packaged application.
