# Production-03: Linux build and generic DOM lifecycle

The Linux production deb build and freeze passed on their first attempts. All five
lifecycle cases have passing runs on the same extracted executable. Ten executions
are retained: five PASS, four picker/setup RED, and one WM-close diagnostic RED.
No product code changed during these runs. The results validate generic installed
DOM renderer lifecycle after the final viewport/image-owner fix; the separate
Mermaid UI matrix is not implied by this report.

## Original failures, retained independently

- disable01: picker did not close during setup. The original WebView screenshot did
  not capture the native dialog contents; the app had closed by later inspection.
  A GTK realized-widget warning correlates with setup, but its cause remains **not
  fully localized**. No fixture activation/loop/disable action occurred.
- disable02: the new test observer used a Python GI `get_text` call that collided
  with an Accessible getter. This observer implementation error occurred before
  input. Actual native screenshot is retained. It is not a product failure.
- disable03: the test's `push button` role-name readiness condition failed before
  input. Its original failed run is retained; its last tree was not captured.
- disable04: new first/last native trees proved actual AT-SPI role display name
  `button`, with Cancel enabled/sensitive/showing. The test string assumption was
  wrong. The final helper compares the actual `Atspi.Role.PUSH_BUTTON` enum43,
  preserving the semantic button requirement. These are harness failures, not
  evidence of a product lifecycle defect or proof of disable01's exact cause.
- wm-close01: real normal close cleared all owned identities/private directory and
  exited the app, but the old test required a best-effort asynchronous terminal
  trace that was dropped. Exact App successful Child-wait confirmation was present.
  Root independently reviewed the identity chain/source guarantee; wm-close02 uses
  that upper-bound contract. The original wm-close01 assertion remains RED.

No whole-case automatic retry occurred. Each subsequent attempt followed an explicit
observability/synchronization or diagnostic-contract change, with source hashes,
checks, command timestamps and raw logs preserved. No deadline, lifecycle cleanup
bound or product source was relaxed to obtain PASS.

## Native picker and measurement boundaries

The final picker observer reads only the exact App PID/birth's native accessibility
roles, states, entry value and geometry through its own session bus. It invokes no
accessible actions or product APIs. The actual focused editable location field
must equal the fixture path; Open must have the semantic button enum and be enabled,
sensitive, showing and nonzero-sized. Real XTest performs input and the click at
that observed rectangle. Native screenshots and first/last accessibility trees
remain in each relevant run. Each bounded observer process exits before fixture
activation/busy measurement; ordinary bus services are not killed to alter results.
The previously frozen shared Mermaid UI picker helper was not modified.

Page listeners, MutationObserver, a 20 ms timer, rAF and external process sampling
add overhead; no overhead is subtracted. The 200 ms assertion applies only to the
specific trusted input→two-rAF samples. It is not a claim about every frame or timer.
Maximum observed busy→cleanup rAF gaps were 177 ms (timeout), 91 ms (disable), and
393 ms (remove); timer maxima were158,63,102 ms. Disable/remove typing occurred after
cleanup, so those input samples do not prove overlap with cleanup. All raw samples,
including gaps above200 ms, remain in `lifecycle-summary.json` and the run evidence.
