# Production-02 build and generic DOM lifecycle results

The production Linux deb build and artifact freeze passed on their first attempts.
All five fresh lifecycle cases also passed on their first attempts, without runtime
harness edits or whole-case retries. The host fence scheduling change was exercised
through the normal installed generic fence renderer in the full production editor.
Official Mermaid multi-diagram/UI/pixel acceptance is a separate next gate.

observed identities, phase timings, input samples, instrumentation baseline and
heartbeat statistics. Each run recorded nine owned PID/birth identities and required
the entire observed context plus exact private directory to disappear before outer

## UI measurement limits

Page event listeners, MutationObserver, 20 ms timers, rAF and external process
sampling add observational overhead; no timing was subtracted. The 200 ms target
passed for the specific trusted input→two-rAF samples. It does not mean every frame
or timer callback completed under 200 ms. Maximum rAF gaps in the observed
busy→cleanup window were 41 ms (timeout), 213 ms (disable), and 253 ms (remove).
Maximum timer gaps were 38, 103 and 253 ms. Disable/remove typing occurred after
cleanup; their input samples do not establish overlapping input latency during
cleanup. The timeout input does occur during the busy renderer.
