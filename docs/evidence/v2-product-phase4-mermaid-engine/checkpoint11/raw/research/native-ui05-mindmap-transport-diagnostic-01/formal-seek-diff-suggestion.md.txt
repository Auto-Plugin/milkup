# Static suggestion only — not implemented

The formal harness `seek(sample, mode)` currently selects the marker by public search, closes search and focuses the input proxy; it never requires a useful marker position or moves the document using a wheel. Its later `assertSample` treats missing preview after30s as image decode timeout even when no image was admitted.

The smallest generic test-only change is immediately after seek’s final focus: read the matched marker line and editor rectangles, choose an editor padding point with elementFromPoint rejecting any presentation scrollbox, and use a bounded native XTest wheel gesture toward the upper third. Preserve source selection and document version; record before/after marker geometry and actual ticks. Keep native conversion deadlines and all existing preview, screenshot, source, history and matrix assertions. If the bounded gesture cannot place the target usefully, report a positioning/setup failure separately rather than claiming decoder failure. Do not use private view APIs, DOM scroll setters, selection-priority product changes, retries or a larger rendering budget.

The diagnostic validated only one light100% ordinary Mindmap case, with four down ticks reaching the upper third. This does not establish that the same six-tick/1.5s bound suffices across narrow/zoom/windowed/source modes. Any proposed generic helper must explicitly define its bidirectional bound and destination condition and preserve the first failure if positioning fails. Actual request width must continue to come from content.clientWidth, not native window width. Normal pointer hit testing must avoid nested preview scrolling. Root should choose and review the exact minimal change before another formal run.
