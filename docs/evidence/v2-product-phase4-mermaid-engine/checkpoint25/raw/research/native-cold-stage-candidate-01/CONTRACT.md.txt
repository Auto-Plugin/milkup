# Layer 1 cold stage candidate — research only

This directory is a source candidate, not a native build or runtime result. It composes current product bootstrap with the exact run05 accepted-wire three overlays and self-pidfd three overlays listed in baseline-inputs.json. It does not use the old stage executable. The final eight overlay files comprise these original six plus bootstrap and the new plugin_dom_stage.rs. Accepted-wire recorder, C guard and native self-pidfd implementation bytes are unchanged. Plugin archive/SDK/frontend/config/budgets are unchanged. Product repository is not edited.

## Opt-in and lifecycle

Stage gate: MILKUP_COLD_STAGE_DIAGNOSTICS=1. Output root: MILKUP_COLD_STAGE_OUTPUT_DIR, explicitly frozen absolute fresh precreated0700 controller-owned directory and trusted ancestors. Writer rejects a final symlink/non-directory/wrong-owner/wrong-mode root. This does not claim protection against same-UID malicious path replacement/ancestor races. Original accepted-wire gate/output and self-pidfd gate/output remain independent and unchanged.

One new bounded asynchronous stage writer starts in the App launch budget and one in the GTK helper **after guardian fork**. Guardian starts no stage writer. Each writer exclusively creates role-PID-birth beneath the stage root, with mode0700, events.jsonl/status.json/complete.json mode0600. Producer callbacks never write files/stderr, wait for queues, or acquire a blocking diagnostic mutex. They do allocate bounded records, read clocks, serialize metadata and call try_send. try_lock contention is a diagnostic drop. Native product locks are unchanged; native settlement records serialize only after dropping control. The owner watchdog is armed before the first stage row is published.

Stage writers only read the already frozen MILKUP_COLD_REQUEST_OUTPUT_DIR/finish.request marker; they do not create it. Thus the unmodified Node cold harness's existing native-capture finalization offers stage closure without any new close wait. Neither wire complete nor App close waits for stage complete. Helper kill or App exit can lose queued/tail records; missing complete is partial even if all retained rows look valid. No timeout/budget extension or retry is authorized.

Per process limits: first eight unique accepted (instance,render ID) scopes, queue32,512 attempted rows,64KiB reserved total event bytes,1024 bytes per event. Limits and drop counts are explicit. App and helper limits are separate; this is **not** a single whole-run64KiB claim. Init/RPC rows have null request scope. Native first8 admission matches helper first8 validated native input frames in the intended one-helper cold experiment; contention/drop/multiple-instance mismatch makes matching incomplete rather than widening scope. Unknown/unadmitted IDs do not become rows. Records beyond scope are not evidence that no work occurred. No source/SVG/AST is copied in stage records. Exact full request and hash come only from the separate accepted-wire record, joined on exact instance/request and independently qualified emitter/owner identity.

## Native row and endpoint semantics

Every row: schema milkup.cold-stage.v1, sequence, emitterPid, emitterBirth(nullable), role(app|helper), instanceId, requestId(nullable), phase, nativeMonotonicNs, captureBeforeNs, details. Native clocks are CLOCK_MONOTONIC in the emitting process. Birth is its own /proc/self/stat field22, not JS or a claimed renderer PID. Cross-process/time-namespace equivalence is **not** established merely by matching API or numeric order; report process-local spans and only qualified cross-process correlations. Native self-pidfd/external identity proof remains separate.

App phases:
- launch: timestamp immediately after original Instant init origin, before observer initialization/private guard/spawn; details guardianPid/guardianBirth become available when published. Original opaque ID generation precedes that origin, as before.
- owner-accepted: after original authoritative DOM_NATIVE_TIMING dispatch, deadline assignment, control unlock and original wire capture. It is **not** a replacement dispatch timestamp; details wireBytes.
- owner-pipe-complete: original input wait/write/flush returned, details ok/type. Sending thread can be descheduled, so a result may settle before this diagnostic row's timestamp.
- owner-frame-read: frame read finished, before original serde parse; details bytes. Published after parse obtains its matching ID.
- owner-receive: receive entry, before existing size/strict response checks.
- render-settled: timestamp immediately **after original control.active=None**, following both original deadline checks, strict result match and output budget validation. Details ok is the accepted boolean; ok:false is a valid settled error. This is neither JS success nor final event delivery. Clock read is under the existing lock only after clearing; details construction/record is after unlock. A later timestamp greater than nominal2s does not alone prove the earlier deadline check violated its contract.
- activation-settled: after original initialized=true, details ok/rpcId, null render scope. Original subsequent rpc clear/wake/unlock stay in place.
- deadline/terminal: finish entry before original trace and cleanup; details hasError. Original DOM_NATIVE_TIMING deadline remains separate authoritative evidence. Not successful settlement.

Helper phases: helper-start, guard-ready, load-finished, init-evaluate-submit/callback(ok); helper-dequeue(type,diagnosticParseIncluded), evaluate-submit/callback(ok), result-drained(bytes), result-pipe-complete. Dequeue's timestamp precedes a diagnostic frame parse; that parse and record are included in subsequent elapsed time. Callback timestamp is taken at callback entry before converting the JSCore value. Dispatch evaluate may return long before asynchronous plugin completion. Empty polls do not publish native event rows. Result-drained is the original output string observed in callback; result-pipe-complete is original write/flush completion. It does not authorize App settlement.

## Bootstrap and original result preservation

Only the private init token and existing private dispatch/drain function are used. The gated helper passes a third boolean init argument; off-gate init script remains the original two-argument form. Plugin receives no sink/token/new API. No extra polling, JS message bridge, permission, network, setting or library internal instrumentation is added.

Closure-only JS marks: module-import-start/end/reject; activate-start/end/reject; invoke-start/resolve/reject; typed-stringify-start/end, typed-encode-end, typed-parse-end; envelope-start/stringify-end/encode-end/output-ready. The two serialization/UTF8 limits are exactly the original262144 typed/266240 envelope limits; no extra product stringify or altered result shape. JS marking uses captured intrinsics, no Array.toJSON for mark accounting, and catches diagnostic errors. It accounts conservative escaped record bytes. Eight render scopes with64 marks each, init32, total64KiB; exhaustion increments dropped and rendering continues. A capped render's undefined scope must never default to init. Module import/init marks cannot claim a render request.

With stage gate on, only drain return is {stageSchema:1,output:<original string or null>,stages:<at most64 triples>,stageState:{marks,dropped,drains,bytes,markMs}}. This travels in the existing evaluate return, **not** the native result pipe. Helper validates closed shape/phase names/finite numbers and scopes request marks to the current pending native frame. Unknown/late JS scopes become diagnostic-unbound-js with no forged request correlation. Native instance/PID always come from native context. Valid wrapper output is forwarded byte-for-byte through the unchanged original result pipe. If diagnostic draining fails and returns original string/null, helper accepts it (diagnostic-raw-drain for strings). A malformed wrapper with a valid output field still forwards that original field, logs diagnostic-invalid-wrapper, and discards diagnostic content; missing output cannot be recovered and yields null plus incomplete evidence. This does not turn diagnostic metadata into product success/control.

Helper records each JS mark as phase js-mark, details {phase,jsMs,trust:'untrusted-js-wall-time'}, nativeMonotonicNs is its callback collection time, **not** the occurrence time of the JS mark. js-state carries the five cumulative state fields when marks/drops change or output arrives. JS marks are untrusted relative wall time only. No PID, wire hash or native dispatch time is accepted from JS. Keep JS local differences separate from native clocks. Synchronous JS stalls can prevent drain until kill and lose all buffered marks; absence cannot locate the stalled stage.

## Accounting and completion

Status schema milkup.cold-stage-status.v1 reports attempted/enqueued/written/reservedBytes/dropped/unknownOrUnadmitted/ioErrors/inFlight/closed/final, captureTotalNs/MaxNs, admitTotalNs, collectionInclusiveNs/Calls, writerThreadCpuNs and limits. Capture starts inside record: details construction and calling clock reads precede it. Collection spans callback entry through original JSCore JSON conversion plus diagnostic processing/record, excluding original output pipe write; it includes capture cost, so do not add these as disjoint costs. Writer CPU excludes last status/complete serialization. No full or zero overhead claim, no subtraction from2s/10s. Status/complete itself is bounded fixed metadata beyond the64KiB event budget. Missing identity, gaps/drops, malformed/raw/unbound diagnostic rows, missing JS expected phases or missing final each remain explicit limitations. A final marker means observer closed/drained, not product request success or complete lifetime capture. No process is signaled by stage code.

It is not WebKit or real Mermaid. It checks output-byte parity with gate off, private token, success/error/cancel/output budget, caps, diagnostic clock failures/prototype changes, and pending/unknown requests. Compile them only after freeze, linking existing local serde_json/libc rlibs with rustc --test (no cargo dependency build/target copy). Preserve first compile/test exits.
