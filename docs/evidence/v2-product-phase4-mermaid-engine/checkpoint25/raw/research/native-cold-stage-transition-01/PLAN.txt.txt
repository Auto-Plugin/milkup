2. Stage recorder source interface and close boundary
Owner confirmed independent stage sink; original request_diagnostic.rs and its
events/status/complete/finish path remain byte-identical. New gate is
MILKUP_COLD_STAGE_DIAGNOSTICS=1 and MILKUP_COLD_STAGE_OUTPUT_DIR pointing to a fresh
precreated0700 root. App and helper writers independently own role-pid-birth
subdirectories containing events.jsonl/status.json/complete.json. Proposed source
bounds agreed with Root:512events/64KiB per process, queue32, record<=1KiB. Exact
record accounting, total-size interpretation, process-count scope, error/drop
counters, gate validation and file ownership must come from final frozen contract.
A per-process cap alone must not be described as an unlimited-run aggregate cap.
No writer may share an events/status file with another process or wire recorder.
Helper writer initialization must occur after guardian fork; no fork-before
threads/locks or a second guardian-side writer are introduced by preparation.

Root's approved lifecycle choice (sent to owner and CPU auditor): stage writers
may additionally READ ONLY the existing original native-capture/finish.request.
The exact path is derived from/frozen alongside the run's original
MILKUP_COLD_REQUEST_OUTPUT_DIR, under exclusive run-owned output ancestry.
The candidate's final interface must make this marker binding explicit; use the
same actual path the unmodified Node harness writes. Do not redirect the wire
writer, overwrite its files, publish its final record, or make it wait for stage.
The independent stage root/finish.request, if retained by owner, is an optional
separate close input, not a substitute for the pre-App-close shared marker.
No symlink trick, filesystem polling bridge thread, CPU observer mutation or
controller delay is needed for the approved shared-marker read design.

Original Node finally writes wire finish.request while App is alive and waits
at most1000ms for parseable wire complete.json; then original App.close proceeds.
The Node file remains WHOLE-BYTE unchanged. The marker gives each stage writer
one opportunity to notice close/drain its already accepted queue. It does NOT
promise stage complete before App.close/helper termination. Do not add waits,
flush acknowledgments, request settlement waits, renderer work, terminal events,
or cleanup deferrals to make final appear. Writers should write queued rows as
they are available; helper killed during writing may leave a partial last line.
Missing complete is partial evidence, not permission to retry or widen timing.
A final stage record covers only that process's accepted observation window. It
does not settle every request, prove lifetime event completeness, or supply a
request-success endpoint. Exact close time is unknown unless the final source
actually records its atomic close boundary; never reuse wire final/drain timestamp.
Counters must distinguish attempted/enqueued/written/dropped/inflight and close
scope. Post-close events cannot be silently reconstructed into successful events.
