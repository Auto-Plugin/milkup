Purpose and authority
This new standalone Python module reads explicitly named saved files, checks their pinned SHA256 bytes, and recomputes per-PID adjacent-sample CPU independently. It neither imports v05 nor invokes product code, tests, live proc, signals, clocks, subprocesses, or a sampler. This candidate changes no old evidence. Root authorized one initial pure offline synthetic test execution after input freeze. No stage runtime is available or authorized by this delivery.

Endpoint and clocks
One exact accepted wire and original DOM_NATIVE_TIMING dispatch per owner/instance/request is required. owner-accepted, pipe completion, helper callbacks, JS marks, next dispatch, capture close, complete.json, App close and kill never supply a successful endpoint. Duplicate settlement, duplicate original deadline or conflicting settlement/deadline evidence stays unresolved; do not choose earliest/latest. An App render-settled row requires boolean details.ok and null rpcId. Actual original deadline-observed provides the distinct deadline observation endpoint; a stage deadline alone does not replace it. Missing stage complete makes capture partial but does not erase a valid retained endpoint. Even loss-free final is only diagnostic closure, never proof of lifetime coverage. Publication order is not native temporal order; owner-pipe-complete may occur after settlement and is not rejected for that reason.

sameAppDurationNs uses only qualified exact App dispatch and endpoint clocks. Independent per-PID sample counter differences are also measured facts. Numeric selection of observer brackets within that App window is always clockJoinStatus=unverified-coordinate-assumption and candidate-intervals-not-strict-request-attribution. Common API, plausible order, namespace inheritance or observedDelay fields do not establish coordinate equivalence. No time namespace calibration/offset is attempted. JS time is never subtracted from native time or used as an endpoint. Helper/native WebProcess clocks are not used to prove App transfer latency.

CPU arithmetic and gaps
For every known exact PID/birth, retain one observation position for every original sample round. Absent/duplicate members, wrong instance, invalid counter/bracket or terminal status are barriers, never filtered out to bridge a gap. Only adjacent valid positions with nondecreasing individual utime/stime and disjoint ordered read brackets form an interval. A skipped scheduling slot between two valid saved adjacent rows remains the actual larger measured difference; no invented intermediate row is added. Original quality/skipped/eviction/late fields remain in output.

Own CPU ticks are delta(utime+stime), divided by saved CLK_TCK; no child/cgroup CPU is mixed in and no initial cumulative ticks are assigned retrospectively. The full process interval table is independent of all request endpoints. Each leaderSchedstat delta is separately validated; a leader failure does not erase otherwise valid own CPU. These are leader-thread runtime/wait/timeslices only, never all-thread waiting or runtime. BindingTimeRole and original proof are retained; later exec is not inferred. Ordinary bwrap arguments never imply WebProcess identity.

For a candidate App window [D,E], include only adjacent sample intervals satisfying D<=a.readStart<=a.readEnd<=b.readStart<=b.readEnd<=E under the explicit unverified coordinate assumption. No valid interval gives CPU=null, not 0; valid equal counters give 0. Leading range [a.start-D,a.end-D] and trailing range [E-b.end,E-b.start] are conditional unmeasured-edge bounds, never exact cross-process latency. Empty selection has null gap ranges. FirstSeen/firstSample remain visible. All excluded adjacent pairs are retained with round indexes for independent inspection; interval sums do not imply uninterrupted coverage between disjoint included intervals. No interpolation/extrapolation, sample frequency/budget change, terminal read or lifetime backfill occurs.

Shared interval IDs expose reuse across overlapping request windows. No sum across requests or aggregate renderer CPU is produced. fullRendererTreeCoverage is permanently false. Discovery caps, cooperative 5ms overruns, known incomplete ancestry/children interface, native1target limitation, observer overhead and ring quality remain raw independent context; nested overhead fields are not added or subtracted from a deadline. CPU/Node/wrapper exits are independent. Audit process exit0 means computation/report writing completed, not cold PASS, complete coverage, valid endpoint for every request, or a root-cause conclusion. Malformed/changed file inputs throw and exit nonzero. Per-request unresolved/partial conditions remain structured report data even when the calculation completes.
