# Hidden-page timer control — plan only, no implementation or execution

2026-10-16. Root requested this separate diagnostic after the CPU sampler preparation. The cold CPU batch remains transport's exclusive runtime task. This document neither authorizes runtime nor changes production04, the frozen stage candidate, its source, or any prior evidence.

## Question and evidence limits

Does the helper's hidden-page timer policy impose material latency on serial zero-delay timers, and does the same single configuration change alter an unchanged short official class-diagram request? This is a mechanism experiment. It cannot retrospectively attribute historical render3/render68 failures, and successful class requests cannot establish a general performance guarantee.

The production helper creates a GtkWindow Toplevel, calls realize(), then shows only its WebView child. It does not map/show the top-level window. Current source therefore suggests a hidden page, but neither GTK mapped state nor document.hidden has yet been measured in this configuration. Local sysroot pkgconfig identifies WebKitGTK 2.52.6; the pinned Rust crate webkit2gtk 2.0.2 enables v2_40 and does not wrap the newer feature APIs.

WebKit's exact 2.52.6 preferences source lists HiddenPageDOMTimerThrottlingEnabled as true for the WebKit GTK configuration, while HiddenPageDOMTimerThrottlingAutoIncreases is false. DOMTimer declares a one-second hidden-page alignment interval. Alignment is not a guaranteed one-second delay for every individual callback: phase, page state and scheduling affect each sample. [Preferences](https://github.com/WebKit/WebKit/blob/webkitgtk-2.52.6/Source/WTF/Scripts/Preferences/UnifiedWebPreferences.yaml#L3572), [DOMTimer](https://github.com/WebKit/WebKit/blob/webkitgtk-2.52.6/Source/WebCore/page/DOMTimer.h#L60).

view_fixes statically traced the actual installed Mermaid 12.2 class-v2 route into ELK and elkjs 0.9.3's fake Worker: postMessage schedules setTimeout(0), and the PromisedWorker receive path schedules another setTimeout(0). The generic fixture below tests serial timers, not an asserted instruction-for-instruction ELK reproduction. Keep the exact official bundle unchanged for the class comparison; no fake Worker replacement, timer monkeypatch, pre-render or alternative layout algorithm.

## Public API and compatibility

The public Settings feature getter/setter/list APIs exist since WebKitGTK 2.42. Enumerate the feature list once, require the exact identifier, record runtime version, feature status/default/current value, and require the post-set readback to be false for B. Missing symbol/feature or failed readback makes that cell unsupported/incomplete, not an unmodified control labeled B. Do not claim API existence guarantees this feature's availability on every 2.42+ release.
