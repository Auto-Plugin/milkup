## Source mechanism

Installed Mermaid12.2.0 `journeyDiagram-BOSHW7O7.mjs:1160–1167` calls configureSvgSize, then explicitly sets the viewBox, xMinYMin meet and height(height+title-extra+25). A responsive root width does not proportionally reduce its explicit height. At width380, the viewBox is width-limited: scale380/1300; mapped viewBox height540×scale=157.846153846px, leaving407.153846154px of the565px viewport below it. Capture's unstroked bbox ends at source y450, mapped y138.846153846px; bbox alone is not full painted bounds, but the actual paired pixels independently show the lower blank region.

`svg-converter.ts:1412–1446` preserves attached rect dimensions and root aspect. `paint-envelope.ts:664–674` unions conservative ink with the original viewport; rasterBounds is deliberately not a tight ink crop. `document-svg-image-codec.ts:1256–1284` preserves the inner mapping inside the integer outer viewport. `view-dom/document-svg-image.ts:21–63` creates the exact slot and adds insets only for real raster overflow; this sample has no additional inset. Thus neither ceil rounding nor the host's negative-ink allowance accounts for the407px space. The final200% natural size being twice CSS dimensions is consistent with the retained native zoom observation; it is not evidence of an accidental second layout scaling.

## Minimum recommendation

No host sizing correction is justified under the present preserve-original-viewport contract. Do not change max-scroll to an arbitrary value, special-case Journey/plugin ID, discard lower pixels based on a screenshot, use getBBox alone, change global CSS, or shrink every SVG to its viewBox ratio. Other diagrams can have intended space, labels/strokes/markers/filters outside the viewBox, and different aspect alignment.

If the parent explicitly chooses a compact-canvas UX policy, the narrow generic candidate is plugin-side removal of proven trailing vertical letterbox space only for width-limited xMinYMin meet roots, preserving width, viewBox, every node/style and the original affine mapping. Use the existing conservative paint-envelope calculation *before* its original-viewport union to bound actual ink; keep at least the mapped full viewBox extent and all conservative ink, with integer outward rounding. Only shrink when the candidate root CTM is mathematically unchanged and the complete conservative painted bounds remain contained; otherwise retain the original. Recompute raster bounds against the intentionally smaller declared viewport. Existing root transforms/unsupported effects must retain their fail-closed behavior. This is a proposed explicit normalization policy, not an implemented or proven-safe patch. It changes document footprint while leaving graphic positions/scale unchanged; it need not change the public SVG schema or host renderer. A generic host ink-crop field would be a larger contract change and is unnecessary for this narrow option.

For this retained sample alone, ceil157.846…=158px is a *candidate* minimum based on the mapped viewBox; it is not a hard-coded size or universal ink proof. An implementation must derive and bound ink, not copy158 into code. Relative lengths, root clipping, filter regions and conservative false positives need explicit guards; uncertainty keeps the full canvas.
