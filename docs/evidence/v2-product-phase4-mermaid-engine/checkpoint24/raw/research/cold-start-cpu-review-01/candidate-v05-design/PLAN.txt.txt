V05 external observer proposal — DESIGN ONLY, no candidate implementation/tests/runtime
Based on frozen candidate-v04 sampler b5c5167b0d28a7205d1572be83e0bff3b1a1a59932e921a9584be8f9cfdd8364 and run04 completed review.
Native transport is unverified. This design does not authorize a build, probe, or product invocation.

Goal and unchanged boundaries
Use a diagnostic native WebProcess self-pidfd received/held by the exact already-bound renderer helper to discover one otherwise-unbound target. The ordinary v04 children/direct-pidfd paths remain; no global /proc, task or process-name search. Sampling250ms, discovery500ms, SINGLE5ms cooperative discovery budget,64 total CPU identities,2MiB sample ring,60s duration and all prior limitations remain. App CPU, guardian CPU, helper CPU, target own CPU and leader-only schedstat remain distinct. No attribution of historical timeout to CPU or successful-prefix closure.

Trust chain and agreed proposed native record contract (native implementation still unverified)
1. Existing App-owned guardian-spawn binding -> exact App/guardian pid,birth,instance -> existing guardian held-pidfd + direct parent proof -> exact helper pid,birth,instance.
2. Only after helper binding, read a FIXED native record path deterministically constructed from this helper identity and instance under an explicitly configured pre-existing run-owned0700 directory. Never read a PID/path supplied by the record as the record location. Fixed paths slot/helper-<pid>-<birth>-armed.json and slot/helper-<pid>-<birth>-result.json. Instance must match inside both records. No directory enumeration. Native claims root/slot by exclusive mkdir once: a pre-existing slot disables that native diagnostic; there is at most one helper and two final files for this run.
3. Maximum8KiB record, regular file/no symlink, owned private directory and file (mode0600 expected). Open relative to verified directory descriptor with no-follow semantics; preserve directory/file device,inode,size,read times and content SHA256. Do not assume0700 protects against same-UID malicious writers; provenance is the controlled run's exact native publisher plus frozen source/context and identity checks, not a cryptographic attestation.
4. Native gate MILKUP_WEBPROCESS_PIDFD_DIAGNOSTICS=1 and MILKUP_WEBPROCESS_PIDFD_OUTPUT_DIR points to the precreated private directory. Schema milkup.webprocess-self-pidfd.v1; common instanceId, helper:{pid,birth,parent}, guardian:{pid,birth,parent}, kind, nativeMonotonicNs. The armed file means this native private context was gated; result status is held or failed. A held result supplies heldFd, receiverFdinfoRaw<=4096, receiverReadStart/EndNs, C nativeStart/EndNs, pageId; failures preserve errno/stage/GError domain/code. All required identity/fd/ns values must be exact bounded integers (bool invalid); instance48hex; require known helper and guardian parent identities. Exact kind spelling will be frozen with native source before implementation. Native uses O_EXCL|O_NOFOLLOW0600 temp then linkat to exclusively publish final paths, not replace. Both files are each<=8192B and one immutable publication; conflicting subsequent digest/inode becomes a gap, not rebind. Received duplicate is CLOEXEC and intentionally held until helper process exit, with no native release/reuse API. Armed/held source timestamps are publication observations, not target birth or request deadlines.
5. Any native target PID text and native NSpid inside receiverFdinfoRaw are retained as source evidence only. They NEVER index external /proc or establish namespace mapping. The private sender callback must pass exactly its own pidfd with exactly1 FD via the frozen context-local native channel; a message name, echoed instance or argv text alone is insufficient provenance. This receiver/channel/runtime capability is not yet demonstrated.

Exact-held-FD observation and two-phase ancestry proof
- Prioritize a ready record's exact heldFD before ordinary fdinfo enumeration of that helper. Every first/repeat fdinfo read counts against the SAME per-owner32 / per-round128 read budgets as v04; no extra parallel allowance. Refactor shared counters rather than resetting owner_reads between mechanisms. Duplicate enumeration/read may consume budget twice honestly; do not exempt a read because it was previously seen.
- Read helper stat before: exact bound birth, original guardian parent identity and nonterminal state. Require record helper/guardian/instance match. Read exact /proc/<helper>/fdinfo/<heldFD>, max4096 bytes, saved raw proof <=1024. Preserve Pid/NSpid/other raw fields. Only positive Pid in this observer proc view may become a candidate; -1/exited, zero, malformed/ambiguous values, permissions or namespace visibility problems remain unbound.
- Phase A: collect target -> parent -> ... -> EXACT HELPER using only the just-read PPID of each node; save each PID/birth/PPID/state and read bracket. Maximum8 distinct nodes inclusive of target and helper, cycle detection, positive sane PID, parent birth <= child birth, live state (not Z/X/x). PID0/1 or escape, missing ancestor, identity mismatch, cycle/depth/cap/budget failure rejects this binding. Do not search siblings, infer omitted ancestors, translate NSpid, or stop at guardian/subreaper as a fallback anchor.
- Phase B: reverse-reread the collected nodes; require each exact birth, unchanged PPID and live state, including helper. Require every saved parent edge to equal the next exact collected PID and chronology to hold. Finally repeat exact helper fdinfo and helper stat; require raw fdinfo unchanged, exact helper birth/guardian parent/live. Save both full chains, read times and both raw fdinfo. Check original shared wall budget between all reads and before acceptance.
- These brackets are not an atomic kernel ancestry snapshot. Reparenting or PID reuse visible in either phase rejects; a same-value ABA during an unobserved interval cannot be categorically excluded. If an intermediate exits/reparents to a subreaper, mark the chain unavailable instead of accepting a shortened historical chain. A later wholly valid helper-anchored chain can be a new observation, never reconstructed earlier ownership.
- The native publisher's held-FD lifetime must outlast observation. External repeat checks cannot turn an unverified native FD lifetime into a guarantee. Do not reopen/duplicate targets with pidfd_getfd, adjust permissions or sandbox, or signal any process.

Additional bounded work and membership
At most2 fixed native-record reads/round (armed and result); at most one candidate held target from that single native slot. At most16 total chain-node visits/round and32 two-phase chain stat reads/round remain defensive aggregate caps; one complete proof needs at most8 nodes/16 chain stat reads. The initial/final helper boundary checks also consume a separate shared native-proof-stat counter capped40/round (at most4 extra checks per two attempts); every operation additionally consumes the unchanged5ms budget. Max8KiB each record; no unbounded read or scan. The source slot allows at most one helper. If multiple already-bound helpers would require probing more than2 fixed files this round, select them with a bounded cursor and explicitly retain skipped-owner/slot-ownership uncertainty; never enumerate the slot or assume a globally unique helper from a name.
If any limit is reached before the complete proof, do not add that target. If another target proof completed before a later error/cap, retain it with partial coverage. Complete proof adds only its target to the existing64 CPU identity set; intermediate nodes remain bounded ancestry evidence and are not automatically adopted/sampled. Existing known targets cannot be rebound to another instance. Re-observation must not reset firstSeen/firstSample or retroactively claim CPU. Retain at most64 binding proofs/status examples and bounded round quality records; retain total drop/error counters.
The2MiB limit is the existing sample ring, not total metadata. New proof metadata is separately bounded: <=64 proofs, each <=8KiB record + two <=1KiB fdinfo + two8-node stat arrays + <=4KiB argv (raw hex inflation disclosed). Native record repeats may be rechecked with digest/device/inode; detect replacement rather than silently accepting a new publication. No raw environment output.

Role and failure semantics
After a complete ownership proof, retain bounded target argv rawHex/parsed/read bracket inside the identity validation window. The native private page-created self-pidfd provenance and stable external identity are required evidence. Assign webkit-web only when argv[0] itself also identifies WebKitWebProcess; a bwrap argument containing that path does not qualify. If argv[0] cannot corroborate WebKitWebProcess, preserve the validated identity/provenance and argv as diagnostic evidence but leave the CPU target unbound; never silently call it WebProcessCPU. This conservative proposal avoids a new ambiguous sampling role. Later exec remains unmonitored; roles are binding-time descriptions.
Repair the v04 live-owner contract mismatch by explicitly rejecting Z/X/x owner states in relevant discovery proof paths; do not change sampling's existing terminal-record behavior. Preserve exact owner state in proofs. This is a small trust-condition correction, not expanded authority.
Record pending/not-published, native negative result, record mismatch/tamper/oversize, fdinfo error/exited/changed, target/owner terminal, missing ancestor/reparenting, permission error, cycle/depth/node/stat/FD/identity/time caps as distinct bounded statuses. No retry burst; any recheck occurs only on scheduled500ms discovery. Unresolved native identity remains explicit incomplete/unbound at stop. Existing children-interface gaps and incomplete rounds still force observer exit2 even if a target is captured. Harness cold assertions and wrapper status remain separate. fullRendererTreeCoverage remains false in all cases. No successful fixed-record proof implies all WebProcesses, all renderer descendants, or any CPU causal explanation.
