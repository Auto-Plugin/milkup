# 第十三阶段：大文件滚动边界、长行渲染与编辑一致性

本轮从已推送的 `69e1d7dc8cd255194a4a6c794e3cce1cde8f4d06` 接续，工作分支仍为 `dot/milkup-v2-quality`。未合并远端 v2、未强推、未发布应用。第十一阶段的精确恢复 SHA、正常启动与 WebDriver 启动结论见[恢复报告](./v2-phase11-clean-environment-verification-2026-10-13.md)；本报告不把历史测试重新计为本轮完成。

## 结论与验收边界

100 MiB、1,638,402 行文件原先无法到达末尾：引擎布局高度停在 33,554,432 px，最后渲染行为 1,597,855。修复后物理滚动高度约 8,000,072 px，source/live 均能在原生窗口到达真实 EOF，完成编辑、撤销重做、全文件字节保存及重开。

这不代表达到 Typora 级质量。相同文件搜到末尾 source 为 106,936 ms、live 为 105,830 ms；真实系统中文 IME、Windows/macOS/Word 2016、窗口化表格和大文件替换等仍未验收。长行延迟以本报告的逐样本结果为准，不以测试数或延长超时宣称性能通过。

## 修复及依据

1. **布局高度上限**：新增有界滚动坐标映射，只压缩屏幕外占位空间，真实可见行维持原尺寸。首尾 2,048 px 保持原比例，避免顶部 padding 被放大而漏掉第一行。显式跳转、滚动事件、插件可见行范围使用同一逻辑行坐标。
2. **键盘访问和光标可见性**：窗口化视图补齐 Ctrl/Cmd+Home/End、PageUp/PageDown 及 Shift 方向选区；连续方向键经过 overscan 边缘时滚动到光标。EOF 来自实际行的 UTF-16 `to`，不使用文件字节长度。
3. **长行额外工作**：按平均行长限制 overscan 文本量，保留完整可见窗口；source 不预热 Markdown，超过 65,536 字符的 live 窗口不做空闲预热。source 行窗口缓存按文档版本隔离，最多 16 项、524,288 UTF-16 单元；替换 source 时显式清空，避免重开同一文档且版本重置时显示旧文本。该边界单测修复前得到 `before`，修复后得到 `after`。另一个延迟读取回归确认：旧 source 的请求晚返回会重新填入同键缓存；现在按读取时的 source 对象与版本校验缓存写入和 DOM 应用。相同规模的前后对照见下表。
4. **编辑与异步渲染竞争**：本轮滚动／缓存改动的独立 XTest 复验发现输入 `qrs`、保存后屏幕仍可能使用空行旧坐标，连续 Shift+Left 从 55 错移到 50。渲染必须等待已排队的 source 提交，并拒绝覆盖更晚的乐观编辑；提交失败仍允许重绘回滚，提交改变行数后重新计算请求。等待沿用原批次定时器，不能主动 flush 拆开连续输入的撤销组。新增两模式的延迟读取／未提交编辑回归，且保留已有提交失败回滚测试。
5. **滚动条事件**：原生根滚动条拖动不应进入编辑器文字选区手势；补充 overlay scrollbar 边缘检测和回归。

初始滚动单测在修改前 4 项失败；异步覆盖回归在修复前 source/live 均得到 `alpha` 而非 `qalpha`。第一版仅保护编辑修订号仍未关闭原生故障，加入提交等待后才通过。等待提交曾使已有失败回滚测试失败，已修正并复验；主动 flush 的中间版本又使原生 EOF 输入 `xyz` 被拆批，一次撤销只退回 `z`，最终改为等待原定时器，并保留不提前提交的断言。顶部 padding 的 JSDOM 初版用例没有失败，不能称红灯证据；该缺陷的红灯来自真实原生 Ctrl+Home 操作。

## 真实原生输入、磁盘及鼠标边界

`tests/native/x11-save-history.py` 使用正常 CLI 打开文件、XTest 系统按键和只读观察接口，未使用 WebDriver 输入或 DOM 合成事件。普通 EditorView、内存窗口和 Rust 原生窗口分别在 source/live 验证：保存前后连续输入、保存后立即撤销、重做后输入、反向选区替换／撤销／重做，以及正常关闭重开。原生窗口另验证连续 40 次 ArrowDown 的精确逻辑位置和光标可见性。每次保存检查完整 UTF-8 字节及 CRLF。

`tests/native/x11-scroll-limits.py` 生成编号 CRLF 文件，含中文和 emoji，实际 104,857,639 字节。每模式执行 Ctrl+End、Shift+PageUp、PageDown、Ctrl+Home、十次固定种子分散滚动条拖动、行内点击、PageDown/Up、两处随机编辑历史、完整搜索末尾、末尾编辑历史、全文件 SHA-256 保存比对和重开 EOF 坐标。鼠标使用真实 WebKitWebDriver pointer actions，键盘仍是 XTest；文件通过应用真实 CLI 参数打开。只读观察接口不提供输入、执行代码或文件操作能力。

最终原生 EOF 截图已人工查看：滚动后的正文连续，末尾中文、emoji、追加的 `xyzxyz` 与光标均可见，状态栏为已保存，没有原先的大块尾部空白。该纯文本夹具没有覆盖复杂 Markdown 排版；正文左侧起排、宽屏阅读、主题和辅助功能仍需专门体验审查，不能据此认定达到 Typora 的视觉质量。

XTest 鼠标本身在当前环境未验收：释放鼠标后仍继续拖动，系统 button mask 已为 0；独立静态 8,000,000 px 滚动容器、没有编辑器事件处理器，也复现同一现象。第二次点击才释放。该证据把问题限定在 XTest→当前 GTK/WebKit 输入路径，不能进一步断言具体系统根因。随后 WebDriver pointer 完成真实拖动和点击验证；不把换用驱动说成 XTest 鼠标问题已修复。第一次只修滚动条选区判定的失败也保留。

一次性能诊断由于 Vite HMR 导入带时间戳模块，原型采样没有附着到实际视图，导致尾部采样超时；重启普通 Vite 后消除该采样问题。最终矩阵使用新普通 Vite，没有只读观察服务和诊断预热覆盖。缓存替换边界补修前的完整矩阵也保留，未择优删掉其四个 live 超标样本；中间矩阵的三个 live 超标样本同样保留。最终 source 对象／版本保护完成后重新跑完相同八格矩阵。

## 距离 Typora 级质量的剩余必办

- 全文件搜索和长文交互性能：减少约百秒的末尾搜索；对剩余超标样本定位，保留同规模基准；进一步覆盖混合 Markdown、极长行和长时间连续滚动，不能用更小夹具关闭性能缺口。
- 真实中文 IME：在有可用系统输入法会话的环境，实测预编辑、候选提交／取消、中文标点、光标移动、撤销及保存。此前 IBus 已安装但会话未通，合成 composition 不算验收。
- 跨平台与互操作：当前分支 Windows/macOS 原生键盘、文件对话框、IME、窗口与文件监视；Word 2016 粘贴／导入导出均保留未实测。历史文档的旧平台勾选不替代当前分支验收。
- Markdown 产品完整性：窗口化表格编辑、大文件替换及复杂块组合，继续按真实编辑闭环验收。
- 体验与视觉：补齐辅助功能、焦点可见性、触控板／XTest 鼠标环境差异、混合块纵向节奏、长行水平阅读与窗口化换行体验；当前 EOF 截图只是功能布局证据，不能代表完整视觉或易用性达标。
