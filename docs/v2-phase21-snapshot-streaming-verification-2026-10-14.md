## 有界协议与安全验证

恢复 gate 先串行化捕获、写出、校验、发布与 settlement。在文档注册表锁内一次验证版本并捕获分片描述、编码、独立文件读游标及工作文件租约，然后释放文档锁。完整正文写出、fsync、SHA 和原子清单发布均在文档锁外；恢复 gate 与跨进程存储锁仍保护发布。超 256 MiB 的快速拒绝仍存在，前置大小检查不捕获版本，真正版本验证与捕获同锁完成，等待 gate 时不持文档锁。

捕获最多 65,536 个描述，测试确认描述向量最多 3 MiB；流式读缓冲 64 KiB + 3 字节，另有 64 KiB 输出缓冲，没有整文档内存复制。高度碎片化超过该描述预算会明确报错并保留旧恢复点，不静默跳过或改变调度频率。原有正文／恢复目录准入、完整校验、上一代保留不变；这不解决既存全盘长期存储增长。

基础工作文件不可变，add 文件只追加。快照使用独立 open，避免 try_clone 共享 seek 游标。保存若遇被租用的 add 代次，先准备新的唯一工作文件，成功后切换，不能截断旧代次；关闭／重建只释放自己的租约，最后读者关闭句柄后才清理对应工作文件。Windows 的已有 immutable-base 共享模式保留，未把 Linux 验证冒充 Windows 关闭语义通过。

新增旧实现失败回归证实“捕获后、写出前仍持注册表锁”；[红测试](./evidence/v2-phase21/lock-red.log)与可复现补丁保留。首轮候选测试又发现固定 add 文件名在同 ID 重开时截断旧快照，随后改为唯一代次名＋create_new。该失败原始日志保留并压缩归档，不能因最终通过抹去。最终回归验证 UTF-8／UTF-16 LE／BE、BOM、CRLF、中文／emoji、保存、关闭、同 ID 重开与捕获版本字节；另在真正分片写出中途暂停写线程，执行读取、追加、保存、关闭，恢复后核对全部捕获字节与最后租约清理。超预算描述测试、既有发布／配额／磁盘错误保护一并保留。

生产中断新增“部分正文写出”场景，与原有“完整正文但未发布”场景分别执行。首次探针发送 SIGSTOP 后未确认所有线程停止，前者部分正文继续增长，后者清单在 SIGKILL 前已发布新代次，导致断言失败。现场复核显示后者恢复副本 SHA 正好等于已发布新版本，并非损坏；[失败审计](./evidence/v2-phase21/interruption-probe-failure-audit.json)保留。修正探针为观测目标边界后立即 SIGKILL，等待核验过 PID／出生时间的进程退出，再检查清单和正文。两场景各作一次有原因的复验通过：部分正文 1,245,196 字节，预期全长 104,857,631 字节；重启恢复旧点，原件、旧正文及未发布部分正文完整保留。完整正文中断同样恢复旧点。不能把长度观察声称为确切 fsync 完成或物理断电验收。
