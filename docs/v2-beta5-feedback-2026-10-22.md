# beta.5 插件即时生效与编辑完整性

本轮本地生产交互验收已完成，正准备精确候选的 Windows 构建；尚未上传 Windows beta.5 安装包。最新产品修复提交 `66ace39eca0df4be8083e34b53f6e2091aefa73a`，来自已交付 beta.4 `0e74d9fad211c304ef68449fa6becb7450dfffef`；仅独立分支 `dot/milkup-v2-beta5-feedback`，无 main 合并或正式 Release。

## 已确认的问题与修复

- 图表呈现原先只看保留的选区，不看编辑器是否真正有焦点。已有文件中把光标放入 Mermaid 块，再去插件页启用，即使 renderer 已成功也被选区过滤。现在失焦的折叠光标允许块预览，真正编辑焦点/展开选区保留源码；错误诊断不再被选区吞掉。没有另加重复的热刷新链，也没有关闭 Windows DOM/PDF 隔离门禁。
- 插件列表原先整体替换 DOM，且 pending→active 分段改变顺序。改为按身份保留卡片节点和初始顺序，后台更新不抢详情、滚动或焦点。
- UI sync 在逐项 await 后可能把禁用/换文档之前的后续 UI 挂回。现先同步撤下全部失效 DOM，后续工作受 sync 序号和实例代数约束；旧 render/dispose/focus/action 不进入新实例。原生启动持久化响应迟到时，发布前仍须满足原 activation epoch，不能复活已撤销实例。
- Live 代码围栏只隐藏呈现，不删源文；保留完整映射、复制、历史、IME 处理和语言编辑。闭围栏不留空代码行；source 与 readonly Live、普通与窗口化路径分别覆盖。
- Formatting 1.0.1 仅在当前表格快照有效时显示工具条，离表或切文档即撤下，迟到快照和旧命令不能作用到新文档。宿主对空输出统一隐藏整个贡献及空工具行，不耦合插件 ID。
- 实际暗色系统截图发现 Worker 图表未指定 tone 的文字使用 SVG 默认黑色，难以阅读。宿主对这种文字明确使用 `currentColor`，保留显式 tone；没有开放任意 CSS/SVG 或修改插件协议。新增原生 computed fill/宿主颜色一致性断言及截图复核。
- 旧随包 Formatting 1.0.0 仍为 pending 时，卡片原先优先显示旧候选，遮住实际下一次开启会选择的 1.0.1 随包升级。卡片改为优先显示该可信升级，详情仍保留旧 pending 信息；升级校验、候选身份绑定及启用逻辑不变。三种 pending/offer 组合先红后绿，渲染与 catalog 共 91 项通过。

## 生产流程验收记录

使用私有 Linux namespace/WebKit 沙箱、独立 `/tmp` 资料、真实 X11 键鼠/GTK 文件选择器和生产资源，DOM 执行只观察；不注入私有编辑状态。普通 Linux 随包 DOM 候选通过 UI 移除后导入同一独立 Worker，这不是 Windows 旧安装迁移证明。

已出现的验收失败均保留：

1. 读取自建测试进程 `/proc/environ` 被 namespace 权限拒绝。没有调整权限；后续记录启动环境、启动前空目录与实际生成的 catalog/WebKit 文件，明确 `processEnvironmentVerified:false`，只提供间接路径证据。
2. 滚动后原生测试点击使用了陈旧坐标：按钮在 128ms 内移动 57px，原点落到状态文字。静止点击与修后强制滚动点击均成功；helper 等待坐标稳定并复核真实鼠标命中，不改产品来迁就测试。
3. 35 个连续步骤通过后，未知图类的测试要求“不支持/unsupported”字样，但实际已经明确显示“受限流程图与时序图：exactly one diagram header is required。已保留完整源码。”且没有图形替换。测试改为该夹具完整诊断的精确匹配，仍要求可见、无图形、源文完整及选区/失焦条件。
4. 第四轮 55 步通过后，系统复制读取显示 CRLF 变为 LF。独立对照确认 Source 和 Live 的原始 `UTF8_STRING`、`text/plain;charset=utf-8` 都是与磁盘相同的 126 bytes/8 个 CRLF；只有 GTK `wait_for_text` 返回 118 bytes/LF。直接 GTK 写入 CRLF 的控制组也相同。改为读取原始 selection data，并校验格式、长度及 UTF-8；预期字节和严格相等断言未改，产品无需修改。
5. 第五轮严格复制通过，57 步后发现真实产品缺陷：Live 替换代码行后磁盘保存正确，后续复用代码 span 的源文偏移仍是旧值。`console.log(名)` 应由 `77..91` 变为 `63..77`，闭围栏应由 `93..96` 变为 `79..82`，等待 2.5 秒仍未更新，Source→Live 重建后才恢复。不能放宽映射断言；本轮据此追加最小增量映射修复与新冻结构建。

一次系统截图的空白判断经原始 PNG 哈希和像素比对推翻：系统图与 WebView 图对应区域完全相同。另做两轮先截 X11、后截 WebView 的时序采样，首轮 0ms 尚是旧菜单帧，250ms 图形和正文完整；没有复现空白或截图触发重绘，不为此修改产品。
