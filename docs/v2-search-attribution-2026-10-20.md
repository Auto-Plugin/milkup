# 首次搜索延迟的有界归因（2026-10-20）

**交付归因与回归证据，没有性能修复；500 ms 门槛仍开放。** 分支 `dot/milkup-v2-search-attribution` 从已接收的 `67cab4650973e4fba3fd26950b6b68ae5d09dc11` 建立，产品实现仍与该基线及 cf7 相同。诊断只用于独立 Linux 构建，已从最终产品源码撤回；提交保留测试、实验源码/补丁和报告。不采用未接收的大纲候选，不改变插件、公共 SDK、依赖或系统设置。

## 原测量边界和新增证据

承接[上一检查点](./v2-p7-input-search-checkpoint-2026-10-20.md)的 858 条观察、726 条键盘计时与六次首次查询。此前 Source 首次查询为 519/500/512 ms，Live 为 514/921/573 ms，五次超出 500 ms。不能把既有输入 p95 通过当作首次搜索通过。

新增两轮仍使用原始 10,485,779 字节、163,842 行 CRLF 夹具，SHA256 `4260c361024f7d9f0c32e9e5d2abffcbaf3a03efcdd7e553a69f0d5413c16806`。每轮完成原 20 次可逆编辑及精确字节保存后，以真实 XTest 输入首次查询 `A`，忽略大小写，结果 `1/1`、光标 UTF-16 位置 1、版本 40。起点仍是真实 keydown，终点仍是精确结果/光标 DOM 满足后两次 rAF；原有 150 ms 防抖保留。这里的首次查询**不是冷磁盘或冷 OS 缓存**，也不是打开后未经编辑的查询。

诊断构建显式使用 `MILKUP_SEARCH_DIAGNOSTICS=1`，最多保留最新一次查询的 256 个阶段标记，仅记录阶段、序号及有限数值，不接受路径、文档 ID、正文或查询文本。另给既有 20 ms 心跳增加最多 256 个间隔记录。没有减去诊断开销，也没有改变观察条件。这两轮各只有一个首次查询，不构成 p95 或可靠 A/B 加速证明；没有按结果追加计时轮次。

## 得到的归因与不能得到的结论

第一行含 emoji，使整个约 1 MiB 首分片走大小写折叠的 Unicode Worker 回退，实际回退 1,048,523 UTF-16 单元。其余分片走既有原生 ASCII 路径。这是当前实现的实际路径，不能为了通过预算把夹具改成纯 ASCII 或改为区分大小写。

Live 第一轮在首个分片的 143 ms 往返期间出现一个约 108 ms 的主线程心跳间隔；Source 对应期间没有超过 50 ms 的心跳间隔。Live 比 Source 多出的整体耗时主要出现在这一次往返，Worker 活跃匹配时间接近，最终同步高亮与导航不足以解释这 104 ms 差距。这是**本次两轮的观察和相关性**，不是稳定的模式差异或引擎因果证明。

`nativeMs` 在获取文档/搜索锁并进入 `Search.step` 后才开始，覆盖读取、解码、扫描和索引处理，不含命令排队、取锁、响应序列化、跨进程传输和 JS 回调调度。首分片 140.50 ms 余量不能直接命名为“序列化耗时”。现有 WebKit 不支持本测试的 Long Tasks 记录，心跳间隔也不能区分 WebKit 解析、其他主线程工作或进程调度。DOM 后 77/92 ms 的呈现代理等待仍独立存在。此前 921 ms 的长尾没有在这两轮重现，不能宣称已经解释它。

尚无足够依据提交安全的最小修复。缩小回退分片可能减少单次正文传输，却增加混合 Unicode 文档的 IPC 次数；改写 Unicode 折叠或切换原生 ASCII 语义可能改变 `İ`、希腊字母等匹配。这里没有通过猜测修改这些路径，也没有减少防抖、提前宣布完成或放宽 500 ms。

最小下一份证据是：保持同一夹具/查询/完整计时，在首分片增加命令入口、锁获取、step 返回的有界耗时，再与同轮 WebKit 主线程时间线对齐，区分锁等待与返回/回调之间的成本；另需帧调度/绘制证据才能解释呈现尾部。未在本轮获取这些证据，也未为此安装新引擎、工具链或运行时。

## 功能和数据安全核验

两轮计时共 286 条观察，其中 242 条真实键盘计时，仅 Live 首次搜索一次超原门槛；每轮计时之后另做真实 X11 剪贴板替换 `中é👩🏽‍💻`、保存、undo、保存、redo、保存、再次 undo/保存，共 8 个完整字节校验。原始 SHA 恢复一致，修改态 SHA 为 `00cf94802a87feb7ac2382af4e9650da6e5a12b949b65a18208c7ed41336b9b5`。这验证组合码点、emoji、CRLF 和历史，不是真实 IME 验证。

独立 2,097,206 字节 Unicode 夹具的 Source/Live 原生复验 12 项通过：完整计数、首项与下一/上一项 UTF-16 选区、改查询取消旧结果、单项/全部替换后的 undo/redo 精确保存与重开、文档切换时取消运行中的扫描。跨文档记录均包含旧 run 的 `controller-start`、`worker-matches`、`append-start` 和 `controller-cancel`，没有 `controller-complete`；新文档保持未脏、光标 0、结果 0/0，重开原文仍是原始字节。

首轮跨文档测试的观察器注册晚于应用按键处理器，错误地把切换后 `searching=false` 当作切换前状态，断言失败；其 exit 1、原图、JSON 和已通过的五项全部保留。只修正观察方式后做了一次限定复验。新的阶段观察最多 512 项、检查没有丢项，不依赖延长等待把失败掩盖。原生取消证明不等于强制制造迟到 IPC：新增确定性控制器测试在新文档搜索完成后才释放旧文档 step，断言旧结果不会再发布；已有 SourceDocumentView 单测另覆盖迟到导航与文档切换。

诊断阶段单测 9 项及 SourceDocumentView 64 项通过。撤回诊断产品代码后，全仓 `test`、`typecheck`、`build` 和格式检查通过；最终正常前端产物不含阶段标记。诊断 Linux Tauri `--no-bundle --ci` 构建成功，冻结 ELF SHA256 `c8f11431358c3e829fa8efe323a95d15634205b2aa3fd1bc1250b8544e53169b`，构建输入无漂移，旧基线 ELF 保持原 SHA。最终产品源码无修改，因此没有把诊断 ELF 当作可交付默认安装器。
