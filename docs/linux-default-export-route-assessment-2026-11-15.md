# Linux 默认导出：可维护路线只读评估

2026-11-15。产品基线 `0e4e8c580353710db9b7f0ec4820522d305ec9fc` 不变。本轮只读源码与已留存报告，更新文档；没有执行 PDF/CI、构建、安装或修改产品。这不是对当前所有发行版上游状态的检索结论，也不是发布方案批准。研究材料未对外发送。

## 已证明的缺陷与互不替代的证据

| 问题 | 已有证据 | 尚不能声称 |
| --- | --- | --- |
| 原文字形与 Unicode 映射 | 默认 WebKitGTK 的中文/部首共 glyph 映射失真；Noto CJK Latin-context `WRAP0123456789` 经 locl 使用无 cmap 的 glyph，原路径生成 U+0000。私有补丁保留源字符与实际独立 cluster 关系；43672149274 同运行时 A/B 十个数字映射恢复，页面像素相同。 | 不是全局替换字码；复杂脚本、合字、组合/RTL/重排仍有边界。Poppler 提取/搜索不是人工剪贴板验收。 |
| URI 链接 | 私有 GraphicsContextSkia 注释路径已有多页、邻链、无链接负例及独立打印/绘制几何证据；局部重复矩形去重和真实 clip 量化分别验证。 | 不是默认发行版已支持；不能用屏幕 DOM 或文本字框代替链接区域；文字修复不自动修复链接。 |
| 分页 | 默认 2.52.6 的原应用 A4 标题孤行。43693522845 使用原包、原 guard、12mm 设置重现 693 个词坐标一致；CSS 链未修复，且使临界短表从正确整体换页变为孤行。长表续页表头缺失。 | Letter 横向限定通过不意味着 A4、所有纸张通过；内容标记完整不代表标题关联、表头重复或可访问 PDF 通过。没有可集成的 caption/CSS 修复。 |

研究运行时七个二进制/库与前轮保持相同哈希，但最后数字验证未执行安装版步骤；不能拼接为产品全部导出通过。原文/部首、数字、链接、分页应分别保留门禁。

## 最小路线比较

| 路线 | 能保住的性质与实际代价 | 判定 |
| --- | --- | --- |
| 上游审查修复 → 支持中的发行版回补 → Milkup 继续用系统 WebKitGTK | 是现有架构下最合适的完整修复方向：保留实际 glyph、源文字和 URI 注释，不改变文档绘制成图；沿用发行版安全更新与既有离线静态打印边界。仍需单独修复分页，验证复杂文本及正常系统库下的应用输出。 | 首选，但当前仅有待审研究材料，没有发行版采纳或可交付版本证明。不能仅凭版本号判断含补丁。 |
| 发行版维护者先审查窄回补，再跟随上游整合 | 可缩短等待，同时由发行版承担包 ABI、沙箱助手及安全更新重基线。需其接受、维护和正常更新路径，不能由 Milkup 偷换系统库。 | 可审备选，与上一条同样需要维护者和安全生命周期证据；本轮不外发。 |
| 保持默认后端，明确显示已知限制，用户显式选择现有 HTML 或原 Markdown | 不增加引擎/网络/执行权限；可以避免用户误以为 PDF 是可检索的忠实副本。HTML 仅保留其已验范围的文字/链接和离线资源策略，Markdown 保留源码；都没有 PDF 的固定页框、分页或打印合同。 | 可独立做的小型产品提示，**只缓解误导，不修复 PDF**。不得静默换格式或把该路线计入 PDF 保真完成。 |
| 使用已验 Windows 原生 PDF 路径 | 是另一个平台的既有选择，只能继承其精确包/样例证据。不能自动从 Linux 调用，也不能推广到所有语言、链接与分页。 | 可在说明中标注平台范围，不是 Linux 本地离线等价备用。 |
| 私有前缀/自带 WebKit fork、换 Chromium、图像 PDF、提取后字符替换 | 私有 fork 需持续安全补丁、依赖/ABI/沙箱助手与签名更新维护；图像丢文字搜索复制与 URI；事后替换不能分辨真实部首/同 glyph 不同源字符；另一引擎改变架构和验收面。 | 本轮均不采用。研究前缀不是生产依赖，不系统替换、不钉死旧库、不关闭沙箱。 |

当前没有一条**已经交付并实测**的 Linux 默认路径同时满足语言文字、链接、分页及现有安全/离线约束。可维护方向是发行版修复，局部私有探针不能填补这一事实。

## 现有产品边界与独立小修提案（未实施）

源码审查：`apps/desktop/src-tauri/src/output_linux.rs` 用临时 WebKit context、受控静态 scheme 和 CSP（脚本、连接、frame、worker 禁止，图片仅 data）。`apps/desktop/src/output-service.ts` 将资源/呈现 warnings 汇总到捕获快照；`plugins/export-print/src/plugin.ts` 已将 warnings 作为安全文本状态显示，并提供 HTML/PDF/打印显式选择。插件 README 已说明 Linux 复制/搜索限制，但面板没有对应的通用保真说明；“已保存”仅表明写入成功。

可审小修：把 README 的已知限制以可见、可访问文本带到输出界面，并补上链接及分页事实。建议文案：

> Linux PDF/打印目前可能出现文字复制或搜索不准确、链接缺失、表格标题与首行分离等问题。保存成功不代表内容保真。需要保留可编辑原文时，请另存 Markdown；HTML 是另一种输出格式，不保证 PDF 分页。

实现边界待审：在宿主确认 Linux 后，仅 PDF/打印显示；如现有插件能力尚无可信平台字段，先在现有格式帮助区使用明确的条件句“在 Linux 上…”，不能猜测平台或为提示开放额外权限。不要依据文档是否出现已知几个汉字决定安全，普通 Latin 数字也存在已证失真。提示须在提交输出前可读、完成后仍可见；已有成功状态不升级为质量合格。现有 HTML 选项由用户主动选择，不自动转换、不自动打开外部浏览器、不导出第二份未授权文件。原快照版本、图片遗漏提示、目标保护、取消/队列边界都不改变。

下一步若获准实现，最小合同应覆盖 Linux PDF/打印提示、HTML 不作等价承诺、其他平台不被误判、提示可访问与安全文本、取消/写入失败仍保留真实结果。这里只列门禁，不执行测试或派发任务；提示完成也不关闭导出缺口。

## 发行版路线所需材料与停止点

已有待审稿需要去掉夹具开关/诊断，审查源文字元数据所有权、display-list/远端路径、partial run 与各后端支持；保留错误 cluster、合字/组合/重排拒绝和同 glyph 多源字符负例。URI 回补单独审查去重作用域、跨页/邻接链接及裁剪。分页需新的可判别引擎级解释；已停止的 CSS 链不继续尝试。

未来正常发行版验收入口已准备：`run-webkit-link-probe.py ... --system-acceptance` 拒绝私有前缀、清除库覆盖，检查 host/owned WebProcess 系统库映射、包版本及哈希；该入口尚未在修复后的正常系统运行时原生通过。它也不能替代严格几何、实际 Milkup 安装版、复杂文本、复制界面和分页。只有有维护者认可的运行时可用后，才讨论必要的精准后续验证；本轮不发起。
