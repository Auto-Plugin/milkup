# Milkup 2.0 P1：版本体系与应用更新

本阶段从交付基线 `0f2ccc754c138b925d0db7c925f2b1d741200fc1` 开始，工作分支 `dot/milkup-v2-product-completion-phase1`。完整产品计划见[阶段计划与验收矩阵](v2-product-completion-plan.md)。P1 完成代码和本地可验证链路；真实发布渠道、签名发布包、Windows 更新安装/重启仍是外部门槛，不能据此宣布整个产品完成。

## 用户可见变化

- “关于”与应用构建统一显示 `2.0.0-beta.1`。根 `package.json` 是唯一应用版本来源；`version:sync` 同步派生字段，Vite、根构建与 Rust 构建检查漂移，Tauri 直接读取根版本。SDK 仍为独立的 `0.1.1`；大纲包为 `1.3.0`，兼容范围明确写为 `^2.0.0-0`，不改大纲实现。
- “关于 → 软件更新”提供检查、纯文本版本说明、已知/未知大小进度、取消、失败重试、下载后安装确认。下载不会自动安装；默认焦点落在“暂不安装”。更新检查、下载完成后的键盘焦点保持连续；用户回到编辑器后不会抢走焦点。
- 安装前复用文档切换的保存保护，先 flush 输入与恢复，再核验 dirty、外部修改冲突和保存状态。更新不能选择“放弃修改”；取消或保存失败不安装。进入安装阶段锁定文档操作，安装失败恢复可编辑状态。
- 默认没有可信发布端点或公钥。实际桌面显示“此测试版尚未开放在线更新渠道”，浏览器预览提示使用桌面版，不误报“已是最新”。

## 可解释的实现边界

发布渠道在 `release/update-channel.json` 编译进后端，只接受无凭据的 HTTPS 地址。稳定渠道不接收 beta，版本比较拒绝同版和降级。前端只能传候选版本令牌，不能传安装路径、任意字节、下载地址或公钥。候选令牌与串行操作约束阻止过期请求安装；取消会清除已验证内容。

使用锁定的 `tauri-plugin-updater 2.10.1`，与现有 Tauri 2.11.5 兼容，未借机升级整套 Tauri。下载调用官方 `Update::download` 完成 minisign 校验，只有成功后才在内存中保存安装字节；再下载会重新验证。设 20 秒检查、300 秒下载超时，下载上限 256 MiB；超限、空包、取消、HTTP 错误、签名错误都不能进入可安装状态。未给前端额外授予官方 updater IPC 权限，使用四个受控应用命令。[Tauri updater 文档](https://v2.tauri.app/plugin/updater/)、[锁定版本 API](https://docs.rs/tauri-plugin-updater/2.10.1/)。

签名测试使用 `minisign-verify 0.2.5` 已公开的 MIT 测试向量（正文 `test`），没有生成或持有发布私钥，也没有跳过验证的生产开关。HTTP 测试端点只存在于 Rust `cfg(test)`；浏览器安装替身仅由 Playwright 路由替换测试模块，生产资源未包含它。许可和来源见[夹具说明](../tests/fixtures/updater/README.md)。

插件恢复时重新验证当前宿主兼容性，旧 `^0.1.0` 插件不能绕过检查自动运行。保留旧档案、来源、设置和审批记录，允许用户从普通入口安装兼容版本；不静默扩大兼容范围或权限，不改变通用预装的“一次处理、禁用/卸载不复活”策略。此处改动 `packages/plugin/src/registry.ts` 兼容检查，未改变 core 公共 API；桌面 CSS 仅增加更新面板的局部规则。插件设置、权限变更和升级回退的完整体验仍属 P7。

## 验证与失败证据

1. 先复现版本范围的 4 项失败，以及恢复时旧插件绕过宿主检查的 1 项失败；修复后插件 registry 30 项通过。真实版本漂移脚本测试在隔离目录故意改动版本/渠道/Tauri 来源，验证失败门禁及同步行为。
2. 全仓单元测试 1026 项、大纲 24 项、版本门禁 1 项通过；全仓类型、构建、格式通过。最后焦点修改后另过桌面类型检查与生产构建。
3. Rust 全量 80 项通过、1 项既有性能测试忽略；随后补充清单故障测试，更新模块最终 6 项全部通过。真实下载验证正确签名通过，修改正文、签名、公钥均失败；503、截断、超限、取消拒绝安装字节。清单测试覆盖 204 无更新、坏 JSON、缺签名、503、超时、离线。
4. Chromium 全量 91 项首轮 90 项通过，1 项在读取 Vite 模块时发生 `route.fetch ECONNRESET`，未进入产品断言；原样定点重跑通过。原生发现焦点问题后，更新相关 12 项全部再过，并补过后台下载不抢编辑器焦点 1 项；最终更新相关 13 项整体重跑通过。覆盖普通文档和 16000 行窗口化 source/live、取消/保存失败/安装失败、完整 Unicode/CRLF 保存字节。
5. 原生基线截图实际显示 0.1.0 且无软件更新入口。首轮新包发现检查按钮禁用后 WebKit 焦点落到 body，保留失败日志；修复后重新构建 deb，再用实际生产资源、真实 IPC、系统键盘和 X11 截图验收。缩放脚本的早期超时另记为测试时序问题，修正为等待原生设置完成，没有用 CSS zoom 或 DOM 状态注入伪造结果。随后新增完整可见范围断言，在 760×520、200% 下实际捕获按钮底部 279 CSS px 超出 260 CSS px 视口的失败；显式滚动到当前操作并为焦点轮廓留出边距后重建验证。

Linux 生产矩阵覆盖 light/dark × 原生 100/125/150/200% × 1100×760/760×520 共 16 组合，检查按钮和焦点轮廓完整可见；检查更新后 source/live 输入、撤销、重做和磁盘保存保持完整 Unicode/CRLF。旧大纲 1.2.0 的不兼容提示及正常 GTK 选择器安装/启用 1.3.0 已通过，原文件字节未变。

具体生产矩阵、插件迁移结果和产物摘要见[证据摘要](evidence/v2-product-phase1/summary.json)。[基线 About](evidence/v2-product-phase1/before-about.png)、[修复前 200% 裁切](evidence/v2-product-phase1/before-clipped-200.png)、[最终深色 200% 窄窗](evidence/v2-product-phase1/after-dark-760-200.png)、[浏览器确认安装界面](evidence/v2-product-phase1/browser-update-dark-760.png)。证据中浏览器截图验证更新流程；Linux WebKitGTK/X11 截图验证实际未配置渠道、原生缩放与交互，两者不混称。

## 未验证和下一阶段

- 未创建真实发布密钥、签名完整安装包、部署更新清单或发布 Release。真实签名发布包的安装/回滚/重启必须在受控发布渠道建立后单独验收。
- Linux deb 仅用于本阶段生产 UI/IPC 验证，不把它当作已支持的自动更新目标；Tauri Linux 自动更新包格式需在发行方案中明确。Windows NSIS 更新安装、重启、权限/UAC、用户文件保留、真实 IME/DPI 未由 Linux 或浏览器测试替代。
- 本阶段未构建或上传 Windows 包。用户新批准的 WebView2 Runtime 再分发条款与单次 ≤256 MiB、≤1 天、≤US$0.01（税费另计）上传额度已记录在计划，尚未消费。P2 可据此继续标准/离线双包与安装升级矩阵；需要新的单次请求记录，不复用已消费额度。
- 正常推送此隔离工作分支后向父线程报告阶段边界；不整合 main/v2/quality，不强推，不自行宣布 P2–P9 完成。
