# 第十四阶段：大文件查找／替换设计与安全边界

基线为 `55f8f999aa6363c1aaa7ef127e7b250c6a18850f`。只处理当前文档，不增加工作区搜索。

## 已取得的原始测量

同一个 104,857,639 字节、1,638,402 行编号 CRLF 文件，查询 `tailneedle`。原型仅观测现有路径，不改变搜索策略。首轮没有 ready 等待条件，发生超时且未留下分项结果；不能仅据此确认超时根因，不计通过；补充 ready 检查与中途进度后有界重测成功。

- source：搜索 87,626 ms，窗口读取累计约 83,668 ms。
- live：搜索 94,740 ms，窗口读取累计约 90,668 ms。
- 每次约 3,201 次扫描读取，另有少量跳转窗口读取；返回的窗口正文与行正文合计约 206,444,460 UTF-16 单元（约 197 Mi 单元）（含重复）。
- UI 回调和高亮时间单独记录；读取累计包含 IPC、原生读取／序列化、返回解码及调度，不能直接全部称为磁盘扫描。
- 原生同窗口直接读取／序列化基准另行分解。所有原始样本保留，后续同夹具、同查询对照。

## 搜索

- 原生按约 1 MiB、完整逻辑行边界推进，检查 documentId、版本和查询代次；每批释放锁，允许输入、取消和新查询接管。
- 大小写敏感的字面匹配，以及可证明与当前 JS locale 等价的纯 ASCII 批次由原生扫描；其余批次在 Worker 中复用原有 JS 字面匹配语义，采用背压分批返回坐标。不得把 Unicode 搜索改成不同的正则 case-fold 语义。
- UTF-8 字节位置与 UTF-16 编辑位置分开保存，CRLF、emoji、大小写展开和跨批次边界保持原坐标。
- 完整结果保存在原生临时索引；同一行等间距同长度匹配可用游程压缩。界面只加载有限结果页，显示完整计数，并可导航到全部匹配。当前页高亮限制不等于截断搜索。
- 原生索引只有全量扫描结束才标记 complete。取消、失败、文档版本变化和旧代次均不得启用全部替换。

## 替换与历史

- 单项与全部替换使用同一原生准备／提交协议，替换文本按字面插入，不解释 `$1` 等规则。
- 先 flush 已接收输入；替换准备阶段显示进度并暂时只读，保留取消入口。搜索阶段仍可编辑。
- 原生分批写入替换前后临时快照，完成索引构建后再次检查版本和取消状态，才一次切换文档；失败／取消不修改当前正文，不直接写用户文件。
- 保存继续走既有磁盘冲突保护。前后快照仅保存在原生侧，前端历史保存不透明 token，从而一次撤销／重做全部替换，无需把全文或百万个 Change 对象送入前端。
- 文档关闭释放索引和历史临时文件；同一文档新查询释放旧索引。临时目录必须私有。

## 显式资源边界

单个需要完整上下文的逻辑行缓冲最多 8 MiB，查询最多 65,536 UTF-16 单元；索引和历史磁盘空间有明确预算。超过预算必须报错、保持 complete=false 且禁用替换，不能把部分结果伪装为完整结果。前端任何时刻只保留有界文本批次、Worker 背压批次和结果页。

验收覆盖头／中／尾／空／密集查询、大小写和 Unicode、快速重搜、搜索期间编辑／换文档、取消／失败、单项／全部替换、整体撤销重做及保存重开字节。运行串行并记录内存与输入响应性。Windows/macOS/Word 2016、系统 IME、窗口化表格和视觉可访问性继续保留未验收。

## 复跑入口

先按环境文档启动原生 driver，再执行 `pnpm dev:native:search-profile`。这是只读观察与计时的专用 Vite 服务，不进入正式构建。提供 `MILKUP_SEARCH_FIXTURE`（第十三阶段 100 MiB 原始编号文件）和独立 `MILKUP_NATIVE_EVIDENCE_DIR` 后运行 `pnpm bench:native:search` 或 `MILKUP_NATIVE_XTEST=1 pnpm test:native:large-search`。Unicode 流程使用 `pnpm test:native:unicode-search`，自己生成跨批次夹具。各流程串行运行；原生输入工具故障和实际覆盖见[最终验收报告](./v2-phase14-search-verification-2026-10-13.md)。
