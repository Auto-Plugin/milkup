# 第十七阶段：异常退出与恢复副本验收

本轮从已推送且核验的 `0ca868a077fe88459c227736739209ec141259c1` 接续，专用分支仍为 `dot/milkup-v2-quality`。初始干净；没有重置、新建环境、强推、合并远端 v2 或发布应用。新环境最初精确恢复 `cefe9e4` 的证据见[第十一阶段](./v2-phase11-clean-environment-verification-2026-10-13.md)，本轮没有回退到配置默认的 `f713d91`。

## 已确认的问题与修复

旧版本只在正常关闭时询问未保存内容。普通草稿驻留内存；大文件虽有 base/add 工作缓冲，piece tree 结构并不持久化，重启不能直接恢复。启动清扫还会删除死进程缓冲。架构文档的 crash recovery 是目标，不是原有已完成承诺。

冻结基线的生产二进制实测未命名草稿、已有文件未保存、大文件已提交编辑三种异常退出：原文件未坏，但重启没有恢复提示或完整编辑恢复链路。大文件工作缓冲在终止前另存副本，未丢弃仅存的测试数据。

新增独立恢复点，按进程和文档分开记录；正文写出并同步、计算长度与 SHA-256、原子提交清单后才显示“恢复点 vN”。普通文件遵循保存换行策略；窗口化文件由 Rust 写出，不把全文传给前端。每份上限 256 MiB，保留当前和上一份已提交快照；未知或写入未完成的文件不自动删除。新增代次采用独占创建，清单错误不会被静默覆盖。

启动只提示已经退出的会话。恢复校验后生成独立副本，成功打开才归档记录；不会自动覆盖原路径。暂不恢复下次仍提示；放弃本次恢复只归档，菜单“恢复记录（含已归档）”仍可取回。活跃会话不可恢复或归档。停止旧的死进程缓冲清扫，正常关闭仍清理本会话明确拥有的工作文件。

原生 UTF-16 验证另发现写出按每个码元调用文件写入，约 2.8 MB 夹具在原有 15 秒断言预算内未完成检查点。改用 64 KiB 缓冲，显式 flush 后再 fsync；相同夹具、期限和生产路径复验通过。增加 UTF-16LE/BE、BOM、CRLF、多缓冲区与原文件不变的回归，没有以增加超时宣称性能通过。

## 恢复点和可能丢失区间

编辑停顿 750 ms 后尝试，连续编辑最多每 5 秒发起尝试；保存及大文件替换准备前也尝试检查点。这是尝试调度，不是“最多丢五秒”的承诺：队列、I/O 失败、大文件写出、尚未提交的窗口化批次／IME 都可能让恢复点更旧。状态栏显示最后成功版本及待更新或失败状态。

受控测试明确记录 v7 已落盘、界面观察到 v8 后立即 SIGKILL：重启只能恢复 v7。该结果是已说明的丢失窗口，不能记成最后输入无损。没有承诺恢复光标、选区、撤销栈或 IME 预编辑。这里验证的是进程异常终止，不是断电、介质故障或系统强制回收全部写缓存。

## 真实生产验收矩阵

全部通过构建后的 `tauri://localhost` 生产资源、真实 Rust IPC、XTest 系统按键和磁盘读取完成；没有注入内部编辑器状态或调用伪造恢复接口。终止前核验二进制、启动夹具、PID 与 `/proc` 出生时间；只信号本任务应用。每次原生启动沿用既有期限。

窗口化待提交输入另以同一 100 MiB 夹具验证：后台真实检查点写出期间通过 XTest 发送 `PENDINGBATCH`，观察到界面为 `CHECKPOINT17NEXTP…`，当时原生 add 缓冲仍为 `CHECKPOINT17NEXT`，确有可见而未进入原生缓冲的输入。停止／终止只针对已核验进程。终止前读到 v5 清单，进程完全退出后读到已发布 v9 清单；恢复按后者完成，全文 SHA-256 为 `3c58f27ea321d57e8cf300c959de36b001174c6395e0fb2a0db818726ea6c19c`，与恢复副本一致。恢复以完整发布清单为准，可能比前端最后来得及显示的确认点更新；不保证待提交输入。

该实验的前两次工具结果不能计入通过：首次 Node 测试进程耗尽堆，未留下完整比较结果或具体断言位置；应用仍存活，磁盘恢复副本与清单一致；另一次发现 WebDriver `null` 被工具包成真值对象，等待条件无效，明确撤销该次待提交断言。修复 null 解包并加入回归，使用紧凑的完整 `Buffer.equals` 与哈希输出、退出后稳定清单后，第三次形成有效闭环。原始日志、撤销说明和最终结果均保留；没有增大 Node 堆或交互超时。

两个 100 MiB 用例使用原夹具的独立复制：104,857,639 字节，原始 SHA-256 `d9b2dd396a2624d9563c3bfc43e69a3c1e7c1dd4b1f0239f28bc5a8bafcbf6e1`。完整编辑副本 SHA-256 均为 `4e64f5c50ea958c98658c01aef9f7344c031f8e734192c47df374e011d550b99`。没有缩小夹具或提高性能目标期限。
