# milkup 2.0.0-beta.7 Windows 手测试用

本包用于手测中文组合输入、逐键列表输入、CSS 外观和菜单开启时的标题栏操作，并保留右键菜单、表格浮层和插件回归，是未签名的 Windows x64 测试包。本指南是待执行步骤；**本轮新增 UI 尚未完成真实 Windows GUI 验收**，构建、浏览器或 Linux 结果不能替代 Windows、中文输入法和系统 DPI 实测。源码、EXE 摘要及随包插件以 `manifest.json`、`plugins.json`、`SHA256SUMS.txt` 为准。

**完整 Mermaid 尚未完成，也未放入本包。** 本包沿用 beta.6 的受限 Worker Diagrams，只覆盖已支持的流程图、时序图语法；不支持项应保留源码并说明限制。Windows DOM 插件与 PDF/打印仍关闭，独立 Mermaid 渲染原型不在本包中。

## 开始前

1. 使用已有的独立测试环境。安装器沿用原应用标识，可能覆盖旧安装、复用用户数据或改变文件关联；换安装路径不等于数据隔离。不要清空原插件、设置或信任记录。
2. 本小包需要 WebView2 Runtime，优先使用已具备 Runtime 的环境。缺失时按安装器原有正常流程处理；下载、权限或组织策略阻止时记为“环境阻塞”。
3. 在 PowerShell 对实际 EXE 执行 `Get-FileHash -Algorithm SHA256 .\实际文件名.exe`，与 `SHA256SUMS.txt` 核对。哈希不一致不运行；遇 SmartScreen、安全软件或权限警告，保留原文并停止反馈，不关闭防护、不绕过警告。
4. 手动安装后核对“关于”为 `2.0.0-beta.7`，记录插件实际版本和运行方式。把 `samples/basic.md` 复制到全新测试目录，命名为 `basic-A.md`、`basic-B.md`，分别将“文档身份”改为 A、B。只编辑测试副本，不打开真实工作文档。
5. 先保存两份副本，记录各自 SHA-256；后续无修改的保存、切换视图和启禁插件应保持文件字节。需要编辑的用例另复制一份，避免混淆预期变化。

## 本轮优先：拼音组合文字与逐键列表输入

1. 在测试副本的普通正文和 JavaScript 代码中，用系统中文输入法逐键输入拼音，先不选词。正在输入的拼音应可见，候选窗位于合理位置，不能只在选词后才显示汉字。用退格缩短拼音、Esc 取消、空格或数字选词，检查提交不重复、不丢字；再撤销、重做并保存重开。
2. 在有组合文字时点击菜单或另一处正文，记录系统实际提交或取消行为。输入法自行提交或取消都应保持一致，不能遗留悬空拼音、重复汉字或重置输入框导致选词中断。另检查亮色、暗色、自定义主题、Live/Source 和较大窗口化文件；每项分别记录，勿用一种模式替代另一种。
3. 在一个全新空行**逐键输入而非粘贴**：`-` → `- ` → `- [` → `- [ ` → `- [ ]` → `- [ ] `。单独 `-` 应仍可见，补空格后才显示列表圆点；输入未完成的任务前缀时仍能继续输入，补上最后空格后应显示复选框，光标位于框后的正文位置。继续输入任务文字，点复选框后 Source 中应在 `[ ]` 与 `[x]` 之间切换，撤销/重做和保存保持一致。
4. 空任务 `- [ ] ` 末尾直接按退格会退出为空行。再重新逐键输入**无尾空格**的 `- [ ]`，逐次退格，检查能退回未完成任务前缀和普通列表；空列表前缀 `- ` 按退格会退出为空行，再单独输入 `-` 核对原文显示。不能卡住、删除其他正文或跳到错误行。对 `+`、`*` 各检查单独字符与后续空格；在缩进列表、Source 和代码块中重复关键步骤，Source/代码块应保留完整原文，不出现编辑器额外生成的列表控件。
5. 仅当光标仍在正在输入的无尾空格 `- [ ]` 后，Live 会保留可继续编辑的前缀；移开光标后，已有的空任务仍可显示复选框。显示变化不能改写源文。列表输入与中文组合尚未提交时也不能提前插入或删除 Markdown。

## 本轮优先：菜单与标题栏

1. 打开样例 A，记录选区与滚动位置，再点击左上角菜单。菜单应出现在标题栏下方，文件名和最小化、最大化、关闭按钮仍可见、可用。来回切换“文件 / 插件 / 外观 / 关于”，不能出现透明遮挡或无法点击的旧面板。
2. 菜单打开时，拖动标题栏的文件名或空白区域，窗口应移动；点击菜单按钮、窗口控制按钮不应变成拖窗。双击标题栏空白区域检查最大化/还原，先保存样例再检查最小化和恢复。菜单和编辑区应跟随新的窗口尺寸。
3. 快速连续点击菜单开关，观察打开、关闭动画；最终状态应符合最后一次点击。关闭后编辑器可立即正常点击、选择文字，不能留下透明遮挡；关闭动画期间不能误点到下面的正文并改变选区。
4. 用 Tab/Shift+Tab 检查菜单焦点，按 Esc 关闭后继续编辑。菜单关闭期间打开文件或保存对话框，焦点应留在新对话框；旧动画完成不能把焦点抢回去。记录实际按键与结果。
5. 在约 760 像素窄窗、最大化、应用缩放 100/125/150/200% 下重复开关菜单和外观面板。记录 Windows 系统 DPI；若系统已启用减少动画，检查菜单仍能即时开关，不必改变系统设置。
6. 保存后通过菜单打开时仍可见的窗口关闭按钮退出，重开检查文档和设置。另用测试副本制造未保存修改再点关闭，确认正常出现保存处理，不把菜单开关当作丢弃修改的操作。

## 本轮优先：外观模式、CSS 与恢复默认

1. 打开“菜单 → 外观”，检查“浅色 / 深色 / 系统”三个模式卡片和样式名称。默认样式应为“系统默认主题”；浅色和深色缩略图可见，系统卡片包含亮暗两部分。分别选三个模式，编辑区、侧栏、标题栏和菜单应协调可读；系统模式按当前系统偏好显示，显式浅色/深色不能被系统偏好覆盖。
2. 先在默认样式下点击“打开当前主题文件”。应用会请求用已有的 `.css` 默认关联打开本地示例，按钮悬停提示可查看路径。记录是否真正出现编辑器窗口；没有关联、系统拒绝或仅请求成功而无窗口，分别记录原文和实际现象，不改变文件关联或绕过系统限制。
3. 默认 CSS 文件含允许的变量、选择器和范围说明。可复制它到独立测试目录再编辑；**编辑文件后需要重新导入，不会即时热加载**。也可把下方例子保存为 UTF-8 文件 `海蓝 主题 #&.css`（确认不是 `.css.txt`），再点击“导入 CSS”选它。应看到新样式名称、卡片预览和正文配色，文件名含中文、空格、`#&` 不应导致失败；导入操作不得改写原 CSS 文件。
4. 用同一文件切换浅色、深色和系统，检查下面的标题、引用、代码、表格和链接。应用缩放后在正文中点击定位、拖选、输入中文/emoji、撤销、保存重开；切 Live/Source 和 A/B 后继续检查，不能出现光标与文字错位、选择错行或内容变化。较大文档另按后面的窗口化用例记录实际模式。
5. 导入后保存样例，退出应用再打开：样式名称、当前模式和配色应保留。点击“打开当前主题文件”应对应当前选用的本地 CSS 副本，不是对原导入文件的实时链接。原文件与应用副本若需要修改，先保留副本，再显式重新导入。
6. 点击“导入 CSS”后取消文件选择，样式与模式不应改变。再将有效 CSS 复制为另一个文件，末尾加上下面的拒绝例子后导入：应明确报错，之前生效的样式、预览和文档保持原状，不能部分应用坏文件。分别记录错误原文；不要把错误提示记为成功导入。
7. 点击“恢复默认”，样式应回到“系统默认主题”，当前浅色/深色/系统选择保留。重启后再次确认默认样式；原导入 CSS 和文档不应被删除或改写。需要恢复自定义样式时重新导入先前有效文件。
8. 若存储读取、写入、并发冲突或 CSS 校验失败，应有可见错误并保留原文件；先记录样式名、当前文件路径和原文，再使用“恢复默认”或重开后导入有效副本。若按钮仍失败，停止这一用例并反馈，不删除应用数据或修改权限。默认示例被外部修改时也应保留文件并说明情况，不能悄悄覆盖。

可复制的有效例子（只保存代码块内容）：

```css
:root {
  --panel-bg: #fff4da;
  --text: #234567;
  --chrome-bg: #e7f1f7;
  --code-bg: #e4eef8;
  --code-text: #243f68;
  --link: #245ea8;
}
:root[data-theme='dark'] {
  --panel-bg: #15283b;
  --text: #d9edff;
  --chrome-bg: #102031;
  --code-bg: #203449;
  --code-text: #f0c9ff;
  --link: #96caff;
}
.milkup-editor {
  font-family: serif;
  font-size: 18px;
  line-height: 27px;
  color: var(--text);
  background: var(--panel-bg);
}
.milkup-block-heading {
  color: var(--link);
  font-weight: 800;
}
.milkup-block-code {
  color: var(--code-text);
  background: var(--code-bg);
}
```

拒绝例子：把下面一行追加到**另一个测试 CSS 副本**再导入，应拒绝整份文件；地址使用保留的无效域名，主题不应加载它。

```css
.milkup-editor {
  background: url('https://example.invalid/theme-probe');
}
```

也可分别用 `@import 'https://example.invalid/theme.css';` 或 `.milkup-editor { position: fixed; }` 检查明确拒绝；每次用新的副本，不改已成功导入的文件。

支持范围：Milkup 主题 CSS 支持应用列出的亮暗颜色变量、编辑区选择器、颜色/渐变、字体族、字重、字距、装饰、边框颜色等；字号/行高只允许编辑区根的统一设置。它不是任意网页或 Typora CSS 兼容层，不支持逐行尺寸、间距、任意布局、网络/本地资源、`url()`、`@import`、`@font-face`、脚本或 `!important`。文件上限 128 KiB，具体限制见默认示例。主题不能重排菜单或窗口控制，导入与切换样式不能改变 Markdown 内容。

## 右键菜单：宿主动作与插件项

1. 先停用提供菜单项的插件，在编辑器正文选中 `MENU_SELECTED_中文🙂`，右键打开菜单：应有复制、剪切、粘贴、全选、撤销、重做，以及“插入”入口，图标、快捷键和禁用态清楚。没有选区时复制/剪切禁用、没有历史时撤销/重做禁用是预期。
2. 分别实际执行复制、剪切、粘贴，将复制内容粘贴到独立纯文本测试文档核对。剪切后应只删除所选文字；撤销恢复、重做再次删除。再从右向左选择含中文和 emoji 的同一段重复，不能拆字或改变未选文字。
3. 系统剪贴板失败必须有明确提示，失败的剪切不能删正文，失败的粘贴不能改正文。记录右键动作与系统 Ctrl+C/X/V 各自结果；看到错误提示不等于复制或粘贴成功，也不要仅凭提示猜测是哪项 OS 权限拒绝。
4. **先点击编辑器取得焦点**，按 Shift+F10 或键盘菜单键。用上/下、Home/End 移动，右方向键打开子菜单，左方向键返回，Enter/空格执行；Esc 逐层返回/关闭，Tab 关闭并正常移出。打开、浏览或取消菜单不能改动原选区或正文。
5. 用键盘进入“插入”：检查标题 1–6 级、无序/有序/任务列表、引用、代码块、链接、图片链接、表格、分隔线。至少实际插入一个二级标题和一张表格，再撤销、重做，切 Source 检查 Markdown 和选区，保存重开核对。
6. 开启 Formatting 后重新打开菜单：插件贡献与宿主动作分开，**所有插件合计最多 3 项**，禁用项也计入；少于 3 项是正常情况。快速关闭后换选区、换 A/B 或切 Live/Source 再开，不能出现上次文档的旧动作。若操作有处理中状态，试按 Esc 取消；尚未提交的旧操作不得迟到修改新文档。

右键读取/编辑有界：选区最多 256 行，读取总量最多 65,536 个 UTF-16 单元，超长行也可能超限。收到提示时缩小选区；**全选成功不代表可以一次复制整份大文件**。

## 表格浮层：空间、选区、模式与卸载

1. 开启 Formatting，进入 A 的 `TABLE_ORIGINAL` 单元格，再移到表格前后正文：浮层应显示/隐藏，无空白占位；浮层本身不能改变编辑区高度、滚动位置或选区。选中文字后点浮层按钮，不应因按钮夺焦点而作用到别处。
2. 点击“下方加行”，确认仅当前表格增加一行；撤销、重做、保存重开核对。打开再关闭应用菜单，返回原单元格时浮层应恢复，不需要额外点击正文才能出现。
3. 在同一单元格切 Source → Live → Source，随后再操作表格：工具条应对应当前模式和单元格，不能用旧按钮执行或被迟到的空结果清掉。切换视图本身不得改写源文。
4. A 表格打开浮层后切到 B 的普通正文，旧浮层应撤下；B 表格的操作只能改 B。返回 A 检查原文、选区和保存状态，没有迟到操作误改另一份文件。
5. 保留当前文档，去插件页停用 Formatting：返回后浮层和插件菜单项应清除，宿主基础菜单仍可用。重新开启检查当前表格；最后用“更多”卸载 Formatting，确认输出撤下、重启后仍卸载。**返回编辑器点击取得焦点后**再用 Shift+F10 检查宿主菜单。仅需恢复时从本包 `plugins` 导入对应归档并显式开启，记录为手动导入。
6. 在浅色/深色、宽窗/约 760 像素窄窗、应用缩放 100/125/150/200% 下抽查菜单和浮层。浮层可横向滚动，但应留在可操作区域，活动单元格可见；Windows 系统 DPI 另记，不能用应用缩放代替。

## 保留回归：卡片、隐藏围栏与保存字节

1. 插件列表滚动到中间，用鼠标和 Tab/空格启禁 Diagrams、Formatting。卡片前后顺序、列表滚动和焦点应稳定；快速点击有明确状态，不误点另一张卡片。若有旧随包插件升级提示，记录开关前后的版本与来源，不能以清空用户数据替代升级。
2. 样例代码块在 Live 中隐藏开闭围栏、保留正文；Source 中围栏和语言标记完整。切换语言后撤销/重做，只改语言，不改 `COPY_BODY_中文🙂`、空行或文件尾。另在代码内用真实中文 IME 输入、撤销、保存重开。
3. 从 `COPY_BEFORE` 行首选到 `COPY_AFTER` 行尾，实际复制到纯文本目标，应包含隐藏的开闭围栏。菜单取消、插件启禁、Live/Source 往返后不编辑直接保存，重新计算 SHA-256，应与该副本操作前一致。
4. 在测试副本上分别检查 LF 与 CRLF。可用已有可信文本编辑器将另一副本保存为 UTF-8/CRLF，关闭该编辑器后先记基准哈希，再用 milkup 打开、无修改保存及编辑后撤销保存，核对字节；记录换行和编码，不能拿两种换行文件互比哈希。
5. 开启受限 Worker Diagrams，检查样例流程图/时序图的块外预览、块内源码编辑以及原文保存；停用后显示完整源码。`gantt` 应提示不支持并保留原文，不得空白替代或生成假图。
6. 可选复制 `samples/larger.md`：记录是否实际进入窗口化模式，测试全选、首尾小段编辑、撤销和保存重开。要复查窗口化表格时，可在副本末尾加入样例小表格并先保存。不要要求右键一次复制整个较大文件。

按 `FEEDBACK.md` 分别记录“通过 / 失败 / 未测 / 环境阻塞”。发现丢字或保存损坏时停止编辑该副本，保留最后保存时间、最短步骤、原始错误和仅含测试内容的截图。此包不代表正式发行、真实更新/自动回滚验收或完整 Mermaid 支持。
