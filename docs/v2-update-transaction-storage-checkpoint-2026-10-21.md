## 实际生命周期和存储合同

一笔事务包含内部 transaction ID、原/目标版本、安装器摘要、schema、revision 和时间元数据。记录上限 4 KiB，拒绝未知字段、非规范版本、非升级版本、不合法摘要和阶段/revision 组合。时间仅是元数据，不替代签名有效期或其他授权检查。事务 ID 也不是凭证；此记录不是签名日志或最高版本水位的替代品。

| 当前状态                   | 内部操作             | 新状态                                |
| -------------------------- | -------------------- | ------------------------------------- |
| Prepared                   | 提交前取消           | Cancelled                             |
| Prepared                   | 准备交接             | HandoffPending                        |
| HandoffPending             | 观察到启动请求被接受 | AwaitingCompletion                    |
| HandoffPending             | 观察到明确启动拒绝   | LaunchRejected                        |
| Cancelled / LaunchRejected | 重试                 | Prepared，保留同一意图并增加 revision |
| 任一未完成状态             | 要求核对或重新打开   | NeedsReview                           |

所有状态的 verification 都只能是 **Unverified**。没有安装完成、健康确认或回滚事件；`HealthConfirmed` 等伪造 JSON 阶段和额外 `verified` 字段被拒绝。接受启动请求不等于安装完成。取消只允许在交接前；进入 NeedsReview 后不能自动重试或恢复。这里的 Retry 仅改变观测记录，未来安装调用仍必须重新经过现有保存、签名、有效期、水位和候选门禁，本模块不授予安装权限。

存储由宿主未来提供的、已有私有父目录下的**全新专属目录**承载。本轮没有选择产品目录或调用 create。目录内使用 `transaction.lock`、`transaction.json` 和同目录唯一暂存文件：

1. `create` 使用独占新建目录；即使已有目录为空，也拒绝重用。Unix 新建模式为 0700，文件沿用现有 0600 规则。初始化失败留下的目录保留，不能清空后假装创建成功。
2. `Store` 在整个句柄生命周期持有现有 fs2 的 OS 独占锁。另一个进程打开同一事务得到 Busy；Drop 或进程终止后由 OS 释放锁。持锁期间所有变更重新读取规范记录，并比较 transaction 与 revision，旧结果不能覆盖新状态。
3. 新状态先写到同目录 `create_new` 暂存文件，写完并 `sync_all`，关闭后调用已有 `replace_file_atomically`。Unix 为 rename 后同步目录；初始化还同步父目录。Windows 沿用已有 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`，候选文件单独 `sync_all`；本轮没有 Windows 目录或断电耐久性实测。
4. 一旦开始持久写入就保守设置“结果需重读”。任何写入/替换/同步错误都返回 ReloadRequired，阻止继续 apply；必须通过 snapshot 重新读取、校验并同步规范记录及目录，才解除限制。失败可能发生在替换已经完成之后，不能凭错误码认定旧 revision 仍有效。重读失败不解除限制。
5. 打开已有事务先取得锁、校验并同步记录，再将 Prepared / HandoffPending / AwaitingCompletion 持久转为 NeedsReview，增加 revision。已终止或已待核对状态重开不改字节。墙钟倒退不阻止重开核对，普通事件仍拒绝时间倒退。
6. 缺失、损坏、未知 schema 或超限记录原地保留，不重建、不截断、不选择孤立暂存文件作为恢复依据。提交失败只尝试清理本次确实独占创建的暂存文件；名称冲突的别人的文件不能删除。进程中断遗留文件保持原样，后续不自动晋升。

首次创建失败若尚无规范记录，无法恢复一个从未确认提交的事务；同一目录再次 create/open 均拒绝。未来协调器只有在明确重新授权并选择新的专属目录后才能开始另一笔事务，旧目录保留待核对。本模块没有提供自动删除、证据归档或批量保留策略。

## 复用原语和保护边界

未新增依赖。复用现有 fs2、serde/serde_json、semver、标准文件 API 及主模块中的原子替换函数。`update_policy.rs` 只提取原目录校验与文件打开逻辑为 updates 内部可见帮助函数：原信任 Store 的调用顺序、打开方式和检查条件保持一致。新增 `open_regular_for_sync` 允许写权限同步但**不创建缺失文件**，避免 Windows FlushFileBuffers 所需写句柄导致意外重建记录。

原有根目录/叶文件符号链接检查、Windows reparse 检查、Unix hardlink 检查沿用。与原信任存储相同，能任意替换父目录或回退整个目录的本机账户所有者不在该保证内；此实现不能凭本地 JSON 防止账户所有者篡改。宿主未来必须提供可信私有父目录；目前没有设置新的 Windows ACL 或新增系统权限。

生产安装函数、外层 PE 校验、vendor updater、NSIS、发行清单和签名协议、插件 SDK/实现、保存确认、依赖/锁文件和 CI 配置均未改。既有最高版本水位不会被此模块读取、重置或降低。信任记录损坏后的恢复仍维持前一检查点的架构阻塞。
