### B 的具体边界与阶段

当前 `output_linux.rs::render` 用 `current_exe` 启动内部输出helper，`start_print` 使用GTK纸张设置与 `WebKitPrintOperation`，打印及PDF共用这一引擎路径。产品没有可直接装入不同WebKit的已验证接口；同一进程已经加载系统WebKit后不能靠改环境变量切库。

1. 首选将**已有静态输出helper**作为独立构建目标复用现有实现、协议与guard，而非增加第二套排版引擎。主编辑器保持系统WebKit；helper从包内固定绝对路径启动，在进程加载前绑定匹配的私有WebKit/JSC、WebProcess等必要组件。安装位置与loader路径需显式设计，所有DSO/子进程都校验，不能假设一个RUNPATH自动递归覆盖所有依赖。用户可写目录、任意环境指定prefix和系统fallback不能成为生产选择规则。
2. 原guardian/PID出生身份、CLOEXEC管道、有限输入、临时目标、完成后原子提交、异常取消/父退出回收全部复用；注入bundle guard必须与该WebKit ABI匹配。保留无脚本/无网络静态CSP、仅受控资源、bubblewrap默认沙箱与普通账户打印对话框。主进程不得通过全局LD_LIBRARY_PATH污染插件/其他输出。没有这些证据不能接受“隔离成功”。
3. 用确定的版本目录和运行时manifest绑定应用/helper/全部库及资源。新旧版本不能混用，更新中断不留下半套运行时；已有任务持有旧实例，新任务切到完整新版本需有明确生命周期。deb包管理事务及应用安装器路径分别实测，不私下自更新运行时。
4. 安全发布流程须有负责人、公告监测与有界修复响应、补丁重基线、来源/哈希/许可证清单、干净重建、负例和原生回归、可撤回候选。回退只能到仍受支持且未撤销的完整兼容版本，不回滚到已知不安全引擎；没有验证的自动回滚继续标未实现。正式签名/端点等待所有者授权，本轮不配置。
5. 验收安装包在受支持普通用户环境**无需手装库**打开原功能，主进程/system与输出/private的实际映射分别符合manifest，运行时更新/卸载不损坏系统库或文档。离线安装包括自身必需组件并验证系统先决条件；不能把包内存在等同缺依赖离线可装。

## 4. A4 标题孤行：先证明布局机制，停止 CSS 猜测

原型caption和CSS断页链已经反证，保留原样，不重复。新源码线索是2.52.6及2.54.2的 `RenderBlockFlow::applyBeforeBreak/applyAfterBreak` 只直接检测强制断页；`breakInside:avoid` 则进入整个child的unsplittable判断，超页高时不整体搬移。**这支持调查跨相邻块的keep-with-next缺口，但尚未证明它是唯一原因**，其他布局/页框路径仍可能参与。不能简单加 `avoid` 就宣布修复。

下一次允许动引擎前，判别方案必须同时回答：

- 在同一最终打印布局中记录标题、table/thead/首数据行的真实逻辑位置/高、折叠margin、页面剩余高、pagination strut、实际break值与递归重排次数；记录采用的布局分支。独立PDF坐标用于核对结果，不能从待修输出倒推“期望布局”。沿用原包已校准的12mm、1024×768、loaded/guard-ready与字体，不重新试调行数。
- 若避免断页约束未被考虑，最小修复应在布局阶段把有限的标题+表头+首数据行约束移到可容纳页；不能把整个长表设不可分、复制标题/首行、固定页坐标或造空白页。若已考虑而表格重新布局丢失strut，应修复传播/收敛，而非重复在父节点加CSS。两者是不同分支，先观察再选。
- 保留临界长表/临界短表/宽松短表/多页长表基线，同时覆盖宽窄、字体回退、跨页首行、超过整页的单元格和强制断页优先级。标题、表头与首行的既定同页条件、重复表头、行顺序/完整/无裁剪、页面方向均不降；超高不可满足组合须明确终止/合理分页规则，不能循环或吞内容。不是为“绿色”改合同。
- 先源码/翻译单元预检及可判别小布局门禁，只有确实区分上述分支、有资源预算和缓存来源、无同类运行时才考虑一次有限原生验证。当前没有布局跟踪结果，所以**未写分页修补、未派发构建**。
