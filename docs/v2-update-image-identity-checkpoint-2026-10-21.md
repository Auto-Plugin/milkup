# 更新应用身份：签名绑定与只读观测检查点（2026-10-21）

从 `bdfea1171a85b81f59c499d98601a2d0873b5e8a` 在独立分支 `dot/milkup-v2-update-health-contract` 继续。**交付正常编译的内部身份验证模块；没有安装、健康确认或外部消息入口。** 新模块 `update_identity.rs` 的生产入口只能观察当前进程映像，不能由调用者传入路径、hash、version 或“完成”消息。结果类型字段私有，仅提供读取方法，不提供反序列化或变成健康状态的方法。

## 先核对的实际结构和兼容选择

现有 vendor updater 的外层签名 statement 严格要求 schema 1、固定 product/channel；验签后保存完整 release，`verified_release()` 只有在版本、URL、包签名、target 和 raw_json 均仍匹配时才返回。平台项原来只有 URL/包签名；NSIS 钩子仍只处理文档图标注册表项，既有安装调用仍依赖 ShellExecuteW 启动，没有可信完成回执。前一检查点已经确认外层安装器版本资源不等于内嵌应用版本。

本轮选择独立版本化的 `platforms[selection].application` schema 1，完整字段与迁移规则见[清单合同](./v2-update-manifest-protocol.md)。保留原 envelope 与 vendor 代码，不新增依赖或通用 SDK API。扩展在原有签名的 release 内，因此原清单签名、完整 release 摘要、同序号冲突与防回放门禁覆盖它。旧清单不包含新证明；新扩展缺字段/未知 schema 时身份验证失败，不能回退到旧证明。

应用版本、基础平台、应用 SHA-256、精确字节数和安装器 SHA-256 同时绑定。平台项须由已认证 URL/包签名唯一定位；多个项复用同一组合时拒绝身份验证，避免从某个平台挑出另一个平台的应用声明。原下载流程仍沿用原选择规则，没有因此修改运行行为。兼容成本是发行方将来必须对最终应用/安装器字节分别计算摘要，并用新 sequence 签发扩展；当前没有改动真实发行流水线。

## 正常编译的验证路径

1. 只接受现有验签器返回的 Update，从完整已认证 release 解析严格 application 声明，核对宿主平台与选中项。固定宿主配置/验签根依然由原更新层负责，本模块不接收公钥或网络端点。
2. 从持有 OS 独占租约的事务 Store 读取记录，匹配期望 transaction/revision、版本和安装器摘要；只允许已提交启动或待核对阶段取得观测结果。不是给 Prepared/Cancelled 阶段授权安装。
3. 新增 `policy::Store::authorize_existing`：只打开已有目录、锁和状态文件，取得共享 OS 文件锁后复用原 authorize 的策略检查。缺失时不创建目录/文件，损坏时不修复。原安装 authorize 仍保留原调用行为，两个入口共用相同门禁函数。
4. Linux 直接打开内核 `/proc/self/exe`，用固定 64 KiB 缓冲流式计算 SHA-256。普通文件大小限定 1 至 256 MiB，前后检查 descriptor 的 dev/inode/长度/mtime/ctime，变化或读失败即拒绝。版本来自编译期应用版本，平台来自宿主构建，进程来自当前 PID，均没有外部覆盖参数。
5. 比较完整版本、平台、摘要、长度与当前进程；读取完成后再次检查有效期、防回放和事务绑定，再返回一次 ImageMatch。返回内容绑定 transaction/revision、已签名 release 摘要和实际观测；没有序列化的可转交凭证、持久健康结果或安装授权。正常有效声明可以重复读取，签名续期可正常重试。

成功匹配依然保留事务 **Unverified**。它只证明本次读取的指定映像与已接受的签名声明一致，不证明该安装器曾运行、安装已经完成、完整载荷一致或应用运行健康。验证结果是瞬时观察；未来在异步使用或持久提交时必须重新检查事务及当前授权，不能缓存为永久授权。

## 运行映像获取边界

[Linux proc_pid_exe 文档](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html)说明直接打开该链接会打开进程执行映像；这里不把 readlink 返回的名字再次当路径打开。真实文件测试也验证：打开 descriptor 后重命名/替换原路径，读取仍对应原文件。该保证依赖可信内核/procfs 和未遭控制的当前进程，不是远程证明，不抵御恶意进程内代码、特权篡改或整个 OS 账户/环境被控制。

**Windows/macOS 当前观测明确阻塞并返回错误。** 现有路径 API 没有在本轮提供与已加载映像绑定的只读文件句柄。[Rust current_exe 文档](https://doc.rust-lang.org/std/env/fn.current_exe.html)明确列出路径与替换风险；[Microsoft GetModuleFileName](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulefilenamea)返回的是模块路径。因此没有以“查路径、再打开、再 hash”替代运行映像证明，也没有为此新增权限、Native API 依赖或安装布局。平台无关的签名/事务验证代码已编译；不能将 Linux 成果声称为 Windows 运行映像验收。
