# 第十六阶段：视觉与键盘可访问性

从本地、fetch 后远端一致的 `dffdcbeb848f43629e42863d95213a47199c51dd` 接续，仍在 `dot/milkup-v2-quality`。本阶段只生成本地 Linux release，未发布、合并远端 v2、强推、调整权限或安全设置。未切换模型或委派子模型；工具不能独立证明模型服务端档位。

## 设计原则

1. 正文优先：标题、正文、代码和表格的层级清楚，辅助信息不抢占阅读空间。
2. 间距一致：同层级控件使用一致的留白、对齐和焦点标记，窄窗保留实际编辑区域。
3. 整界面可读：菜单、状态栏、对话框和正文一起检查，正文单独变大不能替代 UI 缩放。
4. 键盘可达：保留正文 Tab 编辑语义，同时提供操作区域间导航；模态焦点受约束，关闭后恢复。
5. 状态可理解：加载不闪烁，错误保留原文并给出可达的关闭或恢复操作；语义与实际行为一致。

这些原则用于本轮有界修复，不引入 Typora 专有素材或扩展一套未经验证的主题系统。

## 历史问题核对

本轮直接读取 GitHub 原始 issue，未关闭或修改 issue：

- [#232：最小宽度与分屏留白](https://github.com/Auto-Plugin/milkup/issues/232)。原诉求包括允许更窄窗口及减少两侧留白，并不只是避免整页空白。当前 Tauri 最小尺寸仍为 **760×520**；本轮验证该尺寸下正文、搜索及大纲可用，不能据此宣称取消最小宽度诉求已完成。
- [#240：高分辨率界面缩放](https://github.com/Auto-Plugin/milkup/issues/240)。当前外观页没有缩放实现，Ctrl+Plus 在生产 WebKit 中未改变 viewport 或 devicePixelRatio。仍未完成。
- [#243：source 切换残留行内代码样式](https://github.com/Auto-Plugin/milkup/issues/243)。普通／窗口化文档各反复 source/live 三轮，检查实际 computed background/border 和系统截图；当前 Linux 样本未复现。不能外推 Windows/macOS。

## 修复与失败证据

- 菜单声明 `aria-modal=true`，原实现 Tab/Shift+Tab 会离开菜单。现在背景 inert，焦点只遍历可见、可用的菜单控件；WebKit 的 `code=Tab` / `key=Unidentified` 路径同样处理。Escape 优先关闭最上层菜单，保留背景搜索；菜单中的文档快捷键先关闭菜单，再进入未保存保护。
- 原关闭菜单／侧栏／打开失败处理只使用普通 view 的输入框，窗口化长文可能把焦点留在隐藏菜单按钮。统一通过当前编辑视图恢复；打开错误优先聚焦关闭按钮，Escape 可关闭错误遮罩。
- 新增 F6 / Shift+F6 顺序移动到菜单、搜索、侧栏、正文、表格操作和状态栏中的可用区域。正文 Tab 仍负责缩进／表格导航。已有快捷键页面补入这些操作的说明。
- 壳控件添加统一焦点轮廓，正文输入焦点有内侧边框；辅助文字由 `#8993a3` 调整为 `#647083`。输入代理不再同时 `tabindex=0` 且 `aria-hidden=true`，并有名称；菜单分类使用适合按钮的 `aria-current`，菜单触发器声明 dialog。
- 等效 **380×260** 区域下，原未保存对话框底部为 275.53 px，超出可见区。现在对话框限制高度并允许内部滚动，键盘到达保存按钮时能滚入可见范围。失败提示保留 alert，加载详情增加 status，编辑区域报告 busy。
- 外观页明确当前浅色支持边界，避免空白页面让用户误以为内容加载失败。未把占位说明当成暗色或缩放功能。

`browser-before.log` 保留菜单约束失败；`compact-dialog-before.log` 保留打开错误焦点和小视口对话框失败。后续聚焦回归通过。首轮原生视觉脚本的两次失败分别来自 XTest 发出 Escape 后立即断言，以及直接读取多行 DOM `textContent` 未补行分隔；对应截图／日志保留。修正观察时序和读取方式后通过，没有增加超时或缩小性能夹具。首轮全仓单元测试还保留了旧的 `aria-hidden=true` 合同；已将它改为验证可聚焦代理有名称且不被隐藏，未删除测试。

## 验证边界与真实 IME 最小外部需求

本阶段不重复安装 IBus。此前输入法软件已装入隔离目录，但真实候选会话未打通；不是“未安装”，也不把 Unicode key actions、中文剪贴板或 synthetic composition 记为 IME。

最小外部验收需要一台稳定 Linux 桌面会话，IBus/libpinyin 或等效中文输入法已能在原生文本框正常显示候选；使用同一源码构建，在普通／窗口化、source/live 四个组合中实测：预编辑、候选选择提交、Esc 取消、中文标点、选区替换、切换菜单／搜索失焦、撤销重做、保存重开。交付候选窗口截图或录屏、按键记录、预期与实际源文本、保存文件 SHA-256。随后在 Windows/macOS 各自真实输入法重做对应矩阵。

**没有做屏幕阅读器验收。** 输入代理有名称只解决明显的焦点隐藏语义冲突；完整文档阅读、光标与选区通告、虚拟行和表格语义、插件控件的范围属性及 Orca/NVDA/VoiceOver 仍需专门设计与实测。
