# 当前分支外部最小验收脚本与平台清单

这些项目均未由本云环境验收。历史 Windows 报告、安装过 IBus、Unicode WebDriver 输入、剪贴板或合成 composition 事件不能替代本次真实 IME。当前 IBus 候选会话已有明确阻塞，不再在同环境重复尝试。

## 准备与身份

在有真实桌面与输入法的 Linux、Windows、macOS 分别 checkout 本次专用分支的最终 SHA。记录 `git rev-parse HEAD`、`git status --porcelain`、生产二进制 SHA-256、OS/WebView 版本、IME 名称及版本、键盘布局、缩放与屏幕尺寸。用本地生产构建，不用 Vite。Windows 的版本需包含 WebView2 与 Word 2016 完整 build；macOS 记录系统构建号与系统中文输入法。

在仓库运行（Node 可跨平台）：

```sh
node scripts/prepare-v2-external-acceptance.mjs prepare <一个不存在的新目录>
```

生成普通、175 KiB 窗口化 JS、1 MiB 原生窗口化文件各 source/live 两份，以及只标记 pending 的清单。生成器拒绝覆盖已有目录，不启动应用、不注入文字、不认定验收通过。用生产应用逐个打开文件，核对实际后端和视图；应用升级改变阈值时以实际诊断为准，不只相信文件名。

## 真实 IME 最小闭环

每份文件独立进行并连续录屏，保留候选窗、预编辑正文、光标和撤销结果。Windows/Linux 文档首用 Ctrl+Home；macOS 同时验证平台实际首尾快捷键（包含 Cmd+Up/Down），不要用脚本移动光标替代平台行为。

1. 激活系统中文 IME，输入 `zhongwen`，观察真实候选窗与预编辑。按 Esc 取消：正文、dirty 和历史不应增加一次提交，保存字节应仍等于清单 originalSha256。
2. 在文档第一字符前通过候选提交“中文候选”（可分词候选，记录实际提交次数）。观察没有重复文字、丢字或光标跨 emoji 错位。撤销必须按实际提交边界回退，重做回到准确前缀；不能预设多个候选提交必须合并为一次撤销。
3. 保存、关闭、重开，正文应为“中文候选”加原有完整文件。运行下面命令核对全部文件字节，包括 CRLF、emoji 和文件尾：

```sh
node scripts/prepare-v2-external-acceptance.mjs verify <目录> <例如windowed-native-live>
```

4. 另开新夹具检查选区替换、方向选区、候选期间方向键、失焦到搜索/菜单后取消或提交、列表/代码/表格单元内组合输入、跨窗口边界的预编辑与连续输入。每个动作记录期望全文及实际保存 SHA-256，撤销/重做后再次比较。遇到错误保存录屏与原文件，不继续覆盖唯一异常样本。

字节脚本即使成功仍输出 `imeAccepted:false`：它只验证指定最终字节，候选、取消、方向选区、失焦、历史和平台输入必须由录屏及操作记录证明。六份结果各填 pass/fail/blocked；缺一项不能合并成“真实 IME 已通过”。
