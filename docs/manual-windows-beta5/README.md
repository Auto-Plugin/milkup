# milkup 2.0.0-beta.5 Windows 手测试用

这是未签名的 Windows x64 测试包，不是正式发行。精确源码、版本、安装器 SHA-256 和随包插件以 `manifest.json`、`plugins.json`、`SHA256SUMS.txt` 为准。以下是待执行的验收步骤，不是通过报告；构建检查没有执行安装器，Linux 或浏览器结果不能代替 Windows GUI、中文输入法、系统 DPI 或旧安装升级验收。

## 开始前

1. 使用已有的独立测试环境。安装器沿用原应用标识，可能覆盖旧安装、复用设置和插件、改变 Markdown 文件关联；换安装路径不能保证用户数据隔离。保留现有测试数据与设置，不清空插件目录或信任记录。
2. 小包不含完整 WebView2 Runtime，优先使用已有 WebView2 的环境。缺失时保留原默认下载模式；下载或策略阻止请记录为环境阻塞。
3. 解压 Actions artifact，在 PowerShell 对实际 EXE 执行 `Get-FileHash -Algorithm SHA256 .\实际文件名.exe`，核对 `SHA256SUMS.txt`。不运行哈希不一致的文件。
4. 如遇 SmartScreen、安全软件、权限或组织策略警告，记录原文后停止反馈，不要关闭防护或绕过警告。
5. 由你手动安装。把 `samples/basic.md` 复制到全新测试目录，命名为 `basic-A.md`、`basic-B.md`。将两份的“文档身份”分别改成 A、B 并保存，只编辑副本，不用真实工作文档。
6. 在“关于”记录应用版本，在插件详情记录当前版本和可用版本。本包预期是 **Diagrams 1.2.0 / Worker、Formatting 1.0.1 / Worker**，以 `plugins.json` 核对实际归档。

## 已有随包旧插件：显式开关升级

这一项需要保留旧安装和用户数据的测试环境；没有旧版本时填“未测”，不要把首次安装记成升级通过。

| 原有随包版本              | 本包提供的版本            | 应核对的变化                                                   |
| ------------------------- | ------------------------- | -------------------------------------------------------------- |
| Diagrams 1.1.1 / DOM      | Diagrams 1.2.0 / Worker   | 卡片提示随应用新版与运行方式变化，升级后核对受限流程图、时序图 |
| Formatting 1.0.0 / Worker | Formatting 1.0.1 / Worker | 卡片提示随应用新版，升级后核对表格工具条与跨文档保护           |

1. 安装前记录旧版本、启用状态及已有测试设置；安装 beta.5 后、操作开关前，再记录当前版本与“随应用新版”提示。不要通过删除用户数据获得新版本。
2. 新版在下一次开启卡片开关时应用：原来已开启的先关闭，再开启；原来关闭的直接开启。无需重启应用，也无需进入详情进行另一次批准。
3. 操作完成后核对实际版本、启用状态、诊断和原有设置。失败须保留现场，记录失败前后版本；不要据此声称已验证自动回滚。
4. 此入口只针对上述已识别的随包旧来源。用户手动安装、来源不同或已有待升级包时，先记录卡片状态，不要求覆盖或删除。需要测试手动导入时，仅从本 ZIP 的 `plugins` 选择对应归档，再显式开启，并在反馈中标为“手动导入”，不能替代旧随包升级用例。

## Mermaid：已有文档即时启禁与编辑焦点

以下步骤先对“beta.5 流程图”执行，再对“beta.5 时序图”完整重复。使用同一份一直打开的 `basic-A.md`，记录当时是实时视图（Live）还是源码视图（Source）。

1. 关闭 Diagrams，打开样本的 Live 视图，点击图表前的“块外焦点”正文。进入插件页开启 Diagrams，再关闭插件页回到同一文档：应立即显示图形，无需重开文件、切换视图或重启应用。
2. 再进入插件页关闭 Diagrams，回到同一文档：图形应立即撤下并显示块内源码，文字应完整。重新开启后应恢复图形。
3. 开启状态下进入图表块内编辑，将“开始”改为“起点”或将“保存副本”改为“保存测试副本”。编辑器有焦点且光标/选区位于块内时，应保留源码以便编辑，不应把光标换成图形或丢字。
4. 点击图表前后的“块外焦点”正文：应更新为修改后的预览。另做一次块内编辑后直接打开插件页，让编辑器失焦；不移动原文中的折叠光标，关闭再开启 Diagrams 并返回：已有文档应显示预览。记录焦点所在控件，不能仅凭源码中的光标位置判断是否失败。
5. 以键盘移到块首、块尾及相邻正文，检查选区、光标和预览切换；撤销修改，切 Source 核对语言标记、开闭围栏与正文完整，切回 Live 再检查。Source 中显示完整源码属于预期。
6. 查看“不支持语法”中的 `gantt`：应显示不支持说明并保留源码，不能出现空白替代、崩溃或假图形。关闭 Diagrams 后相关图形/诊断应撤下。

Windows 归档使用受限 Worker，仅覆盖支持的 flowchart / sequence 语法，不代表完整 Mermaid。独立 DOM 插件与 PDF/打印安全门禁仍关闭；不需要新增 Runtime 或更改系统安全设置。Linux 的完整 Mermaid 归档保持独立。

## 插件卡片：顺序、滚动与焦点

1. 插件列表滚动到中间，记下目标卡片前后各一张卡片和滚动位置。在卡片上启禁 Diagrams、Formatting：原有卡片顺序应稳定，列表不跳顶，开关不移动到鼠标下的另一张卡片。
2. 用 Tab 聚焦目标开关并按空格，检查焦点仍在该入口，后续 Tab 顺序合理。快速重复点击应有明确的处理中状态，结束后状态一致；失败应可见且能重试。
3. 查看某插件详情时，观察其他插件的后台状态更新；当前详情、滚动和焦点不应被切换或抢走。详情没有批准、拒绝或启禁按钮。
4. 点击卡片上的面板/命令图标本身，关闭弹窗后应回到入口。停用插件的“更多”不应提供重载。升级期间也重复检查卡片位置。

## 普通代码：隐藏围栏、源文与输入

1. 查看“beta.5 普通代码”与“长代码行”：Live 应显示代码正文和语言选择器，开闭围栏不应作为可见代码行或留下多余尾部空行。Source 应显示完整围栏、语言标记和正文；切换视图不得修改文档。
2. 把 JavaScript 改成 Python，再撤销、重做。只应改变语言标记，`COPY_BODY_中文🙂` 等正文与空行保持不变。切 Source 修改语言后再回 Live，选择器应一致。
3. 在代码正文选择 `COPY_BODY_中文🙂`，实际按 Ctrl+C，粘贴到单独的纯文本测试文档核对。再从 `COPY_BEFORE` 行首选到 `COPY_AFTER` 行尾，Ctrl+C 后粘贴到纯文本目标：应包含这一范围的完整 Markdown，包括 Live 隐藏的开闭围栏。记录实际粘贴结果，不能用截图代替复制验收。
4. 在代码内用真实 Windows 中文 IME 输入“代码输入测试🙂”，完成组合后撤销、重做并保存重开。检查候选窗口、组合文字、emoji、选区及撤销边界，不应丢字或重复提交。
5. 用上下方向键跨代码块、空代码块及文件尾代码块，用 Home/End 到长行边缘，检查光标可见且不滞留在隐藏围栏；再到 Source 核对完整原文。未闭合代码块可在副本中另测，不能被错误隐藏。

## Formatting 1.0.1：表格上下文与跨文档

1. 确认 Formatting 实际为 1.0.1 且开启。在 `basic-A.md` 点击“表格前正文”，表格工具条应隐藏且无空白占位；进入表格单元格后显示可用操作，停留几秒应保持稳定，不反复闪烁或推动正文跳动。点击“表格后正文”离开表格，再确认隐藏。
2. 在 A 的单元格执行“下方加行”，核对只增加一行且只改 A；撤销恢复原表，重做后再次核对。清空/对齐等操作必须对应当前单元格。
3. 在 A 的表格激活工具条或打开格式弹窗，然后切到 B 的普通正文。A 的工具条/过期状态应撤下，不应把 A 的操作应用到 B；若旧入口短暂可见，点击后不得改动任一文档。核对两个“文档身份”、表格内容和保存状态。
4. 再进入 B 的表格执行“下方加行”，确认只改 B；切回 A 检查未被改变。快速切 A/B、离开单元格后重复观察，不应出现迟到的旧工具条。
5. 在表格内打开工具条后到插件页关闭 Formatting：返回文档时工具条和占位应清除，旧按钮不能继续改文档；再次开启后只反映当前文档/选区。

## 其余回归与交付边界

1. 在普通正文输入中文与 emoji，点击任务 checkbox，切 Source 核对 `[ ]` / `[x]`；撤销、重做、保存、退出、重开核对磁盘文字。
2. 检查粗斜体、长表格单元格、工作区恢复上次测试文件夹、大纲导航及多侧栏分隔条拖动；失效目录应能重新选择，不能循环弹窗。
3. 浅色/深色、宽窗/约 760×520 窄窗、应用缩放 100/125/150/200% 分别复查卡片、代码、图表、表格工具条的控件、选区与焦点。Windows 系统 DPI 单独记录。
4. 可选打开 `samples/larger.md` 副本，修改首尾标记并保存重开；记录实际渲染模式。恢复记录是异常退出后的本地草稿保护，不等于原文件已保存；恢复生成独立副本。
5. 菜单→关于，版本旁检查更新：当前正式签名渠道未配置，应明确提示，不能误报“已是最新”或亮红点。插件列表不再运行旧 Updates，旧目录和数据保留；不要为本轮试用清空它们。

真实更新安装、健康确认、自动回滚、损坏信任恢复未验收；本包不含 debug/health 实验。本轮交付仅限 `Auto-Plugin/milkup` Actions 测试 artifact，不是 Release 或 main 合并。未签名提示、WebView2 前置、Windows GUI/IME/DPI 及旧安装升级仍须真实手测；复杂图表布局、辅助技术和断电恢复不能由本样本代替验证。
