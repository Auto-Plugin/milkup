# P8 发行工程门槛

本清单从已接受的 P7 检查点 `a4d44e680478d7894450f30f3d533dc1c3131974` 开始，工作分支为 `dot/milkup-v2-product-phase8-readiness`。依据[八阶段总计划](v2-product-completion-plan.md)、[原计划历史](v2-product-completion-plan-history-2026-10-15.md)中的旧 P2 安装升级与共同验收要求。历史旧 P8 是现 P4 Markdown，不是本轮发行阶段。

本轮是发行前工程准备。授权范围为代码、测试、现有 CI 的测试/编译、工作分支提交推送；不生成安装器，不上传 artifact，不下载 WebView2，不新增运行依赖、费用、签名密钥或凭据，不合并、部署、Release 或升稳定版本。历史已消费请求保持关闭。编译成功不构成安装、交互或发行通过。

## 先行审计与执行顺序

1. Windows 检出必须保留独立插件已审查的精确输入字节，修复冻结闭包在 CRLF 检出及 Windows 路径分隔符下的实际兼容问题，不放宽哈希或路径校验。
2. 在现有工作流增加隔离的完整桌面与公开 SDK 插件测试/编译路径。历史标准包的 validation-only 仍执行 NSIS，不能用于本轮；离线请求也不得重新启用。
3. 修复更新取消后迟到下载结果重新发布的竞态，保持同一 release 重试合同；加强非法 SemVer 和 Cargo.lock 漂移门禁；为现有 updater 2.10.1 作限定的启动失败恢复补丁。版本保留 `2.0.0-beta.1`。
4. 按以下单项门槛记录实现、失败和实机证据；工程检查点不自动关闭产品功能缺口。
