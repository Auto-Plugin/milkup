# P4 编辑与资源阶段记录（2026-10-15）

本记录描述独立格式与图片插件、公开编辑/资源能力及另存为资源保护的实现边界。它不是 P4 全部产品能力已经完成的声明。公式、图表/流程图、脚注等能力仍属后续工作；本轮使用独立分支 `dot/milkup-v2-product-phase4-editing-resources`，精确基线 `516577020a275fb1fca2ead9b0882e18b2582c09`。

## 插件与宿主分工

`plugins/images` 是独立 Worker 插件，ID 为 `milkup.images`，通过公开 `@milkup/plugin-sdk` 0.3.2 使用宿主能力。不导入 Tauri、宿主源码或私有 Milkup 包。权限显式声明 `document:read`、`document:write`、`images:import`，安装与批准权限是不同步骤；敏感能力需用户批准。

插件负责图片导入流程、替代文本与 Markdown 构造、资源目录策略、受控 UI、状态、错误及取消。通用 modal ID 为 `images-panel`，命令为 `images.choose`、`images.paste`、`images.change`、`images.cancel`。卡片使用随包分发的 PNG 图标。

宿主负责真实选择器/剪贴板事件、临时能力句柄、文件与图片格式验证、受约束目录派生、资源持久写入、文档版本检查及保存协调。插件不取得任意磁盘路径、文件字节、原生 IPC 或网络能力。`pasteHandlers` 是通用 manifest 贡献；图片粘贴入口依赖宿主签发的一次性授权，不把普通脚本调用当成真实粘贴。

## 格式与表格

`plugins/formatting` 只依赖公开 SDK，声明普通文档读写权限；由启用动作授予这些普通权限，敏感权限仍单独审批。提供文档工具栏、格式面板及键盘可达的编辑右键菜单。插件持有标题、强调/删除线、链接、列表/任务、引用和代码的格式转换规则，以及表格操作的业务文案和流程；表格结构编辑使用宿主既有 view-dom 原语，宿主不按插件 ID 识别业务。

表格操作复用 view-dom 既有编辑器，不另造一套表格模型。覆盖行列增删、对齐、单元格设置/清空、选取和退出；表格后的真实文本也纳入有界快照，避免把截断的表格误当文档末尾。普通与窗口化视图都通过相同受控事务入口，实际写入 Markdown，并以独立历史组支持一步撤销/重做。

快照绑定文档身份、版本、选区 revision 和保存位置 generation；最多 64 Ki UTF-16、256 行、64 笔修改。不认识的 HTML、嵌套上下文及远端窗口化位置不推测语法。插件不能拿截断快照当全文；明确提示不支持，用户可继续使用基本编辑。格式面板字段编辑保留快照，文档改变后旧操作失效。

通用工具栏按钮用鼠标操作时保留正文编辑焦点；键盘焦点及表单字段行为不受影响。工具栏在标题栏的独立第二行参与布局，长内容在自己的区域内横向滚动；键盘焦点会将整个按钮及焦点环滚入可见区域，不覆盖标题和窗口控件。详细表格状态留在面板，关闭面板后重新取得工具栏快照。右键菜单在命令提交后关闭，Escape 返回正文，文档切换或停用时失效。删除线增加对应 CST/render 支持，位置映射修复此前批量修改累计偏移在边界点的错误。

## 导入顺序与取消

本阶段选择明确的最小范围：支持本地 PNG、JPEG、WebP 选择和真实图片粘贴；不实现拖入、网络图片或未命名草稿的持久图片暂存。

导入首先调用 `resources.prepareDocument`。未命名文档由宿主完成普通首次保存；取消保存就结束导入，不产生图片文件或引用。插件随后捕获编辑快照，取得图片源句柄，调用 `resources.stage`。只有资源完成持久暂存后，插件才构造 Markdown，并通过 `editing.apply` 同时提交引用和 `assetIds`。

编辑快照绑定文档身份、版本、选区与保存位置 generation。内容、文档或保存位置改变后，旧操作必须失败，不能将迟到引用插入另一个文档。插入是单笔隔离历史操作，光标落在引用末尾。

插件命令启动异步操作后及时返回，避免将用户停留在原生保存/选择器中的时间占用为命令 RPC 等待。UI 使用通用更新能力刷新。成功粘贴不打开弹窗或抢编辑焦点；后台粘贴失败通过通用 `ui.notify` 发出有界纯文本错误，面板也保留状态供检查。

Linux 生产 WebKit 的真实 textarea 粘贴事件曾返回空 types/items/files，而同次可信事件内 `navigator.clipboard.read()` 能读取 PNG。新增的宿主兼容路径只处理没有文本、HTML、文件或其它类型的空载荷；在事件分发期间同步校验原生可信事件、创建一次性授权并立即开始 Clipboard 读取。授权绑定具体插件实例、文档/版本/选区及保存位置；只读取一个受支持图片类型，不读取文字或 URI，不添加原生任意路径/剪贴板 IPC。读取超时、取消、停用、异步命令投递失败及状态变化均不能产生迟到插入；无图片时取消而不触发首次保存。

关闭插件界面、取消、停用或卸载会停止待处理请求；迟到的源、意图及未接纳资源会释放。已经接纳的资源归宿主文档生命周期管理。撤销只撤销引用，停用插件及撤销均不删除已接纳图片，也不删除用户原图。

## 两种资源目录

插件提供两个固定策略：

- `assets`：文档同级 `assets/`。
- `document-assets`：宿主按文档名派生的 `<文档名>.assets/`。

插件不能填写任意资源路径。策略保存在插件私有 storage 的 `import.policy.v1` 中，只影响之后的导入；持久化失败会明确提示，本次会话仍可使用当前选择。

替代文本使用受控文本字段，最大 512 个字符单位；方括号与反斜线在 Markdown 中转义，换行规范为单行文本。宿主返回的相对引用需通过本地安全格式检查，插件不会将它转成绝对文件地址或网络 URL。

## 保存与另存为保护

图片已落盘后才能接纳文档引用。另存为先收集当前文档中的本地图片引用，由原生资源服务验证来源与目标，再复制所需资源，最后提交目标 Markdown。原文档和原资源保留；资源检查或复制失败不能静默跳过并继续产生失效引用。

手写本地图片 URL 也由扫描器交给原生层，不因为字符串看似处于 `assets/` 就自动授予访问权。宿主仍需检查其是否属于允许迁移的资源。HTTP/HTTPS 图片链接保持文本，不触发下载。

`apps/desktop/src/resource-reference-scan.ts` 提供普通字符串扫描和 `EditorDocumentSource` 流扫描。原生流由宿主读取当前文档数据，检查预期版本并在 UTF-8 安全边界分块；扫描前、各块之间及结束时检查文档快照与取消状态。保存锁及最终 CAS 检查由调用方保持。

扫描预算为最多 4 Mi UTF-16 文本和 4096 个图片引用出现次数，底层资源服务可以实施更严格限制。超过文本预算时丢弃聚合缓冲，只继续流式检查跨块 `![` 起始标记。完整流没有图片起始标记时可证明无 Markdown 图片引用，允许无图片大文档另存为；超过预算且出现候选标记时明确报告暂不支持安全迁移，不在 JavaScript 中物化全文或冒险漏拷贝。

预算内使用保守 Markdown 子集解析并借助现有块解析器判定容器延续。代码围栏、缩进代码、完整行内代码、转义图片标记与代码中的引用示例不作为图片资源。直接图片链接支持转义替代文本、平衡括号、尖括号 URL 和标题。引用式图片、无法证明的目标语法、需要 HTML 实体解码的本地 URL 或结构/工作预算超限会明确拒绝。这里不宣称完整 CommonMark 兼容，也不以“不支持”为理由静默漏掉候选引用。

## 恢复副本与图片显示

恢复副本打开后，宿主根据已校验恢复记录中的原路径查找资源，在受保护的恢复副本目录内完成资源复制，再归档恢复记录。复制失败保留原恢复记录；源 Markdown 和原图片不改动。路径、内容哈希、符号链接和外部修改均由原生层检查，清理只针对本次新建且未改变的文件。显式“导出恢复记录”仍只导出 Markdown，不能视为图片归档导出能力。

普通和窗口化视图都接入图片导入；source 保留原始 Markdown，live 为已授权本地 PNG/JPEG/WebP 增加预览。预览仅接受宿主解析后的 blob URL，最多 32 个可见预览，保留映射的 Markdown 文本。恢复复制完成后可重新请求之前尚不存在的资源。转义 `]` 的替代文本先由 Markdown 解析器正确识别，显示时仅还原 CommonMark 可转义标点，不解码 URL。

### 缩放断点焦点回归

原生矩阵发现设置下拉框在 150% → 100% 缩放时失去焦点：1100 像素窗口的 CSS 宽度跨过 760px 断点，主界面监听器无条件调用 `focusActiveView()`，把焦点从仍打开的设置面板移到正文。修复前使用单个 Home 键即可重现，随后 5 秒仍是 textarea 焦点；[原生记录](evidence/v2-product-phase4-editing-resources/native-focus-before/zoom-focus-trace.json)与原始截图保留。

候选 03 在更新侧栏后保留仍可见且可交互的当前焦点；只有 body、文档根、inert 或实际隐藏元素才恢复正文焦点。两项新增浏览器回归覆盖设置 select/input、搜索、Unicode/版本不变，以及隐藏侧栏控件的必要焦点恢复，先失败后通过。没有在测试每次按键前强制重新聚焦来掩盖问题。候选 03 原生单 Home 键复核的 28 次采样均保持 SELECT 焦点，实际缩放从 1.5 变为 1，CSS 宽度从 733 变为 1100。64 组矩阵结果见下表。

### 仍未关闭的边界

P4 只完成本轮格式与本地图片范围，公式、图表/流程图、脚注继续留在 P4。未知嵌套语法、超预算图片资源迁移、任意本地引用、拖入及网络图片不属于当前支持范围。显式恢复导出仍是 Markdown 文件，不是含图片归档。

Rust 早期并行失败不被串行通过抹去：4 项 `EFAULT` 跨目录注册和解析，另 4 项是文档注册缺失。默认 Cargo runner 使用 proot，但当次没有 syscall trace；共享测试资源注册容量也是潜在干扰，不能据日志证明根因。随后在同一当前测试二进制上，显式取消 Cargo runner 和线程覆盖、直接执行默认并行，118 通过、1 忽略，退出 0；[执行参数与二进制哈希](evidence/v2-product-phase4-editing-resources/resources/native-parallel-direct/execution.json)和输出均保留。这个对照关闭了当前二进制的并行门禁，但不追溯宣称已证明早期失败根因。Windows 实机、系统 IME 和读屏尚未验收。
