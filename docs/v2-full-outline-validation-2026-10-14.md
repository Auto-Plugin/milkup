## 完整性与边界

大纲 1.1.0 通过独立 manifest 和公开 `@milkup/plugin-sdk@0.1.1` 安装。连续扫描从首行到 EOF 的 4096 行范围，建立整个文档版本的标题记录与可见序号映射。500 是呈现行上限，既不是索引条目上限，也不是文档行数上限。取消后显示已经索引的部分和未完成状态；重试重新建索引；配额、读取、截断和版本失效不会显示为完成。

支持顶层 ATX H1–H6 与 Setext H1/H2，包括跨读取窗口和跨 4096 行扫描范围的段落/下划线。Setext 归属于包含确认下划线的扫描范围，但定位回段落首行。围栏、缩进、列表、引用、HTML 块与分隔线边界保持上下文；标题最多保留 4096 个 UTF-16 单元供标签使用。这不声明完整 CommonMark 一致性；嵌套容器内标题仍按宿主现有解析范围处理。对应边界测试同时覆盖宿主 Markdown 块解析与公开标题扫描。

每个索引标题记录含源偏移、文档版本内身份、父序号、最多六级祖先和子树结束序号。重复文字不会混淆身份。编辑/撤销/重做或切换文档立即废弃旧动作；启动有 120 ms 去抖，旧扫描、操作队列和存储释放完成后才建立新存储。没有整文档复制、全标题数组、无限页目录或降低恢复频率。

## 分页、配额与生命周期

公开 `host.storage.createTemporaryStore()` 只返回不透明实例及 `get/set/getMany/setMany/dispose`，不暴露路径或任意数据库访问。大纲仍只申请 `document:read`，没有文件或网络权限。能力属于通用插件存储合同，不包含按大纲 ID 判断的宿主分支。SDK 的最低版本检查也已修正：`^0.1.1` 不能接受 0.1.0，0.x 的 caret 上界遵守次版本边界。

标题页八条、可见序号页 256 条，每个缓存最多八页；每次最多准备 500 个呈现条目。页面缓存满时批量刷盘并淘汰四页，保持内存上限并减少细碎事务。已经准备、内容未变化的可见行可以复用；层级变化、折叠和范围变化会失效该缓存。

宿主在单独的 IndexedDB `milkup-plugin-temporary-v1` 中保存索引。写入与配额计数在同一事务提交。默认每实例 256 MiB、全局 512 MiB 计费字节，最多 131072 页/32 个实例；每插件激活最多四个实例，每实例最多 16 个在途请求。单次或批量值最多 256 KiB UTF-8，最多 32 个安全键；每页/实例另计 1024 字节开销。这是逻辑计费上界，不是浏览器数据库文件物理大小的硬上界。

禁用、卸载和正常原生关闭会等待本实例清理。关闭后旧存储能力不可再次打开。未知 owner 的崩溃遗留仍计入额度，不自动删除，不接触正文、历史或恢复目录。反复异常退出可能耗尽额度并使索引显示失败；本轮没有加入长期遗留管理或删除用户副本的功能。

## 生产发现与修复

真实安装流程揭示了单元替身未覆盖的两个往返边界：宿主回传已呈现范围被当作新滚动请求，导致持续重绘；显式取消使迭代器静默结束，被误报扫描中断。两者均补了回归。渐进更新还会在 pointerdown 与 click 之间替换按钮，宿主通用受控 UI 现将按住期间的中间输出丢弃，在手势结束后请求一次最新呈现。该处理不依赖插件身份，点击和 pointercancel 均有测试。

原始失败证据保留在 `/workspace/.milkup-full-outline/production-full1` 至 `production-full4`。其中一次中部滚动条拖动没有移动列表，不能计作中部导航通过；后续使用真实 XTest 滚轮动作验证。

## 同合同扫描证据

对照不是旧区域大纲与新全文大纲的混比。两份生产宿主安装完全相同的[测量插件](../tests/fixtures/plugin-scan-probe.milkup-plugin)，读取同一 26018029 字节、40001 行、8775 个有效标题的 fixture，查询均为 `fromLine:1, toLine:40001, windowSizeLines:4096, batchSize:128, maxResults:50000`。每次重新开始完整扫描，文件缓存状态不宣称是冷缓存。使用同一容器、显示、原生运行器及公有 Worker 文档协议。[驱动](../tests/native/tauri-plugin-index-profile.mjs)记录请求/响应时长而不改变返回数据。

| 生产完整扫描 | 三次总耗时            |  中位数 | 请求数/次 |
| ------------ | --------------------- | ------: | --------: |
| b86edd3      | 8859 / 8269 / 8884 ms | 8859 ms |       315 |
| 候选扫描器   | 7300 / 6657 / 6451 ms | 6657 ms |       159 |

标题数量每次相同，中位数减少约 24.9%。主要变化是受 262144 UTF-16 预算约束的最多 512 行读取、自适应缩小窗口，以及最多四窗/约 16 ms CPU 预算的 `next` 聚合。每窗仍让出执行权。纯 JavaScript 微基准的较大收益不替代原生数据。

直接拦截原生 `invoke` 未生效，记录中 `nativeInstrumentationAvailable:false`；零值不是“零次原生读取”。原生证据能证明公有 RPC 数量与时间变化；精确读取次数来自单独的 broker 诊断微基准。`ps` RSS 是采样值，CPU 为进程累计平均，均不是峰值或单次操作成本。

完整磁盘建树与纯扫描分开测量。首次完整建树基准为 86882 ms，索引 8775 条、1132 页、2970008 计费字节；改进前十次头尾导航 590–809 ms。没有宣称 200 ms 或 Typora 品质已经达标。

最终生产宿主补样为 **7126 / 6617 / 6600 ms**，中位数 6617 ms，较同合同 b86edd3 中位数减少 25.3%；每次仍为 8775 个标题、159 次文档 RPC。[完整测量数据](evidence/v2-full-outline/scan-summary.json)保留初测和最终补样。

缓存改进后的完整建树为 **50106 ms**，对照 86882 ms 减少约 42.3%。这是相同全文建树合同的一次前后样本，不能当作稳定 p95；页数/字节与标题数量均保持 1132 / 2970008 / 8775。完整建树仍较慢。全部折叠实测约 **22198 ms**，具有进度提示，仍是明确的性能缺口。

| 最终导航（含真实输入与观察开销） | 样本 |    p50 | p95 / 最大值 |
| -------------------------------- | ---: | -----: | -----------: |
| 头部                             |    5 | 692 ms |       771 ms |
| 尾部                             |    5 | 667 ms |       762 ms |

[原始生产结果](evidence/v2-full-outline/production-results.json)和[导航分布](evidence/v2-full-outline/navigation-summary.json)同时记录索引资源。建树完成时原生 RSS 146988 KiB、WebKit 453032 KiB；导航及全树折叠展开后分别 147184 / 519776 KiB。这是采样 RSS，不能推出峰值或持久堆大小。全过程 DOM 最多观察到 374 个标题行，单位测试另覆盖 18000 个标题的完整索引与 500 行呈现上限。

中部首次 X11 截图在较早绘制时点出现空白，而随后 WebView 截图已有正确活动项。补验显式等待 source 模式与活动标题可见，再等待 1200 ms；[稳定系统截图](evidence/v2-full-outline/settled-middle-x11.png)确认第 28064 行活动项与周围列表均正常呈现。补拍中的启动失败已定位为执行工具断连后驱动退出；另一个脚本错误是把审计里的旧插件 ID 当作安装完成，现改等真实启用控件。均未把这些失败算作产品通过。
