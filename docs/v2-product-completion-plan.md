## 架构边界与通用验收

### 不依赖可选插件的最小可信基础设施

以下能力由宿主保证；禁用或卸载所有可选插件后仍须正常工作：

- 基础文档新建、打开、编辑、保存、关闭，以及必要的撤销/历史、Unicode/IME、光标与选区正确性。
- 普通与窗口化大文档的数据访问、脏状态、保存失败保护、外部修改冲突处理、恢复记录及恢复入口。插件启停不得删除原文、恢复记录或未保存内容。
- 插件包读取与验证、兼容性及权限校验、可信审批、隔离运行、通用贡献注册、启停/卸载和故障恢复的最小管理安全壳。管理扩展自身出错或被禁用时，用户仍能禁用故障插件、撤销授权和继续编辑。
- 应用版本与 SDK 版本、构建防漂移、可信发行渠道及版本元数据、签名校验、受控暂存和安装执行。更新插件缺席时，版本/签名真实性与宿主可启动性不能依赖它；检查更新的交互不必继续显示。
- 通用能力 broker/RPC、配额、生命周期撤销、系统文件选择和受信确认/保存保护。执行安装等高影响动作必须经宿主安全门；插件不能伪造确认或替用户决定保存。
- 为上述能力必需的基础渲染、平台窗口、主题/可访问性底座与操作系统适配。它们只提供机制，不承载可选产品的专用业务面板。

### 独立插件的判定

每个产品插件须具有独立目录、manifest、入口、构建和插件档案；仅依赖公开 SDK，不导入桌面源码、宿主私有 store 或 build helper 私有实现。可预装，但安装和贡献发现须走通用目录/注册机制，不能按插件 ID 在宿主写分支。

预装不等于授权或启用。只读默认插件可沿用经审查的自动激活策略；含敏感权限的 Worker 发行插件（包括 `updates`）仅安装并在管理列表可见，必须由用户明确审批后启用。它们不能继承只读插件的自动激活待遇；用户禁用或卸载后，重启及默认插件目录同步均不得让其复活。

插件拥有业务状态、文案、交互流程与受控 UI 描述；宿主仅渲染通用卡片、详情和贡献槽位。新增插件不应要求宿主复制其专用状态机。通用插件列表采用简洁卡片，详细说明、权限、兼容信息和操作进入详情；图标按公开 manifest 契约呈现。

所有阶段共同验证：独立目录构建并安装 → 显式审批最小权限 → 可见操作 → 禁用/卸载后贡献消失 → 已捕获句柄与迟到 RPC 拒绝 → 再启用不复活旧句柄。随后在所有可选插件禁用状态验证基础打开/编辑/保存/恢复以及管理安全壳。宿主硬编码业务 UI 加一个插件入口不满足此标准。

- 本轮仅收尾审计和文档纠正，不新增功能、构建、打包、上传、重试或部署，不删除 artifact 或证据。离线 Runtime 延后正式合 main；历史弹题不能覆盖较新的范围限制。P2–P9 表格及下方工作区草案均不是当前实施授权。

- 新权限须在公开 SDK/manifest、审批界面、受控 broker、Worker/sidecar 边界与撤销测试中闭环；新增能力不表示所有插件自动获得授权。

- 区分底层机制已实现、插件体验已验收与真实平台已验收。模拟安装替身只能证明交互和保护流程，不能证明真实安装成功。
- 每阶段记录失败证据、修复断言、用户可见截图及剩余边界。按父线程授权维护专用分支；不合并 main/v2/quality，不强推，不发正式 Release。
