# Single current-source TU gate

This adds `current-source-preflight` to the existing manually dispatched WebKit QA workflow. All older jobs explicitly exclude this operation. It does not use either old object format, restore a cache, invoke an engine target, install a runtime, or launch an application.

Inputs remain the official 2.54.2 archive SHA `a76345b391bef6211fb5ab6cfab2e86b285d18cda17cbb9ade595f1252b86065` and normal-path patch SHA `855e58cc8ad531cc32e893b8274983a6264e6fdfc248c13e80c5ef0e01d7a4e5`. Patch behavior has not changed from 8df7b0cb.

- Ubuntu 26.04, ordinary user for source/configure/generation/compiler. Official Ubuntu SDK build dependencies only are installed through the existing isolated-runner convention; repository lists remain task-local and authenticated. Simulated dependency removal or system WebKit/JSC changes are rejected.
- Configure directly for the previously fixed final QA prefix, Release, GTK3/API4.1/Soup3, non-developer, bubblewrap enabled, GTK Unix printing required. Actual `cmakeconfig.h` and cache must agree. Unconsumed CMake options fail. Distro hardening flags are retained, with `-g1` and LTO disabled for this recorded object profile.
- Source download/extraction and every command have process-group time limits. Whole job: 1800 seconds. Work deadline: 1560 seconds from first workflow step, reserving four minutes for object compression/upload. Individual configure at most 300 seconds; header generation 240; each selected object 180. Disk reserve 8 GiB and available-memory reserve 2 GiB are checked before work and after objects.
- Enumerate all ten directly modified `.cpp` files from the locked patch receipt, resolve their actual configured unified/non-unified TUs, and retain the full compile database and Ninja graph. Exactly one TU per source; no fixed obsolete 1–3 TU count. This is not an exhaustive compilation of every transitive header consumer.
- Only PCH producers explicitly referenced by selected TU commands are compiled first, using exact original commands and the same deadline; no umbrella target or PCH suppression. PCH inputs/identity are retained, but PCH binaries are not archived.
- Header command graph is inspected before execution and execution compared with it. Compiler/linker prerequisites are forbidden there. XML/XLink/XMLNS official generators use their exact configured commands. Objects use the exact compiler/flags/dependency arguments from the graph; no shell-target substitution or warning suppression, and ccache explicitly disabled.
- Preserve earliest failure, command lines, logs, generated-header hashes, selected actual unified sources, config/ABI, source/compiler identity, resource samples and successful object hashes. Object archive is only completed selected `.o`/`.d`, at most 512 MiB uncompressed; no runtime, credentials, or user data. Cross-job restore remains unproved. Large config/graph evidence is retained in lossless ordered gzip parts (32 MiB raw per part, 128 MiB aggregate configuration cap) with complete hashes and lengths.

30 local tests now pass, including actual failed-run compile DB/PCH graph and lossless graph-retention replay. YAML and shell commands parsed locally. The runner executes the current dependency-free gate tests before SDK installation. See evidence/43849878532/REPORT.md: real configuration and ordinary headers passed; first TU failed because the harness omitted its configured PCH. The local correction has not run remotely.

A passing result will be `passed-actual-selected-TUs-not-engine-or-package`. Failure stops this run; there is no retry/automatic continuation. Even success requires a separate measured full-build plan and trusted actual component/resource inventory before packaging. Current generated-config support, host ABI and dependency availability are intentionally measured, not inferred from the old runtime.

Subsequent delivery must retain the same non-developer configuration/flags or explicitly revalidate their changes. Actual app linkage and each WebProcess/NetworkProcess/injected bundle mapping must prove the final prefix; staged ELF checks alone do not. Installation, failed-update recovery, uninstall, editor/IME/plugins and all native PDF cases are not executed in this gate. Security maintenance ownership is still unassigned; no production endpoint/key or publication is configured.
