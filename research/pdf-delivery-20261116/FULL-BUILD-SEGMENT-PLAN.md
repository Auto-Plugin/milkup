## Gate order and stop conditions

1. **Current clean-job proof:** pin full source/configuration/toolchain/installed SDK; rebuild original PCHs; reject identity/object mismatch; independently establish exact old/fresh selected-byte equivalence; restore prior bytes; prove selected Ninja no-op and normal-graph reuse; perform a real relocatable partial link. This deliberately recompiles the ten objects, so it is not yet an efficient general cache. The current operation cannot build or install the full engine.
2. **General resumable object state:** a subsequent implementation must cover every selected/generated source, compiler dependency from depfiles, tool/flags/ABI and response file, plus command/dependency metadata. Generated inputs and PCHs must be regenerated and content-checked before restored outputs are accepted. An unchanged output may only be made current after all of its dependencies are content-verified; unknown/missing dependency provenance must reject reuse. Files outside the test root stay read-only. Do not archive or reload executable/runtime products as if they were compile objects.
3. **Bounded compile segment:** after (2) has positive and mismatch evidence, execute the configured graph with limited compiler concurrency and a separate archive reserve. Start with a measured segment, not a guessed promise to finish all 2,833 entries. Track completed unique targets, wall/CPU/RSS, free storage, archive bytes, regenerated targets, and cache hits. A timeout or deliberate progress stop must preserve independently verified finished objects and log incomplete outputs separately. Next-job success must demonstrate real restored hits plus new unique targets, not merely recompilation. Stop on no forward progress, resource reserve breach, input drift or archive failure; no automatic cold fallback or loop.
4. **Complete and link:** only when remaining graph work and resource evidence support completion, reserve a separate bounded link interval and actual RSS/disk monitoring. Original flags and upstream link edges remain unchanged. A `ld -r` partial object is never a completed shared library. Failed/incomplete link files are not accepted into an installation manifest.
5. **Same-package installation/native behavior:** derive install manifest/resources/license/SBOM and host symbol requirements from actual successful products. Install the matching final QA prefix and application in an isolated guest, record real process/library mappings and default sandbox, and execute the native PDF matrix on that exact package. No research-prefix copying or 2.52.6 result inheritance.

No fixed full-build completion time is asserted: no complete current-version compile/link or peak-memory sample exists yet. A first segment must supply this missing evidence. Current 30-minute restore work does not authorize silently turning its target into an hours-long engine build. The release blockers in NEXT-PACKAGE-GATES.md, including supported-host ABI and an accountable security maintenance/rebase route, remain unchanged.
