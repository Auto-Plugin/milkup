# Clean-job 2.54.2 restoration gate

This is a selected-object restoration proof, not a complete engine, a shared-library link, or an installed PDF result. The source receipt is run 43852458294 / candidate ae1f50b4, preserved byte-for-byte in evidence/43852458294/original.zip. It contains ten objects and their depfiles; it contains no PCH binary, runtime, credentials, or user documents.

The new manual `current-source-restore` job has a 30-minute hard limit, a shared 1,560-second work deadline and evidence reserve. It uses the same absolute root, official 2.54.2 archive, patch, release options, final QA installation prefix, default sandbox configuration and SDK. There is no 2.52.6 object fallback and no engine build/install command.

Before restoring anything, compare complete recorded configuration, actual compiler/tool hashes, compile database, all generated headers, patched sources and installed package inventory. Each identity field has an explicit mismatch rejection control. The normal name-header generator commands are registered through their approved generator-only Ninja graph, so identical header bytes do not conceal missing build metadata.

Regenerate the two original-parameter PCHs and independently compile the ten selected TUs through minimal Ninja edges containing exactly the original expanded compiler commands. Require fresh PCH and every object/depfile to equal the prior bytes. Only then restore the prior archived bytes while retaining the independently verified fresh output timestamps. This conservative first proof deliberately recompiles the selected objects; it is not yet a time-saving general incremental cache.

A corrupted-object control must reject before any write. A selected-graph dry run must be a no-op. Inspect the normal Ninja graph without executing it: unrelated missing order-only dependencies may remain, but selected objects/PCHs may not be scheduled again. Perform a real `ld -r --fatal-warnings` partial link and verify ELF REL, explicitly not a finished WebKit shared library. Retain input hashes, exact commands, Ninja dependency/log metadata, resource samples and bounded objects. A failed normal-graph check remains failed even if the independent partial link succeeds.

Local verification uses a real official Ubuntu Ninja 1.13.2 binary and host C++ compiler for the orchestration positive/negative case: fresh compile, old-byte restoration, normal-graph reuse, header-change invalidation, and actual relocatable link. This does not replace the actual Clang/WebKit job. The package was verified against official Ubuntu resolute metadata, SHA-256 533239a464183f041f7c979f899fd8419e31ac82366540e57902a255de78f156. No system package or security setting was changed.

Full-engine planning must follow the measured restoration result. The prior graph has 2,833 compile database entries; ten selected TUs are not a representative runtime estimate. A later bounded segment must bind all compiler inputs, generated state and tool identities, reserve archive/link space and time, retain completed object metadata on an intentional stop, and demonstrate forward progress on its next clean job. Full linking, final-prefix resources/ABI, ordinary installed application mapping, sandbox operation and the same-package native PDF matrix remain separate gates. Security maintenance ownership and a sustainable current-version rebase are still release requirements; the QA prefix is not a product delivery decision.
