# P6 catalog Linux native harness

`tauri-p6-catalog.mjs` uses the frozen production binary, actual GTK package picker,
native X11 keys, shipped manager controls, and actual native catalog commands.
The root task alone starts drivers/UI; this harness has no build/install step.

Use one **new** profile and output directory per case. Reusing a successful or
failed output is rejected by an exclusive lock. `--preflight` only writes fixtures
and records hashes; it never starts an application. Five fixture archives implement
the public plugin object shape with no private imports or host ID exceptions.

Required environment:

```sh
export TAURI_APP_PATH=/workspace/milkup-plugin-lifecycle-evidence/milestone02/production01/milkup-desktop
export MILKUP_NATIVE_EXPECTED_BINARY_SHA256='<SHA from frozen production proof>'
export MILKUP_NATIVE_PROFILE_ROOT=/tmp/milkup-p6-profiles/p6-m02-unique-case
export MILKUP_NATIVE_EVIDENCE_DIR=/workspace/milkup-plugin-lifecycle-evidence/milestone02/native-ui/runs/p6-m02-unique-case
export MILKUP_P6_CATALOG_CASE=smoke
export MILKUP_P6_BINARY_CONFIRMED=1 MILKUP_NATIVE_EXCLUSIVE_DISPLAY=1
node tests/native/tauri-p6-catalog.mjs
```

Before running, the existing namespace driver wrapper must already be active with
the **same** binary, DISPLAY, `XDG_{DATA,CONFIG,CACHE}_HOME`, and profile root.
Reuse the reviewed milestone01 runtime copied to milestone02 by the root task;
keep WebKit sandboxing and the read-only namespace overlays. Do not start drivers
concurrently. `startProduction` owns each launched app and closes it in `finally`.

| Case                 | Actual assertion and method                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `smoke`              | UI install, exact candidate approval, actual Worker activation, verified native commit, enabled control. Then Unicode edit/undo/redo/save byte equality.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `manager-rollback`   | UI installs a throwing upgrade, native retains old generation/content/approval; manager activates old code in a new lifetime, old command responds. No harness call to native commit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `manager-hang`       | UI installs version 1.0.2 whose activate enters a synchronous infinite CPU loop. The actual approximately 10-second host deadline must stop the candidate and recover the old verified generation within 30 seconds. The old public ping returns a different activation nonce, proving a fresh activation; the private numeric epoch is not directly exposed. Native package/content/approval stays unchanged. `candidate-recovery.json` retains elapsed time and both nonces.                                                                                                                                                                                                                                                                             |
| `raw-api`            | Base UI install; actual Worker activation probes eval, global Function, intrinsic Function under CSP, importScripts, child Worker, raw fetch, WebSocket/XHR, IndexedDB/caches/BroadcastChannel. Every forbidden API must throw; successful raw API access fails the candidate. Raw fetch uses a successful local data URL, so a DNS/network error cannot fake denial. A subsequent dynamic-import bundle must be rejected and the old version retained.                                                                                                                                                                                                                                                                                                    |
| `late-command`       | A real Worker command first acknowledges execution with P6_DELAYED_COMMAND_STARTED, then waits two seconds; the harness must observe that acknowledgment before UI disables its owner. Old command may not publish. This covers delayed command lifetime, not rollback of already completed external side effects or a claim that an in-flight native request was cancelled.                                                                                                                                                                                                                                                                                                                                                                               |
| `catalog-cas`        | WebDriver **trusted host** invokes two existing native transitions with the same entry revision concurrently. Exactly one succeeds and the other conflicts. This is native authority/CAS testing, not an assertion that ordinary plugins can invoke Tauri.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `trial-restart`      | UI disables old runtime, trusted-host IPC persists approved trial, process exits without commit/abort, a new actual process recovers old verified active metadata and disables interrupted trial. No candidate is synthetically marked verified.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `startup-restart`    | UI disables old runtime; trusted-host IPC persists a startup attempt, process exits without completion, real restart must disable it and retain diagnostics. These restart cases test process interruption at explicit durable boundaries, not arbitrary power failure.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `mirror-restart`     | Exact corrupt localStorage bytes are written only in the test WebView, then the actual process restarts; native package/approval remains authoritative and rebuilds the mirror.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `catalog-corruption` | After app shutdown, backs up exact primary and native backup bytes, corrupts the owned-profile primary, restarts. Backup recovery must retain package metadata but revoke approval and enabled intent. The original corruption is retained in evidence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `legacy-migration`   | Creates a synthetic old-release registry and legacy package directories only in the dedicated profile: one valid enabled/approved row, one missing-name manifest and one malformed record. After app shutdown, preserves and parks the temporary new-profile catalog primary/backup to simulate absence of native authority in an old release. A second real startup invokes automatic migration (the harness never invokes migrate). Exact raw UTF-8 backup/receipt, per-row quarantine, valid unapproved candidate and all user-data sentinels are asserted. Shipped UI approval/activation must ping; a third process startup with the old mirror reintroduced keeps the same imported generation/receipt without duplicate copies or bad-item revival. |
| `remove-failure`     | Disables runtime, removes write access to the owned generations parent, invokes native tombstone/remove. Real deletion refusal must retain a diagnostic; restart cannot resurrect. Restores original mode in `finally`, retries removal, checks user-data sentinel unchanged. This is native tombstone/GC testing; shipped remove button must also be exercised in the full UI matrix.                                                                                                                                                                                                                                                                                                                                                                     |

Every case ends with actual Unicode save/undo/redo and restores the original source
bytes. Screenshots, native snapshots, UI text, localStorage mirror, source/package
hashes and failure details are retained. Assertions do not claim Windows/macOS,
physical printing, a complete malicious-code sandbox, or any P5 PDF/timeout fix.

Fixture checks can run without UI/Cargo:

```sh
node node_modules/vitest/vitest.mjs run tests/native/p6-catalog-fixtures.test.ts
node --check tests/native/tauri-p6-catalog.mjs
```

The fixture suite verifies public archive shape and the production closed-bundle
validator, including intentional dynamic-import rejection. It does not execute the
actual WebKit CSP; only the `raw-api` native run can supply that evidence.

The base fixture declares a minimal public `catalog-probe` modal and renderer so its ping/delayed commands receive the ordinary UI notify capability. This corrects the first rollback harness failure; it does not broaden production permissions or remove the ping assertion.
